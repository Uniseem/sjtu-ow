# 262 自查

连做轮次，自查不能替代独立复核。

## 换角度核对

1. **「激活」这次是真的**：不只看 `js-ready`。`browser-check` 在页面开始解析前挂一个 MutationObserver，首屏启动过程中任何装着 `#main` 的节点被移除就记下来；`createApp` 会清空容器、激活不一致会换节点，两种都会被记到。变异 T4 把客户端换回 `createApp`，browser-check 红了——233 起的「激活」检查恰恰抓不到这一处
2. **体积**：首页壳 JS 从 62261 涨到 70186 字节（gzip）。看了一下原因：`createSSRApp` 把 Vue 的激活渲染器带进来了（`createApp` 时被摇掉）。这是该有的代价；合计 92462，离 300 KB 和 JS 120 KB 的上限都远
3. **整份会话进页面状态**：会话里有邮箱。核对过只有登录的本人看得到（`/api/session` 本来就只回本人的），访客的页面状态里 `user` 是 `null`；登录用户的页面 `Cache-Control: private, no-store` 照旧
4. **`nonNil` 改的是共享数据吗**：顶层是副本；切片元素和指针后面是就地改（把 nil 换成空），都是服务层这次刚造的答复对象，换了不改变含义。`[]byte`、`json.RawMessage` 原样放过（空的 RawMessage 会让编码出错）——测试里放了一个 `omitempty` 的 RawMessage
5. **253 的后台页面改签名是机械替换**：只在 `getApiX(` 后面插了 `api`，没改别的。它们本来就多数是只读、写操作不全（文档 C7），整体在 F8、F9 重写；这一轮只保证不因为签名变了而报错（构建过、browser-check 过；后台页面没有在浏览器里逐个打开）
6. **分块丢失的整页重载**：同一地址一分钟内只重载一次（sessionStorage 记时间），存储不可用时不重载——避免真坏的分块让页面无限刷新
7. **CI 红了一次**（261 的提交）：`TestCalendarICSGenerationAndFolding` 的数据钉在 2026-10-09，`Serve` 用墙上的钟，到 10-10 活动就算过去了。测试机上这条是缓存的结果，所以没发现。本轮给安排服务加了可换的时钟，测试用 `clock.Fixed(t0)`
