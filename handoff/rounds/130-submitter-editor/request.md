# 130 投稿者的编辑页去掉「推荐」标签页

## 背景

继续用户 2026-10-04 睡前的要求（假定各种身份走流程）。以第一次投稿的成员身份打开新建文章：124 轮加了「投稿须知」，但编辑页上还有「推荐」一页：缩略名、标题标签、元描述、在菜单中显示、上线日期 / 时间、过期日期 / 时间。这些是 Wagtail 的叫法，投稿的人看不懂，也用不上；乱填了，编辑审稿时还得改回来。

探查（临时测试，在测试机上跑，没提交）：

```
== 投稿者 tabs: ['内容', '推荐']
labels: ['缩略名', '标题标签', '元描述', '在菜单中显示', '上线日期/时间', '过期日期/时间']
actions: ['submit']
```

## 本轮范围

1. 文章要过审的人（`submits_for_review`：超级管理员、内容编辑、认证作者以外）的表单里拿掉这六个字段，标签页随之消失。拿掉而不是藏起来：藏起来的字段提交时是空的，会冲掉编辑设好的网址和 SEO
2. 新稿的网址片段由表单按标题生成：撞上固定路由的保留词加 `-article`，同一栏目下重名加序号。Wagtail 自己的兜底不避保留词，而且报错会挂在表单里没有的字段上
3. 设计 14.3（v6.25）；文档头部版本号补上（129 漏改了）

顺带：127 的 README 和轮次记录把「谁能给文章发通知」写成了「内容编辑、认证作者」，代码和设计都是只有内容编辑（含超级管理员）。README 改掉，轮次记录加「130 轮更正」。

## 验证

测试：投稿者的表单没有这六个字段、页面上没有，内容编辑和认证作者有；投稿者真实提交表单，网址片段按标题生成，编辑改过网址和 SEO 后投稿者再保存，值不变；标题是保留词、重名时网址片段让开。变异逐条改坏。

## 验收标准

测试机上整组检查全绿；变异全部被抓到；推送 `main`，CI 绿；演示站升级。
