# 038 给独立复核写一份指南

用户的计划是 008 之后的轮次交给 Grok 做独立复核。现在有 30 轮，每轮三份文档。

**逐个读一遍成本很高，而且平均用力等于没有重点。** 这轮把它整合成一份指路的文件：哪里最可能还有问题，以及为什么。

## 任务

写 `handoff/REVIEW-GUIDE.md`，按优先级列出：

1. **本 session 修过的地方**——刚改过的地方最可能有新问题，而且它们有问题本身说明那块测试弱
2. **我自己认下的、测试不够强的地方**——这个 session 五次发现「绿灯的测试没在测该测的东西」
3. **实现方的主观取舍**——我自己定的、不是设计也不是用户定的，专门列出来给复核方推翻
4. **真的没验证的**

## 一条硬要求

**要写明「实现方的自查不能替代独立复核」，并举出我自己判断错的实例。** 不是谦虚，是给复核方指出该往哪儿使劲。

## 验收标准

1. 文件写完
2. 回归全绿
3. git 提交，信息以 `038:` 开头
