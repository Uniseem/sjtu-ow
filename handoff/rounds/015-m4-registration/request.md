# 015 M4 第二部分：报名、名单快照与状态机

> 用户外出期间，本轮仍由 Claude 实现 + 自查。

## 背景

014 做完了赛事本身，留了四处等报名接上的接口，以及一条必须补的落差：赛事详细说明还不是富文本。

设计依据：`docs/design.md` v1.5.7，重点读 8.3–8.6、12.8.2–12.8.4、10.2（邮件清单）、13.4（路由）。

## 本轮范围

**做**：T0–T7。
**不做**：后台报名审核界面、批量通过、CSV 导出（016）；Webhook 投递（M5，只留调用点）。

## 任务

### T0 补 014 的落差

1. 赛事「详细说明」换成 Wagtail 富文本（带迁移）。
2. `ArticlePage` 加「关联赛事」外键（006 当时特意没建假外键），赛事详情页显示关联文章。

### T1 数据表（设计 12.8.2–12.8.4）

`Registration`、`RegistrationMember`、`RegistrationStatusLog`，约束照搬设计：

- (tournament, team) 唯一
- **`is_active = true` 时 (tournament, user) 部分唯一**——「同一赛事每人只能代表一支战队」的数据库兜底
- 状态日志只增不改

### T2 提交报名（设计 8.3）

报名页列出战队**全部成员**，队长为每人选一个游戏 ID（只有一个时自动选中），页面加载时预检查并在每人旁边标出问题。

提交时在一个写事务里依次做 8 项校验，**一次性列出全部问题**，全部通过才写入：报名（待审核、名单版本 1）、名单快照、状态日志。事务提交后：给队长发「报名已提交」邮件，并留下 Webhook 调用点。

### T3 名单锁定与同步（设计 8.4）

名单在提交时锁定；队长可以在报名截止前同步为当前成员并重选游戏 ID，重新跑 8 项校验，版本加 1、状态回到待审核、日志里存完整名单。报名详情页在成员集合和名单不一致时提示「可能需要同步」。

### T4 状态机（设计 8.5）

按设计的状态流转表实现：通过 / 驳回 / 撤销通过 / 撤回 / 同步名单 / 重新提交，包含审核模式的限制（本站 / 上游 / 两级）、队长操作的截止时间限制、驳回和撤销必须填备注、已驳回和已撤回不占名额、重新提交复用记录并加版本。每次状态变化写日志。

本轮只做「本站审核」和「两级审核的本站一步」由管理员触发的部分（服务层实现全部转换，API 那半留给 M5）。

### T5 前台页面（设计 8.3、8.6）

- `/tournaments/<id>/register/`：报名页（队长）
- `/registrations/<id>/`：报名详情（该报名的队长和名单成员），显示状态、最近备注、名单快照、状态历史（不显示具体管理员）、队长的操作按钮
- `/me/registrations/`：我的报名（名单成员也能看到）
- 赛事详情页的报名入口占位换成真实按钮；已通过的战队列表接上

### T6 邮件

「报名已提交」（首次、重新提交、同步名单）和「报名状态变化」（通过、驳回带备注、待上游确认、撤销通过）都发给队长，逐封发送。

### T7 接上 014 的四处接口

`has_registrations`、`active_registration_captains`、`approved_teams`，以及赛事取消时通知队长。

## 测试要求

至少覆盖：8 项校验逐条、一次性列出多个问题、并发下的唯一约束兜底、名单快照锁定（改昵称 / 段位 / 成员不影响）、同步名单加版本并回到待审核、状态机每一条合法转换与非法转换、审核模式限制、截止后队长不能操作、驳回必须填备注、已驳回不占名额（同一人可随其他战队报名）、报名详情页的可见性、`/me/registrations/`、邮件、赛事取消通知、已通过战队出现在赛事详情。
