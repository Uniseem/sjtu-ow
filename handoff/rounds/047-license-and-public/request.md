# 047 PolyForm Strict 许可证，仓库改为公开

## 背景

用户 2026-09-18 问「有没有什么许可证，是禁止他人引用源码的」，听完选项后决定：「用 PolyForm Strict，然后改为公开仓库，推送」。

## 公开之前查出的问题

**旧提交还能在 GitHub 上按编号打开。** 为了隐藏个人身份，043 之前把全部提交的作者改写成 Uniseem 并强制推送。但强制推送只是让分支不再指向旧提交，对象本身还在：

```
$ gh api repos/Uniseem/sjtu-ow/commits/7ec6a2a1fb4c21f698fc7e0b60a109f1ff0608d1 --jq ...
7ec6a2a author=<用户的真实姓名> <用户的个人邮箱>
```

（输出里的真实姓名和邮箱在这里隐去。）仓库一旦公开，任何人拿到编号就能看到，而 043 的报告里就写着 `7ec6a2a`。**这件事要用户选怎么处理，没选之前不公开。**

其他检查（结果见报告）：仓库内容和全部历史里没有密钥、个人信息、本机路径；截图只有测试数据；依赖里没有传染性许可证。

## 本轮范围

做：

- `LICENSE.md`：PolyForm Strict 1.0.0 官方原文，许可方写 Uniseem（不用真实姓名）
- `THIRD_PARTY_NOTICES.md`：`static/vendor/` 下三个第三方文件不受 PolyForm Strict 约束，附它们自己的许可证（Alpine、Sortable 是 MIT，要求保留版权声明）
- `README.md` 加「许可证」一节；设计文档加 17.8；`AGENTS.md` 加依赖许可证的规则和文档维护表一行
- 提交推送（推到现在的私有仓库，不涉及公开）
- 用户选定旧提交的处理方式后，再改公开

不做：

- 不替用户决定旧提交怎么处理
- 不删除任何 GitHub 仓库

## 验收标准

1. `LICENSE.md` 里的许可证正文和官方文件逐字节一致
2. ruff 干净，CI 绿
3. 公开后：按旧提交编号访问不到真实姓名
