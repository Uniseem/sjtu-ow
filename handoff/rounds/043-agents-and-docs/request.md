# 043 AGENTS.md 与文档维护规则

## 背景

用户 2026-09-17：「怎么没有 agents.md，还有目前项目的文档和进度的文档是怎么维护和更新的？都处理一下然后推送，以便后续继续开发」。

仓库刚推到正式仓库 `Uniseem/sjtu-ow`。之后可能换别的 AI 助手或者新同学接手，他们进来第一眼要知道：先读什么、怎么跑、有哪些硬规则、改了东西要同步哪份文档。

现状的问题：

1. **没有 `AGENTS.md`**，也没有 `CLAUDE.md`。入口知识散在 `handoff/README.md`、`README.md`、42 轮报告里
2. **`handoff/README.md` 描述的流程已经不是实际流程**：写的是「Grok 实现、Claude 设计与复核」，008 起实际是 Claude 连做（实现 + 自查）
3. **进度写在了好几个地方，而且互相矛盾**：
   - `README.md` 开头：「当前里程碑是 M5」（实际 M0–M6 完成，M7 进行中）
   - `docs/design.md` 头部：「设计评审中，尚未开始开发」
   - `handoff/STATUS.md`：M7 剩余项里还列着 031 轮已做完的「备份加密与异地同步」；「当前待定问题」一节还写着「不影响 M0」
4. **没有写明「改了什么要更新哪份文档」**

## 本轮范围

做：

- 新建 `AGENTS.md`（入口：先读什么、命令、硬规则、已知的坑、文档维护表）和 `CLAUDE.md`（引用 `AGENTS.md`）
- 重写 `handoff/README.md` 为实际流程
- **进度只写在 `handoff/STATUS.md` 一处**，其他文档改成指向它
- 修正上面列出的过时内容；`README.md` 分队一节改成 032 的拖拽 + 缓冲区
- 核对设计 19.2 待定问题的实际状态，写进 `STATUS.md`

不做：

- 不改业务代码和测试
- 核对中发现的未实现项只记录，不实现
- 不替用户拍板任何待定问题

## 验收标准

1. 新文档里提到的每个命令、路径、设置名都在仓库里存在
2. `ruff` 干净；没有改代码所以不重跑 pytest
3. git 提交，信息以 `043:` 开头，推送到 `origin`
