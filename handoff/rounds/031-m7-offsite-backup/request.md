# 031 异地备份：Cloudflare R2

用户定的：

> 备份用 Cloudflare 的 S3，管理员在后台可以设置。如果数据丢失了可以从 S3 恢复。

这是 022 轮起就挂着的**上线阻塞项**。

## 任务

### T1 后台可配置

`SiteSettings` 加对象存储的配置：地址、存储桶、区域、Access Key ID、Secret（加密存储）、路径前缀、开关。

### T2 加密后上传

设计 16.7 第 3 步：**上传前先加密**。

**加密密钥不能放数据库**——放进去的话，密钥就在它保护的那份备份里，服务器整个丢了就等于打不开。必须是环境变量。

没设密钥就不上传，不能把明文传出去。

### T3 从对象存储恢复

`restore --list-s3` 列出，`restore --from-s3 <KEY>` 下载、解密、恢复。

### T4 上传失败要让命令失败

一次没送出去的备份不能看起来像成功了。

## 测试要求

加解密往返、换钥匙解不开、没钥匙不加密、**密钥不是数据库字段**、开关关着不上传、配置不全要报错、上传失败要抛错、上传的内容不是明文、本地那份仍然可直接恢复、从桶里恢复能拿回数据、列表。

不要真连 R2——用假桶，这几条测的是我们的加密和接线，不是 boto3。

## 验收标准

1. `ruff` / `pytest` / `makemigrations --check` / 生产 `check --deploy` 干净
2. 跑一遍完整流程：备份 → 上传 → 列表 → 换钥匙解不开
3. 证明上传的内容不是明文
4. 回归 + `docker build`
5. git 提交，信息以 `031:` 开头
