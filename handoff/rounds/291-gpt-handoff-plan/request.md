# 291 写下一阶段交班计划（交 GPT）

## 背景

290 推送后（af2ae4c，CI 成功），前台各页面与独立后台代码已齐备，剩余主要是逐页验收、旅程、全站收口与割接准备。用户 2026-10-12 要求「需要我拍板的地方现在就问我，然后开始写下一步的计划，详细一些，给 gpt 看的」。

本轮先问用户拍板，结果：

| 问题 | 用户答复 |
|---|---|
| GPT 这一阶段负责哪些范围 | 「这一阶段 GPT 前后端都做」 |
| 授权哪些正式站运维操作 | 只授权「改 cron 的冬令时写法」；磁盘重测/清理、异地备份 R2 都未选 |
| 干部试用站（检查点 B）什么时候部署到测试机 IP | 「不做这个」 |
| 真实旧库迁移演练的数据怎么来 | 「拷正式站备份到测试机，用完删除」 |

用户随后中断并改要求：「我要的是一次性把剩下所有东西都干完的详细文档，而且要求代码全部写完再测试的那种」（原文末尾「都哪种」按上下文理解为「的那种」）。所以不按多轮拆，改写一份批次执行文档：GPT 先把全部代码写完，再在测试机集中测试，和 290 的做法相同。

## 本轮范围

做：

1. 新增 `docs/final-batch.md`：收尾批次的执行规格，读者是接手的 GPT。覆盖 STATUS 里全部剩余待办：正式站 cron、290 独立复核、验收工具、前后台补齐、割接材料、集中测试与两次真实旧库演练、出口标准、禁止项，附 STATUS 待办对照
2. 把用户本轮拍板写进权威位置：迁移文档第 10 节第 6 件、11.1 F10、11.2 第 8 包、11.6 改指向新文档；文档导航加入口；STATUS 头部、前台迁移说明、运维表
3. 按代码核对修正 STATUS 里过时的几行（`/sitemap.xml` 等、`/_styleguide/emails/`、退订一键 POST、A6、底座），补记 290 的 CI 结果；清掉已失效的 287–289 草稿说明
4. STATUS「最近轮次」超出 3 条的移进 archive

明确不做：

- 不改任何代码、测试、生成物或旧站；不改 OWNERSHIP 的长期分工和 AGENTS（本阶段例外只记 request 和 STATUS）
- 不登录任何服务器，不改正式站 cron（授权交给批次文档第 2 节由 GPT 执行）
- 不改页面验收结果：只修正和代码不符的文字，不把未验的标成通过
