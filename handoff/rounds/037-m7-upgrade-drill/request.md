# 037 升级与回滚演练

设计 16.8 是一份 8 步的升级流程，第 8 步是回滚。**这份流程从来没有人走过一遍。**

回滚是出事时在压力下执行的步骤，也是最不该临场发现问题的地方。022 轮做了备份恢复演练，但那是「误删数据后恢复」，不是「升级失败后回滚」——两者的区别在于**回滚时代码已经是新版本了**。

## 任务

### T1 走一遍完整流程

造数据 → 备份（第 2 步）→ 迁移（第 4 步）→ 模拟新版本改坏数据 → 回滚（第 8 步）→ 验证数据回到升级前。

### T2 第 8 步的要求逐条验

- 恢复第 2 步的备份
- **清空 prerendered 数据卷**（设计明写，否则静态页面比数据新）

### T3 「切回旧镜像」这件事命令管不了，但能提醒

设计第 8 步还写了「切回旧镜像」。如果恢复了升级前的数据库却还跑着新代码，schema 会比代码旧——**Django 不会立刻报错，要等某个请求碰到缺失的列**，那是回滚过程中最糟糕的发现时机。

命令没法帮你切镜像，但可以检查出来并说清楚。

## 验收标准

1. `ruff` / `pytest` / `makemigrations --check` / 生产 `check --deploy` 干净
2. 贴出完整演练的输出
3. 贴出「数据库比代码旧」时的提示
4. 清理演练数据，确认迁移状态没被弄乱
5. git 提交，信息以 `037:` 开头
