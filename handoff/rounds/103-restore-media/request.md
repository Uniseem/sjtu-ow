# 103 `restore` 在 Docker 部署里恢复不了上传文件

## 背景

102 往 169.58.217.180 恢复演示库时，`manage.py restore --yes` 换好了数据库，然后在「恢复 media」这一步报错退出：

```
OSError: [Errno 16] Device or resource busy: PosixPath('/app/media')
```

`/app/media` 是 Compose 挂载的数据卷。命令先 `shutil.rmtree(media)`：里面的文件删光了，删到挂载点本身时失败，后面的复制 media、清空 `prerendered`、删预渲染记录都没做。结果是**数据库是新的、上传文件全没了、静态页面还是旧的**。备份恢复是设计 16.7 的灾备手段，生产和测试机都是 Compose 部署，也就是说这条路径在真正用得到的地方从来没成功过。测试一直是绿的，因为测试里的 `MEDIA_ROOT` 是普通临时目录，删得掉。

用户 2026-10-03 说「继续做吧」，按 102 的计划修这一条。

## 本轮范围

**做**：

1. 恢复 media 时只清空目录里的东西、不删目录本身，再把备份里的文件复制进去；`prerendered` 用同一个函数清空（原来就是逐个删子项，行为不变）
2. 测试：模拟「目录本身删不掉」（挂载点），恢复要成功、文件要回来、静态页面要清掉；备份里没有的旧文件要被清掉
3. `AGENTS.md` 那条坑改成「103 已修」
4. 服务器 169.58.217.180 升级到修好的版本

**不做**：恢复前自动停服务（设计 16.7 说这一步交给运维，命令只提示）。

## 验证

新测试；变异：改回删整个目录、去掉「目录已存在也可以复制」、只复制不清空，三处都要红。整组检查。

## 验收标准

`AGENTS.md`「常用命令」那组全绿；变异全部被抓到；推送 `main`，CI 绿；服务器升级后 `/healthz` 正常。
