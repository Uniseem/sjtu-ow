# 020 内战：活动与报名

M6 的第一部分。和 M4 一样拆两轮：这轮做活动本身和报名（设计 9.1、9.2），**分队算法和后台分队页留给 021**（设计 9.3–9.6）。

## 范围

设计 9.1、9.2、12.9、附录 B 的 `Scrim.status` 与 `Scrim.format` 枚举。

## 任务

### T1 数据表

按设计 12.9 建 `Scrim` 和 `ScrimSignup`。

`Scrim`：标题、说明、开始时间、报名截止时间（可空 = 开始前都能报）、规格四选一、仅限交大、状态四选一、`teams_generated_at`、`reminder_sent_at`、`created_by`。

`ScrimSignup`：活动、用户、游戏 ID、三个位置布尔、`is_selected`、`team`、`assigned_role`、`rating_used`。**唯一约束 `(scrim, user)`**。

021 要用的字段这轮先建好，但不写业务逻辑。

### T2 后台活动管理

Wagtail 后台「社区 → 内战活动」，参考 014 的赛事后台。列表、新建、编辑。

**发布时安排提醒任务**：开始前 2 小时（后台可配置的偏移量）给所有报名者发提醒邮件，用 `reminder_sent_at` 防重复。改了开始时间要重新安排。

**取消时**邮件通知所有报名者。

### T3 前台列表页

`/scrims/`，公开可见。

- 显示已发布的活动，**以及最近 30 天内已结束的**，按开始时间排列
- **已取消的不在列表里**；详情页保留并显示「已取消」
- 草稿前台不可访问（404，不是 403——不要泄漏存在性）

### T4 前台详情页

`/scrims/<pk>/`，公开可见。

显示标题、开始时间、规格、说明、报名截止时间；报名统计（总人数，以及能打坦克、输出、支援的人数）；报名名单只显示**昵称和能打的位置**。

**不显示段位，不显示游戏 ID，前台不展示分队结果。**

### T5 报名

条件全都要查：已登录、有 `scrim_signup` 权限、资料完整、满足参与条件（`sjtu_only`）、活动已发布、在报名时间内、还没报过。

- 游戏 ID 必选，从自己的里挑
- 位置至少勾一个
- **角色限定规格**：勾选的每个位置，在所选游戏 ID 上都必须填了段位
- **不限位置规格**：所选游戏 ID 至少有一个位置填了段位

报名截止前可以改或取消。**取消时如果已经被勾选上场或分过队，要自动移出，并让后台看得到「分队有变化」**（`teams_generated_at` 之后发生的变化）。

### T6 半静态渲染

列表页和详情页都是公开页面，接到 010 的预渲染目标注册和 `/_fragments/` 插槽上，参考 013 的组队大厅和 014 的赛事。个人化的部分（我的报名状态、报名按钮）走插槽。

## 测试要求

至少覆盖：四种规格的报名校验（角色限定要求每个勾选位置都有段位、不限位置要求至少一个）、七种报名前置条件各自失败一次、重复报名、改报名、取消报名、**取消已分队的人要移出并标记分队有变化**、列表页只显示该显示的（已发布 + 30 天内已结束，不含已取消和草稿）、草稿详情页 404、详情页不出现段位和游戏 ID、报名统计数对、提醒任务的安排与不重复发送、改开始时间会重排提醒、取消活动发邮件、`(scrim, user)` 唯一约束。

## 验收标准

1. `ruff` / `pytest` / `makemigrations --check` / 生产 `check --deploy` 全部干净
2. 用真实浏览器走一遍：建活动 → 发布 → 报名 → 改报名 → 取消报名，贴出关键页面
3. 贴出详情页的 HTML 片段，**证明里面没有段位和游戏 ID**
4. 贴出提醒邮件和取消邮件的正文
5. 控制台无错误、无内联样式
6. 回归 + `docker build` + `caddy validate`
7. 清理验证数据，**并查一次全库计数确认干净**
8. git 提交，信息以 `020:` 开头
