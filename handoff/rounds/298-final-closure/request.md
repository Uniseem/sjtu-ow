# 298 完成剩余收尾

## 背景

用户要求「与云端同步，然后用最快的速度完成剩下的所有内容」。开工工作区干净，拉取远端基线 `3f2a31f`，继续 291 收尾批次及 297 未闭环项。

## 本轮范围

沿用本批 GPT 前后端范围、真实旧库备份直接流到测试机且用完删除、最多三名独立检出代理的已有授权。统一集成后台内容、活动、成员与设置修复；完成组件/账号最后边界、后台严格对拍、双引擎后台与 WebKit pages、两次最终真实演练、整组和提交 CI。复用未受影响的通过证据。

用户本轮明确选择：仅后台允许 `style-src-attr 'unsafe-inline'`，保留 CodeMirror；先更新新栈设计与规格，再改 Caddy 和验收。前台、脚本、样式元素及私有预览策略保持原要求。

不改冻结旧站、不新增依赖、不放宽对拍阈值或业务门、不清正式站磁盘、不配置 R2。上线前必须满足磁盘安全门；当前不足，部署/割接不在本轮执行范围。

## 任务与验收标准

1. 查基线精确 SHA CI、读取既有失败证据并批量修复。
2. 测试机后台串行执行受影响专项，日志分项落盘、真实退出码记录。组件四组合、账号最后边界、后台对拍、六旅程的证据闭环。
3. 最终源码整组全绿；两次最新真实旧库演练通过，第二次不超过900秒，输入与临时副本删除并核实。
4. 逐项对照 final-batch 完成标准，更新 report/review/STATUS，中文提交、同步推送 main 并检查该 SHA CI。

## 收口授权

用户在最终验收期间明确要求「差不多了，结束然后 push」。按本轮例外停止扩大验收，整理已得证据、失败和未复验增量后阶段性提交；最新共享离页修复/复制等待器不等待再跑整组。正在运行的真实备份演练完成后删除测试副本，第二次演练和完整最终矩阵不再启动。推送后检查精确SHA的CI；本例外不改长期验收规则。
