## 任务

### T0 顺带提交

工作区里 `docs/design.md` 的 v1.5.4 改动是我在 006 复核时写的，还没进版本库，本轮提交时一并带上。

### T1 字体库（设计 13.12.1、12.4.3、12.4.4）

1. `FontFamily` 和 `FontFace` 两张表，字段按 12.4.3、12.4.4 节
2. 三种添加方式：
   - **上传字体文件**：TTF / OTF / WOFF / WOFF2，单个不超过 30MB
   - **从 Google Fonts 下载**：输入字体名和字重，服务器后台下载
   - **从网址下载**：输入字体文件地址，下载后按上传流程处理。只允许 HTTPS、禁止内网地址、限制大小（设计 15.2）
3. 授权：必须选授权类型并勾选确认；从 Google Fonts 下载的自动记为开源；读 OS/2 表的 `fsType`，**标记为禁止嵌入的字体拒绝处理**
4. 字体库操作：预览（示例文字见附录 C）、下载字体文件、查看处理状态和失败原因、重新处理、删除（被排版设置引用时不能删）

**关于网络**：开发机在国内，`fonts.googleapis.com` 很可能连不上。请按这个顺序验收：优先用「从网址下载」拉一个开源中文字体（比如 GitHub 上 OFL 协议的字体 release），连不上就退回「上传」路径用本地的开源字体文件。**Google Fonts 那条路径如果本机验证不了，就在报告里写明「未验证」并说明原因**，不要写没跑过的结果。

### T2 字体处理（设计 13.12.2）

1. worker 后台处理：fontTools 解析、校验格式和嵌入权限、读取字重和字符数
2. **切片**：英文数字标点一片；常用汉字按使用频率每片约 200 字；其余按 Unicode 区段切成较大的片。每片单独生成 WOFF2
3. 每片生成带 `unicode-range` 的 `@font-face` 规则
4. 分片文件名带内容哈希，放 `media/fonts/<字体 ID>/`
5. 从 Google Fonts 下载的字体已经切好片，直接下载分片并改写地址，不重新切片
6. 任务队列同一时间只处理一个字体；后台显示处理进度和失败原因；处理中或失败的字重在排版设置里不能选

### T3 排版设置（设计 13.12.3、12.4.5）

1. `TypographyRule` 九个区域，由 `init_site` 创建，只能改不能增删
2. 每个区域可设：字体（系统字体 / 跟随正文 / 字体库中的字体）、字重、字号、行高、字间距；正文区域不能选「跟随正文」
3. 后备字体自动接系统字体
4. 实时预览：设置页旁边显示文章、卡片、按钮、分队结果样例，改了立刻看到
5. 保存后生成 `fonts.<内容哈希>.css`，内容按 13.12.4 节：只写被使用的字体的 `@font-face`、每个区域的 CSS 变量；`font-display: swap`
6. 全站布局引用这个文件；`SiteSettings.font_css_path` 记录地址
7. **不要改模板里已有的字体类名**（`font-nav`、`font-button` 等），它们已经在用同一套 CSS 变量

### T4 性能约束（设计 13.12.5）

1. 同时启用的「字体 × 字重」超过 6 个时，保存前警告
2. 排版设置页显示每个区域所用字重的分片数量和总大小
3. 内容安全策略保持 `font-src 'self'`，不放开外部字体域名

### T5 后台

菜单挂在「设置」下：字体库、排版设置。只有超级管理员可见。

## 测试要求

至少覆盖：上传非字体文件被拒、超大文件被拒、`fsType` 禁止嵌入的字体被拒、切片覆盖字体全部字符且互不重复、生成的样式表只包含被使用的字体和字重、九个区域的 CSS 变量都生成、正文区域不能选「跟随正文」、被引用的字体不能删除、从网址下载时内网地址被拒。
