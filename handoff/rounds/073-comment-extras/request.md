# 073 评论增强

## 背景

072 做了评论基础。用户要的 YouTube 要素还剩：点赞、最新/最热排序、管理员置顶、编辑自己的评论；再加作者删除。设计 5.6 已写明这些在 v1.9.1 落地。

## 本轮范围

做：

- 设计 v1.9.1：5.6 去掉「v1.9.1」标记；12.15.2 `CommentLike` 表；13.4 五条路由；附录 C 点赞限流；附录 D
- 迁移 `comments/0002`：`CommentLike(comment, user, created_at)`，唯一 (comment, user)
- 服务：`toggle_like()`（`F()` 增减计数，隐藏或已删除的不能赞）、`pin()` / `unpin()`（内容编辑；每篇只一条置顶，置顶新的自动取消旧的；只能置顶顶层）、`edit()`（仅作者，长度校验，`edited_at`，重新送审）、`delete()`（仅作者，正文清空、行保留，有回复的顶层显示「评论已删除」占位，不能再赞、再回复）；`thread()` 加 `sort`（`new` 默认；`top` 按置顶、赞数、可见回复数、时间）和当前用户点过的赞
- 端点：`/comments/<pk>/like/`、`/edit/`、`/delete/`、`/pin/`、`/unpin/`（POST，返回整块评论区）；点赞每人每分钟 60 次；「加载更多」带排序
- 模板：排序切换链接（静态页也有，走带参数的实时渲染）；点赞按钮与赞数；自己的评论有编辑（`<details>` 里的表单）和删除；内容编辑有置顶 / 取消置顶；已删除占位
- 测试与变异；附录 C pin；地址清单；README、STATUS

明确不做：点踩；按热度的回复排序；通知。

本地检查全绿（逐条看退出码）；新守卫逐个变异被抓到；CI 绿。
