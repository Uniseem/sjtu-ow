# 107 复核结果（自查）

## 结论

自查通过。演示站成员页图片从 4.2MB 降到 505KB，首页、资讯、战队每页二三十 KB；首屏以外的图片都懒加载。

## 验证记录

- **对照用户原话**：「你是不是没做懒加载？」：如实回答（大部分做了、漏了文章正文图），补上，并且用测试把「每张图要么懒加载、要么是首屏」固定下来；真正的慢是图大，用数字说明
- **格式**：测的是实际生成的文件（用 Pillow 打开看格式），不只是文件名；透明 PNG 转 WebP 后左上角像素的透明度仍是 0
- **分享图**：单独要 JPEG，测试看地址的扩展名
- **演示站**：第一次清缩略图漏了 41 条，查库定位到原因后重跑，最后库里 103 个 WebP、6 个 JPEG（分享图），页面里 0 个 PNG
- **重跑**：整组检查和变异在提交前跑过，输出在 `report.md`

## 发现的问题

必须修：无。

建议修：`report.md` 两条。

## 判断里最没把握的

1. **质量 80**：Wagtail 的默认值，动漫头像在 400px 下看不出差别；如果用户觉得糊，可以调到 85–90，体积大约多三到五成
2. **首屏的判断靠类名**：新加首屏图片要用这几个类名之一，否则测试会要求它懒加载；这是有意的，宁可让人停下来想一想
