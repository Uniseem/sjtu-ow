# 264 F1 底座（三）：旧图母版、测试会话、对拍工具

## 背景

接 263。两件事：

1. **旧图出不来**（263 发现）：`sjtuow import` 只把 `wagtailimages_image` 的行导进 `images`，原图从没过新管线变成母版（`data/originals/<id>.webp`），错误还被吞了。缩略图从母版生成，所以正式站的 479 张旧图在新栈里全部 404，263 的出图接口上线了也一样
2. **对拍工具**：`docs/frontend-migration.md` 9.2 定的验收方法——同一份数据、旧站和新站各起一套、逐页逐身份比——还没有工具。之后每组页面「做完」都要拿它的结果说话（9.4）

## 本轮范围

做：

1. `media.ImportLegacyMasters` + `sjtuow import-media <旧站媒体目录>`：每一行没有母版的，按 `file_name` 到旧站媒体目录找原文件，查像素、完整解码、长边缩到 2560、重新编码成 WebP（不带 EXIF、GPS）；已有母版跳过（可重复跑）；越出目录的文件名、找不到的、坏的分别报出编号和原因，坏的让命令退出码 1。`Upload` 和它共用编码与写母版的函数（`encodeMaster`、`writeMaster`），编码完就放开信号量
2. `sjtuow session <邮箱>`：给已有用户发一条会话、打印令牌（测试和对拍用，不输入密码）
3. `e2e/parity/parity.py`（入口 `run.sh`）：
   - 旧站：`scripts/screens.py` 的种子数据（会员、队长、站长、战队、个人赛、整队赛、内战、文章、分组、待发信），外加整队赛的报名单编号
   - 新站：`sjtuow migrate` → `import` 旧库 → `import-media` 同一个媒体目录 → `session` 发三个身份的会话；Go + SSR 生产构建 + 真 Caddy（`deploy/Caddyfile.new` 容器）
   - 48 个「地址 × 身份」（文档第 6 节的前台页面，后台留到 F8）；每个比状态码和跳转去向、`<title>`、`#main` 纯文本、`#main` 链接、表单控件、新站坏图、`#main` 截图像素差（默认 1280 浅色，`--wide` 加 375 和深色）
   - 出 `report.md`、`results.json`、截图；`--only=前缀` 只跑一组；`--strict` 有不通过就退出码 1
4. 跑一次全量对拍，把结果作为前台迁移的基线记进报告和 STATUS 的进度表

不做：

- 修页面（对拍现在大部分「不同」是预期的，这是基线）
- 后台页面的对拍（F8 起加进清单）
- 正式站上跑 `import-media`（要部署和用户点头；写进下一步）
