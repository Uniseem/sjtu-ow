# 218 重构前在现行站上先修的三件事

## 背景

2026-10-07 用户说「开始重构吧」，对象是 `docs/rewrite-research/` 那套调研（Vue 3 + Go）。`12-architecture.md` 第 11.1 节和 `00-plan.md` 的「建议第一步」都写了：**重写开工之前，现行站上有死线、或者已经复现的暴露面问题先修**，修完现行站功能冻结，只修安全和丢数据的问题。

同一天用户拍板了 M0 要写进设计 v8.0 的四个决定（`12` 第 12.1 节），都按推荐：

| 编号 | 决定 |
|---|---|
| D1 | 公开页用自己写的薄 SSR（Node，无状态、不缓存 HTML），不用 Nuxt；设计 2.1「不依赖 Node」要改 |
| D2 | 「没有脚本时照旧能提交」只保阅读，动作要脚本；脚本没加载上有横幅 |
| D3 | 新代码放同一个仓库（`server/`、`web/`、`e2e/`），割接后删 Django 代码 |
| D4 | 字体库：已切好的原样搬，新字体用仓库里的离线工具切好再上传成品包，生产没有 Python |

D5–D7 按文档推荐（AI 巡查割接后再做；镜像在 CI 构建推 GHCR；文章修订只搬已发布那份和最新草稿）；D8、D9 到检查点 B 和割接前再问。

本轮是「先做」里**不碰图片**的三件，图片管线（07-1、07-2、07-3、02-1、02-2、02-4）单独一轮（219），因为它改的文件多、要动上传的每个入口。

## 本轮范围

做：

1. **04-1（高，已复现）**：`/wagtail/login/` 和 `/_util/login/` 绕过 allauth——没验证邮箱的账号能登进去，而且这两个登录页完全不限次数。两个地址都改成跳到 `/accounts/login/`（带上安全的 `next`），Wagtail 页面访问限制的登录跳转也直接指向 allauth。登录入口全站唯一（`12` 不变量 6）
2. **03-1（中，隐私）**：评论的点赞、编辑、删除、置顶、取消置顶、隐藏、取消隐藏七个接口按评论编号取评论，不查所属文章是否上线、是否公开；带 `HX-Request` 头能读出撤下或私密文章第一页的整块评论。七个接口（含点赞、编辑超限的两个分支）都先过 `_page_or_404`
3. **09-9（有时限）**：正式站 cron 按柏林夏令时写死的北京时间，2026-10-25 柏林改冬令时后整体晚一小时。仓库里给一个不受服务器时区影响的做法，README 和 `deploy/crontab.example` 的换算说明跟着改，**正式站的 crontab 本轮不动**（要上服务器，等用户点头）

不做：

- 图片管线（219）、15-2/01-2、13-1 等其余「拖垮全站」和「丢数据」类（217 review 的建议顺序里第 2、3 步）。它们是现行站在重写期间的最小修复集，按重写节奏在 219 之后逐轮做，不挡 M0
- `/wagtail/` 里别的问题（04-2、04-3、04-4、04-5）：都要超管才能碰，新站没有 Wagtail，不修
- 正式站部署和 crontab 改动

## 任务

1. `accounts/views.py` 加 `login_door`：任何方法都 302 到 `account_login`，`next` 只在是本站地址时带上；`sjtu_ow/urls.py` 把 `wagtail/login/`、`_util/login/` 放在对应 include 之前；`settings` 加 `WAGTAIL_FRONTEND_LOGIN_URL = "account_login"`
   - 验证：没验证邮箱的账号 POST 两个地址都登不进去；60 次错密码以后正门照样限流（不是侧门不限）；`next` 带外链时被丢掉；结构守卫——全站每个叫 login 的地址只能解析到 allauth 或 `login_door`
2. `comments/views.py`：`_moderate`、`_act`、`like` 和 `edit` 的超限分支统一用 `_page_or_404(comment.page_id)`
   - 验证：撤下的文章、带密码的文章下，七个接口对别的成员都是 404，不带 HX 头也一样；响应里没有评论正文；点赞数、正文没有被改；正常文章不受影响（现有评论测试全绿）
3. `deploy/` 加按北京时间触发的包装（`deploy/at-shanghai.sh`：每小时的 cron 条目调它，它用 `TZ=Asia/Shanghai date` 判断当前是不是目标时刻再执行命令），`crontab.example` 改成每小时一行、README 的换算说明改掉
   - 验证：包装脚本在柏林夏令时和冬令时两种 `TZ` 下，对同一个北京时间都只在那一刻执行一次（用 `faketime` 或者把「当前时间」做成可注入的环境变量测）

每条新规则都有拆掉就红的测试（硬规则 7），写完把对应的检查改坏跑一遍。

## 验收标准

`bash scripts/remote-check.sh` 整组全绿（ruff、tailwind build、pytest、makemigrations --check、check --deploy）；新测试逐条做变异。推送后看 CI。
