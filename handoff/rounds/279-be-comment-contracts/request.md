# 279 评论权限与编辑时间

## 背景

用户要求「规划一下，规划完自己开始做。不需要询问我，自己做决策」。本次连续开发按依赖先补 BE-4–8，再补账号/内容真实验收，然后推进 F5 个人中心、F6 战队成员、F7 赛事内战、F8/F9 后台，最后 F10 全站验收与试用。每一阶段仍按 frontend-migration 的逐页完成定义，不以接口单测代替页面对拍或真实旅程。

本轮由 Codex 接手后端待办，是本轮范围例外；不更改 OWNERSHIP 的长期分工。后续涉及前端的轮次单独记录用户本次自主推进授权。正式站继续旧 Django，本轮不部署、不删旧站、不引入依赖。

## 本轮范围

- BE-7：session.user 添加 can_comment，表达 article_comment 功能权限本身，独立于邮箱验证和后台 caps。
- BE-8：新增可空 edited_at 存储与投影；只有作者实际修改正文时更新（正文相同不制造编辑记录）；隐藏、置顶、点赞、删除不伪造编辑时间；旧库导入保留该值。
- 生成 API 契约；测试真实路由、编辑/管理操作、旧库导入以及已有库升级。
- 不改页面、pending-api 或旧站；BE-4–6 留下一轮同组处理。

## 任务与验收标准

1. 会话真实 API 覆盖未验证/已验证成员、个人禁用、角色禁用、个人允许覆盖角色禁用、超管、访客与停用账号；断言 can_comment 和 email_verified 独立。
2. 评论真实 GET 列表/回复与 PATCH 投影输出 edited_at；新评论为 null，修改后为 RFC3339 时间，管理员隐藏/恢复/置顶、点赞和删除不改变该时间。
3. 旧库导入验证 edited_at 的 NULL 与带微秒时间，重复导入不损坏。
4. 已有数据库升级保留正文和 updated_at，旧评论 edited_at 为 null（不能根据管理更新时间猜测编辑历史）。
5. 测试机后台专项、规则变异、apigen、整组检查全绿；一个中文提交，推 main 后检查对应 SHA 的 CI。所有结果写 report/review，未跑项目注明未验证。
