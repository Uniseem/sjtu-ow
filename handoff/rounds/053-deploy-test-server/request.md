# 053 部署到测试机

## 背景

上线计划的第 3 步。测试机 `185.99.135.224`，域名 `sjtu.ow-shanghaiuniversity.com`，部署算**测试环境**（用户 2026-09-18 定的）。用户要求证书走 HTTP 验证，HTTP 自动跳转 HTTPS。

这是项目**第一次在真实服务器上部署**。README 和设计 16.4 的部署步骤都没在真机上走过，要边走边把它改成照着做就能成功的清单。

## 任务

1. 按设计 16.4 在测试机上从零部署：
   - 代码从公开仓库 clone 到 `/srv/sjtu-ow`
   - `.env` 在服务器上生成，密钥**直接在服务器上随机生成写入文件**，不经过开发机、不出现在对话和仓库里
   - Compose 项目名用 `sjtu-ow-test`（设计 16.10：测试环境是另一套 Compose 项目），`TEST_ENVIRONMENT=1`
   - 构建、启动、迁移、`createcachetable`、`init_site`、全量预渲染
2. 验证：
   - 证书是 Let's Encrypt 签的，域名匹配
   - `http://` 自动跳转到 `https://`
   - 首页有测试环境横幅；`robots.txt` 禁止全部抓取
   - `/healthz` 返回 200
   - 容器状态健康
   - **不影响机器上的其他项目**：部署前后对比它们的容器状态
3. 部署中发现的问题当场修（代码或文档），写进报告
4. 把实际走通的步骤写成清单放进 `README.md`

不做：

- 不创建超级管理员账号（账号和密码由用户自己设）
- 不配 SMTP、R2、DeepSeek（用户还没给）
- 不改服务器的系统配置（SSH、防火墙）

## 验收标准

每一条验证都有命令输出；本地四项检查干净；推送后 CI 绿。
