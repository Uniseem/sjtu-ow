## 自查中发现并已修掉

- **A1 `check --deploy` 被 drf-spectacular 的 9 条警告污染**：它默认扫描全部 DRF 视图，把 Wagtail 自带的后台 API 也算了进来。加了预处理钩子只保留 `/api/v1/`，部署检查恢复干净。**这条很重要**：`check --deploy` 是每轮的验收信号，不能长期带警告。
- **A2 调用日志里成功请求的客户端是空的**：DRF 的 `Request` 是包装对象，中间件拿到的是原始 `HttpRequest`。改成同时写到 `request._request`。
- **A3 `request.GET.items(multi=True)` 不存在**：Django 的 `QueryDict` 没有这个参数，重复查询参数会丢。改成用 `getlist()` 展开。
- **A4 `timezone.utc` 已被移除**：改用 `datetime.timezone.utc`，否则 `ping` 直接 500。

## 建议修（转 018 / 019）

- **B1** 调用日志每次调用一次写库。按设计 15.1 的规模（上游调用不密集）没问题，真被打爆时可以改成批量写或采样。
- **B2** Nonce 和限流都用数据库缓存表，和业务共用一个 SQLite。设计 12.13 就是这么定的，但上线后要看 `django_cache` 表的增长。
- **B3** 调用日志 90 天、Webhook 记录 180 天的清理任务还没接（设计 16.5），放在 019 一起做。

## 认可的判断

- **Secret 加密存储而不是哈希**：验签需要原文，设计 12.10.1 已经明确；用的是 005 就建好的 `EncryptedTextField`，并且加了「数据库里是密文」的测试。
- **七步顺序照搬设计**：错误码的顺序本身就是对接文档的一部分，先判缺头再判 Key 再判时间，上游排错时看到的提示是可预期的。
- **Nonce 按客户端分桶**：两个上游的随机串撞车不该互相影响。
- **认证失败也写日志**：排查「上游说调不通」时，这是唯一的线索。
- **测试里原样照抄设计的示例代码**：文档给出去的示例和真实实现如果哪天不一致，这条测试会立刻发现。
