# 050 复核结果

## 结论

**通过。** 只改文档，服务器上只执行了只读命令。

## 值得记的

- **本地 DNS 不可信**：开发机开着代理，`dig` 返回的是代理的虚拟地址。如果照着它写，会在文档里写下一个错误的 IP，还会误判「域名没解析过去」。以后查 DNS 用公共 DNS 的 HTTPS 接口
- **CNAME 到线路优化服务**是这次最大的隐患：按地区返回不同 IP 的话，证书会申请失败，而且失败信息看起来像是 Caddy 的问题。提前从海外视角查过，是一致的

## 判断里最没把握的

- **80 端口从外面能不能访问**：主机防火墙没拦，但云服务商那一层的安全组看不到。部署时申请证书就会知道
- **这台机器上的部署算测试环境还是正式站**：用户说「作为测试机，部署也先放在上面」。设计 16.10 要求测试环境显示横幅、禁止搜索引擎抓取，这两样还没实现。已列进 `STATUS.md` 等用户确认
