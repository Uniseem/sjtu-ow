## 判断里最没把握的

1. **日志历史行不改写**。设计 12.8.4 说只增不改，我照办；代价是旧行的 `awaiting_upstream` / `upstream` 会以原始值显示。另一种做法是映射并在备注里注明「原上游」，更好看但改了历史。测试机上很可能一条都没有，所以先按设计来
2. **墓碑包**。`integrations` 留三个空文件永远挂在 `INSTALLED_APPS` 里，不好看。正确的清理是等所有库都迁过 0005 后压缩 tournaments 的迁移；现在测试机动不了，等 074 上线收尾时再说
3. **`pyyaml` 显式化**是不是违反硬规则 5。我判断它不是新依赖（一直装着、测试一直在用），但确实是我自己定的
4. **Wagtail admin API 用测试客户端验证，没在浏览器里点**。去掉 `REST_FRAMEWORK` 后 `/admin/api/main/pages/` 返回 200 且带 `meta`，页面资源管理器就是调这个接口。没开浏览器是因为登录后台要输密码，改用超级管理员 `force_login` 更可重复
5. **自动通过的邮件措辞**。系统通过只发「报名已提交」一封，正文写「当前状态：已通过」。同步名单时那封主题是「报名名单已同步」，也写已通过。没有单独的「已通过」主题，队长要看正文；如果觉得不够醒目，下一轮把主题改成「报名已提交并通过」
