# 058 注销账号与导出个人信息

## 背景

用户 2026-09-18 对上线前的待定项拍板：

| 事项 | 决定 |
|---|---|
| 账号注销和导出个人信息 | **按设计建议做**（19.2 第 6 条） |
| 后台两步验证 | 上线先不做 |
| 用户协议和隐私政策正文 | 我起草，社团改（下一步） |
| 「高风险内容暂缓公开」开关 | 上线前不做 |

设计 15.3 要求有注销渠道，隐私政策也要写清楚怎么删除个人信息，所以注销和导出是上线前必须有的。

## 先改设计

19.2 只有一句建议。新增 **3.8 节**写清楚细节（导出包含什么、不包含什么；注销改什么、删什么、留什么；队长要先转让或解散）；路由表加两个地址；19.2 第 3、4、6、12 条结案；附录 D 记 v1.5.13。

## 任务

1. `accounts.services.personal_data(user)` 和 `/me/export/`：按 3.8 节导出 JSON，限流每人每小时 5 次
2. `accounts.services.delete_account(user)` 和 `/me/delete/`：要当前密码；队长拒绝；其余按 3.8 节。在一个事务里做完
3. 「账号安全」页加两个入口
4. 测试：
   - 导出包含该有的、不包含别人的信息和密码
   - 注销后每一项都对：邮箱、密码、停用、昵称、游戏 ID、联系方式、战队、入队申请、内战报名（含「分队有变化」）、用户组；名单快照和署名文章保留
   - 队长被拒、密码错被拒
   - 注销后原邮箱能重新注册；其他设备上的登录失效
5. 逐项变异

## 注意

- `ScrimSignup.game_account` 是 `PROTECT`：要先删内战报名才能删游戏 ID
- `RegistrationMember.game_account` 是 `SET_NULL`，名单快照里的昵称和游戏 ID 是文本，不受影响
- 改昵称会触发 057 的页面刷新，所在战队页、内战页、署名文章会重新生成

## 验收标准

本地四项检查干净；推送后 CI 绿；测试机上能打开两个页面。
