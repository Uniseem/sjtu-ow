# 012 M3 第一部分：战队

> 用户外出期间，本轮仍由 Claude 实现 + 自查。

## 背景

M2（内容、投稿、字体、半静态渲染、AI 审核）已完成。M3 是战队与组队大厅，本轮先做战队，下一轮（013）做组队大厅。

设计依据：`docs/design.md` v1.5.7，重点读第 7 章、12.6、13.4（路由）、13.13.3（占位区域）、附录 C。

## 本轮范围

**做**：T1–T8。
**不做**：组队大厅（013）、赛事报名（M4）。战队解散时的「有效报名」检查按设计要拦，但 `Registration` 表还不存在，本轮留一个明确的接口，M4 接上。

## 任务

### T1 数据表（设计 12.6）

`Team`、`TeamMembership`、`TeamApplication`，含：未解散战队的队名不区分大小写唯一、每队一个队长的部分唯一约束、`status = pending` 时 (team, applicant) 部分唯一。

### T2 创建与编辑（设计 7.1）

队名 2–16 字、简介 500 字、队标（JPG/PNG/WebP、5MB、正方形裁剪）、招募中默认开。需要 `team_create` 功能权限；每人最多同时担任 3 支战队队长（读后台设置）；创建者自动成为队长；队长可随时编辑。创建限流：每人每天 3 次。

### T3 战队主页与列表（设计 7.2、7.6）

- `/teams/`：公开，只显示未解散的，可筛选「只看招募中」，按创建时间倒序，卡片显示队标、队名、成员数 / 上限、招募状态。
- `/teams/<id>/`：公开，显示队标、队名、简介、招募状态、队长、成员列表（昵称、队长标识、入队时间）。**成员的游戏 ID 和段位不在主页显示**。招募中且未满员时显示「申请加入」。参赛记录留到 M4。
- 已解散：主页显示「该战队已解散」，不进列表、不进 sitemap。

### T4 入队申请（设计 7.3）

意向位置必选至少一个、留言 200 字。条件：已登录、有 `team_apply`、至少 1 个游戏 ID、不是成员、招募中且未满员、没有待审批申请。限流每人每天 20 次。提交后邮件通知队长；申请页提示「提交后队长可以看到你的游戏 ID 和段位」。队长在管理页逐条通过 / 拒绝（可填原因），**通过时在同一个写事务里再次检查未满员和不是成员**；结果邮件通知申请人；被拒后可再申请；申请人可撤回。

### T5 成员管理与解散（设计 7.4、7.5）

退出（队长不能直接退出）、移除成员（不能移除自己，邮件通知）、转让队长（只能转给现有成员，邮件通知）、超级管理员指定队长。解散：队长或超级管理员；有「有效报名」时拒绝（本轮留接口）；解散后软删除、删成员、待审批申请转已取消、邮件通知全体成员；队名可被新战队使用。

### T6 个人中心

`/me/teams/`：我所在的战队（含身份）和我提交的入队申请（含状态、可撤回）。把 005 留下的「即将开放」换掉。

### T7 接入已有机制

1. **AI 审核**：队名、简介在创建 / 修改时送审；入队留言在提交时送审（设计 5.5.1）。
2. **半静态渲染**：`/teams/` 和 `/teams/<id>/` 预渲染；战队创建、修改、成员变动、招募状态变化、解散时重新生成（设计 13.13.4）；「申请加入」按钮做成占位区域 `team-join`，未登录访客看到的是静态页里的「登录后申请」。
3. **sitemap**：未解散的战队进 sitemap。

### T8 后台

「社区 → 战队」：超级管理员可以查看、编辑、指定队长、解散。

## 测试要求

至少覆盖：队名唯一（不区分大小写、已解散的不占用）、队长数量上限、`team_create` / `team_apply` 被禁用时的提示、申请条件逐条、重复申请被拒、审批时的并发检查（满员 / 已是成员）、队长不能退出、不能移除自己、转让后角色互换、解散后成员清空且申请转已取消、解散战队的主页提示、五封邮件、限流、战队页面不显示成员游戏 ID、预渲染事件、`team-join` 占位在未登录时的内容。

## 验收标准

1. `ruff` / `pytest` / `makemigrations --check` / 生产 `check --deploy`
2. 浏览器真实走一遍：创建战队 → 另一个账号申请 → 队长审批 → 成员列表 → 转让队长 → 退出 → 解散，贴出关键页面
3. 手机宽度（375px）下同样可用
4. 贴出预渲染文件里 `/teams/<id>/` 的内容，确认不含成员游戏 ID、不含 CSRF token
5. 回归：前台各页、`/me/`、`/healthz`、后台
6. `docker build`、`caddy validate`
7. git 提交，信息以 `012:` 开头
