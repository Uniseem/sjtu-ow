# 093 复核结果（自查）

## 结论

自查通过。自查时找到三处问题，当场改了（见下）。同一个人连着做的自查不能代替独立复核。

## 验证记录

- **重跑**：整组检查和变异在写报告前跑过，输出贴在 `report.md`
- **对照用户原话逐条核对**：
  - 「所有的比赛都是默认报名」：新赛事的报名方式默认「个人报名」（测试 `test_a_new_tournament_takes_individuals`）
  - 「只有管理有发布时指定了整队报名时才会整队报名」：后台「报名规则」第一项；有人报名后锁定（战队报名和个人报名两种都算，测试分别覆盖）。我没有做成「只能在发布那一刻选」，而是「发布前后都能改，直到有人报名」，因为发布后、开放报名前改错了要能改
  - 「不需要成员确认，队长报了直接整队拉进去」：原来的流程本来就不要确认，这次在报名页和赛事页写明了，游戏 ID 默认选好；另外给队员发邮件、在赛事页显示「你在「队名」的名单里」，让被拉进去的人知道
  - 选项「不能，只收战队」：整队报名的赛事拒绝个人报名，个人报名的赛事拒绝战队报名，服务端拦（不只是不显示按钮）
  - 「内战上面怎么没有 svg 动图背景」：内战详情横幅现在是占位图（会动的那 36 张之一，按 ID 固定），深浅色截图都核对过
- **截图**（无头 Edge，1440 宽，未登录）：整队报名的「秋季校内杯」、个人报名的「新生杯」（浅色、深色）、赛事列表、内战详情（浅色、深色）。登录后的报名入口只有测试覆盖，没截图
- **本机开发库**：跑了 `tournaments/0008`，迁移把「秋季校内杯」（原来两种都开）换成了个人报名，按 STATUS 升级说明里的那条手动改回整队报名

**自查找到并改掉的**：

1. **散人名单的卡片坏了**：赛事页的散人名单用的是 `c-people` / `c-person`，092 把这两个改成了图在上的大名片，这里的结构没跟着改。换成成员页的小卡 `c-roster`（底图首字头像、昵称、位置）
2. **侧栏说明折成三行**：「每人自己报名，管理员编队」在侧栏里被拆成「管理员编 / 队」，改短成「每人报名，管理员编队」「队长为全队报名」
3. **旧说法**：赛事列表页头（「开放个人报名的赛事也可以…」）、「我的报名」空状态、样张页还写着旧开关，一起改了

## 发现的问题

必须修：无。

建议修：

- 同步名单时被移出名单的人（离开战队后队长同步）不会收到信。用户说不需要确认，这次只管「被加进去」的通知
- 迁移把「两种都开」的旧赛事换成个人报名。测试机上如果有这样的赛事并且已经有战队报名，升级后要管理员看一眼（STATUS 升级说明里写了）

## 判断里最没把握的

1. **报名方式什么时候锁**：用户说「发布时指定」，我做成「有人报名之前都能改」。如果社团希望发布后就不能改，加一条「已发布不能改」就行
2. **队员邮件**：用户没要求，是我加的。理由是队员被拉进名单却不知道，到比赛那天才发现；不想要可以去掉
3. **个人报名赛事里的队长**：现在和普通人一样个人报名，管理员编队时可能把队长和队友分开。用户选了「只收战队 / 只收个人」二选一，这是二选一的直接结果
4. **侧栏一句话说明**：「每人报名，管理员编队」「队长为全队报名」是我写的，访客看到的第一印象就是它
