## 4. 接班第一小时做什么

先 `git status --short`。不干净就停下说明有哪些文件，交给用户决定；不替别人提交，也不删除别人文件。干净才 `git pull --rebase`。

随后核对 STATUS 最新轮次与最大轮次目录，分配「最大号 + 1」，目录名用 `NNN-be-具体任务`。不要把前端 next_frontend 中写的预测轮次当作保留号；两边共享一个递增序列。写 request 时限定一个或两个有关的接口组，不写「后端剩下全部做完」。

先确定当前 BE 表有没有新增的前端阻塞。有明确 BE 就优先处理。若 BE-0–3 已标后端完成，不重复实现；读 273/274 报告和生成类型，确认对方尚需的是接入或额外字段。

第一轮建议核查文章公开访问和首页页面数据，再补会话 B3。原因：Claude 正在推进文章/资讯/首页，需要真实可用的页面数据；这些也是后续个人中心与页头的基础。先用源码和一个小的真实接口测试证明缺口，再写具体实施范围。

## 5. 剩余后端工作建议顺序

以下是分组指导，不是说每项都尚未实现。**每项都先查 api.go、service、注册表和生成的类型，已有的扩展和验证，不新建第二套同功能服务。**

### 5.1 优先：公开内容可见性与首页数据

入口：internal/content/{api.go,home.go,store.go,service.go,import.go}、internal/agenda、旧 content/views.py、首页/文章模板、设计 5.2、细节文章/首页章节。

逐项查：

- 文章详情和列表的公开门是否与旧站一致。274 的 pages.search_public 是**搜索可见标记**，不能声称整个站的 Wagtail 访问限制已迁完；新闻详情、新闻列表、首页卡片、sitemap 是否能暴露受限文章，都要单独查。已发布不等于公开，未发布/无权限对象应 404。
- 文章页数据是否包含实际需要的最近更新时间、分类/封面、目录、作者卡、作者公开信息/文章数、关联赛事卡、前后篇、同栏目最新文章、评论相关状态。NewsDetailOut 的字段不能因为文章实体里有就当作已经输出。
- 列表分类筛选、分页、总数、栏目简介、默认封面和排序是否与旧站一致。生成客户端查询参数已有支持，先看生成函数签名，别照旧 STATUS 重写 apigen。
- HomePageOut 是否给登录成员的「我的安排」。agenda.Items 已有服务和 `/api/me/agenda`，应该组合已有逻辑，避免重复 SQL/状态计算。遵守一页「页面接口 + session」的请求预算；不能要求前端每块另打一条 API。
- 首页成员统计目前源码计 is_active，旧设计口径还要求邮箱验证；这是需回归核查的明确候选。用同时有已验证、未验证、停用用户的数据测试，不能只放一个正常成员。
- 时间用请求注入 clock，统计/阶段分类不要绕过固定测试时钟；显示相关时间按上海时区，落库仍 UTC。
- 首页多处 `_ = QueryRow.Scan` 或失败吞空值要检查，数据库失败不能画成「社区没有内容」的成功页。
- 保留首页固定区块选择、上限和空区块规则，后端只给真实投影，不为了旧截图灌假内容。

验收：公开/草稿/受限/不存在四种文章，访客/成员/作者/编辑/超管；首页访客与两名不同成员不互相看到安排；安排去重、排序、上限 4、时间未定排末尾；统计正确；N+1 查询预算；Go 回归和关键可见性变异。页面接入与视觉验收由 Claude 完成。

### 5.2 会话 B3：头像、资料不全、待发信数

入口：accounts.SessionUser、getSession、BuildViewer、账号资料完整判定、notify.Waiting 与 held_letters、旧模板 account_area、me/_incomplete、me/_letters。

只新增字段，先与旧站实际所需语义对齐：

- 头像究竟输出图片编号还是最终 URL；目前图片 URL 工具、默认头像池、首字底图由 Claude 负责，不把母版文件路径或服务器绝对路径输出给浏览器。
- 资料不全使用已有完整判定，明确缺哪些项、公开/私密字段如何处理；不要把「没有公开段位」当作资料不完整。
- 待发信数明确是批次数、单封数还是收件人数，照旧页头/个人中心口径；过期、已处理、后台/前台待办是否合并要对照旧站。

- 访客 user:null；停用账号不当正常成员；caps 没有时 []；私密数据不混进公开页面 viewer。

验收：头像真实/默认/无头像三类，完整/不完整资料，0/多条/过期待发信，一次性提示消费、刷新不消费；两名成员互相隔离。统计别逐封加载信件正文造成 session 越用越慢。

### 5.3 个人中心和内战投影

重点候选：`GET /api/me/scrims`、游戏 ID/联系方式单条编辑页面数据、安全/注销所需条件、我的战队/报名单投影。先看已有 me/profile、me/teams、me/registrations、me/export，别再重复做这些接口。

我的内战应给本人报名、上场/替补、分队/位置、过期分队标记、活动状态和可操作性。复用 scrims.PlacementText/相关服务，不把全员分队信息当本人详情发出。根据旧页确定排序、已结束记录和空状态数据；不从前端传 user_id 决定读取谁。

账号修改的 PATCH 只写 changes 指定字段；遗漏字段不能套默认值。base_version、409 current、验证失败不能覆盖其他字段或虚报成功。注销仍受在任队长等限制，真实密码核验、原地匿名化和关联关系清理按既有服务。

验收：本人/另一成员/访客，报名/替补/已选/已结束/取消，游戏账号已删仍能展示历史状态。用两人同一版本并发更新验证冲突；关闭公开段位后改宣言，show_rank 仍为 false。

### 5.4 待发信单封预览、邮件样张与退订

入口：internal/notify、platform/mail、outbox、held_letters，旧 core 的发信视图/样张，设计 10.5。

现有 batch 列表/确认/跳过已实现；候选缺口是单封 HTML/纯文本预览，以及 styleguide 邮件列表/预览的后端支持。

- 以已冻结信件内容生成预览，不重新查当前昵称/队名拼一封不同的信。
- 校验批次归本人、信件属于批次，不能只知道 letter_id 就读内容；预览中不能暴露完整收件人邮箱和密钥。
- 明确 HTML 预览是 JSON 字段还是独立只读响应；与前端 CSP/iframe 沙箱的现有设计对齐，不手改 Caddy 放宽到 unsafe-inline 来图省事。
- 预览 GET 绝不发送信、消费待发信或入队。
- 确认、跳过、过期、重复点击，只能消费一次；幂等重放回执不能再发一次。
- RFC 8058 的原始表单 POST `/unsubscribe/<token>/` 已有 Raw 路由和 Caddy 修复记录，先用 smoke 证据核查；它不是普通 JSON API，不要重新当 SSR 表单处理。
- 不允许用真实生产邮箱试邮件。用临时种子、邮件桩或授权测试 allowlist，保证演练不会发给真实用户。

验收：跨用户 404/403 语义、不存在/过期信件、预览无副作用、确认幂等、退订签名错误/失效/重复提交、Caddy 对 GET 和一键 POST 的路由。

### 5.5 战队创建和赛事报名表单数据

入口：teams、tournaments、accounts 中资格/游戏 ID 的现有服务；旧 templates/teams、tournaments/registration.py；设计 7、8。

候选：建队表单限制（能否创建、已担任队长数、上限、字段选项），赛事整队报名页面（可选自己的战队、有效名单、各人可选游戏 ID、资格原因、报名阶段），散人报名的选择数据。

### 5.6 后台导航契约

入口：api.Nav、platform/apigen、生成 nav.ts、docs/admin.md 4 节。

当前生成 nav 是接口条目数组，不等于完整的后台导航模型；部分 section 仍叫 scrims/tournaments/users/roles/moderation，和后台八大类不一致。不要直接让 Claude 维护第二份导航猜权限。

设计后端给出大类/标签的稳定编号、显示名、旧页面 URL、排序和能力条件；按旧后台八大类：首页、内容、活动、成员、审核、数据、设置、手册。控制是否显示的门来自服务端角色/能力，前端不硬编码另一个判定系统。

兼容做法：保留现有 nav 字段或导出，新加 navigation 等明确模型；需要替换旧契约时登记 FE，等 Claude 接完再删除旧输出。不能因为 nav 显示隐藏就取消接口真权限校验。

### 5.7 后台网站页面与 Markdown 预览

入口：content 的 pages/site_pages/news_index/page_revisions/home_pins，旧 backoffice/content/pages 和普通页/栏目编辑模板，admin.md。

网站页面不是只有首页置顶：需要列表、普通页读写、栏目简介、预览、发布/撤下、SEO 和计划字段，权限与旧后台一致。文章现有修订/发布服务可以复用共用机制，避免另造不能处理定时/版本的保存路径。

草稿保存在修订里，GET 预览读该身份有权看的草稿；公共页面读已发布值。存草稿不能悄悄改变 live 页面，也不能把正文空着时的表单默认值当发布内容。错误与跨字段校验成组，base_version 冲突不丢稿。

Markdown 预览只能用 platform/markdown 的同一渲染器；文章、普通页、赛事、内战及后台预览不出现两套渲染规则。b23 渲染只查缓存，不联网；慢解析交给 worker。传图进入统一上传管线。

验收：内容编辑/投稿者/无能力者，草稿隔离、修订冲突、发布后公共页面投影、定时上线/撤下、外链/原始 HTML/标题/目录/图片/视频黄金对照、预览限流与请求体上限。只实现后台 API，不编写前端编辑器。

### 5.8 图片与集合管理

入口：platform/media、upload Raw 处理器、images/image_collections、旧后台图片页、设计 5.2 与 12 号 5.13。

现有列表、上传 JSON、Raw upload-file、缩略图已写过，**Raw 路由不一定在生成接口手册中显示**。先查 Routes/ServeUploadHTTP，不要依据 docs/api-reference 缺一条就重复写。

候选：改标题/集合，集合新增/改名/删除，编辑器图片选择所需筛选、分页 48、权属和权限。投稿者不能修改或删除别人图；删除前查所有引用，不能只查封面；母版不公开；不返回宿主文件路径。

### 5.9 报名全局审核、CSV 与分队文字

入口：tournaments 的 registrations/logs/board，scrims 的 teaming/board，旧后台 review 和 split/text，admin.md 活动/审核。

已有单赛事列表、通过/驳回和编队服务，不等于全局审核页完成。核查全局筛选、每页、详情、批量通过、CSV、撤销等缺口；遵守状态机，操作记录和待发信随动作产生。

批量通过需明确旧站语义：哪些失败、是否部分成功、提示和信如何按批次冻结；不能用 for 循环半成功后返回统一 ok。CSV 编码/列/顺序/权限照旧，含用户输入的单元格防公式注入。导出不把不该看到的联系方式、邮箱放出来。

内战复制文字应复用分队状态和 PlacementText 类逻辑，段位/队名/替补/过期提示照旧；GET 文本只读。队伍编排保留两阶段写入与版本号，分队的 board_version 防并发覆盖，别为了前端拖拽容易实现改服务端状态机。

验收：筛选/空结果/跨权限、合法与非法混合批次、重复操作、撤销后名单和记录、CSV 恶意单元格、分队前/后/过期/游戏 ID 缺失/替补、并发 board 冲突。真实拖拽页面仍归 Claude。

### 5.10 字体、排版与设置操作

入口：settings、旧 core/fonts、D4、admin.md 设置页。先按新栈明确规格做，不把调研想法当已批准需求。

候选：字体列表/上传/删除、区域排版读写、生成 CSS 与缓存失效、引用中字体拒删、默认系统字体；试异地备份接口。敏感字段只给设定状态，不返回明文，日志/报错也不能泄露。试备份只能访问后台配置的已授权目标，不接受任意 URL 作为 SSRF 入口。

部署和字体静态输出需与 Claude 已有 UI 契约配合，先后端加字段，FE 说明接入方式。真实对象存储配置/密钥仍由用户安排；没有配置能明确报「未配置」，不能伪报成功。

验收：能力门、合法/坏字体、额度与格式、引用拒删、区域验证、密钥不回显、测试邮件/测试备份失败明确、修改不破坏无关设置。

### 5.11 导入、对账和运维演练

入口：每个领域 import.go、sjtuow import/import-media/reconcile/parity/rulecheck、deploy/rehearse.sh、cutover.sh。

273 只修了 content/import.go；其他域还要查吞错、错表、漏列、错误时间兜底、默认值、孤儿引用、重复导入。每个迁移回归要按旧站真实表名与字段构造，不能在测试里建一张作者想象出来的表来证明通过。

reconcile 不能只比较总行数。检查普通页、分类、图片集合、评论和回复/点赞、角色与个人禁用、游戏 ID/段位隐私、活动名单快照、待发信与队列、日历签名、退订签名、密文设置；字段级差异要输出可定位 ID，但不要输出敏感值。

导入命令的错误传播要保留；不能把读取失败当空表、忽略 SQL 再打印「成功」。按段事务有边界，失败退出时明确哪一段完成，保持只读旧库。不能用正式站整库备份覆盖真实生产库。

演练用隔离临时库和媒体目录，不替换生产数据。为可复现测试保存样本生成脚本和日志，不提交真实成员库、邮箱、密钥和私密图片。验证备份能恢复、失败能停止、旧镜像标签不被新构建覆盖、邮件队列处理不会误发。

## 6. 写一个后端接口的标准步骤

1. 找旧入口、表单、模板、service 和设计条款，整理显示数据/写入字段/资格/状态/发信/错误语义。
2. 查 Go 已有服务，确定是复用、补投影、修接口，还是新增；读生成类型和前端 pending-api 的只读期望。
3. request 写明范围、门、输入输出、兼容、验收与不做的部分。
4. 需要改变设计先按用户决策改 design-next；只是落实既有规则，修改本轮有关实现规格即可，别伪造设计版本变化。
5. handler 做解析和协调，业务在 service；SQL 在 store/事务；跨域通过接口/组合服务而非循环依赖。
6. api.Get/Post/Patch/Delete 声明 Gate、Limit/NoLimit、Budget/Nav。ID 用 api.ID，不收浮点数作编号。原始上传/文本等查现有 Raw 规范，不在 handler 外绕开门。
7. GET 只读；状态变化经过服务和 WriteTx。并发资格/唯一/版本在事务内重查。耗时 Argon2/图片处理/联网不占全库写锁。
8. 错误保持 error.code/message、fields、409 current。400 是请求坏，401 未登录，403 无权限，404 不存在/不应揭示，422 业务校验，429 限流。不要在响应里暴露 SQL、磁盘路径、密钥、私密邮箱。
9. 写 HTTP 级回归，验证 JSON 和权限门；业务测试不能代替 handler 的解析、状态码和 nullable 编码。
10. 编译、回归、apigen 都在测试机。取回生成物后再跑整组，让生成守卫比对干净；不手改类型来掩盖 Go 形状错误。
11. 可编译变异验证关键规则。go vet 失败是无效变异，不算被测试抓到；等价变异要说明，不能拿编译错误充数。
12. report/review/STATUS，只写执行过的证据；一个中文提交，提交后 pull --rebase 再 push，检查 CI。

## 7. 后端通用验收矩阵

| 维度 | 至少覆盖 |
|---|---|
| 身份 | 访客、本人、另一普通成员、对象负责人、相关干部、无相关权限干部、超管、停用/注销 |
| 对象 | 不存在、草稿、公开、受限、已结束/取消、已删除关联、旧导入数据 |
| 输入 | 最小合法、缺必填、空值/省略的区别、类型错、未知字段、超长、多字节汉字、超大编号、恶意 URL/HTML |
| 并发 | 同版本两写、重复请求、相同幂等键、相同键不同内容、唯一冲突、写后删对象 |
| 数据 | 空切片 []、nullable 字段、时间/精度/时区、排序第二键、上限与第 21 条、跨用户隔离 |
| 错误 | 查询/扫描/迭代/事务失败向上报，不能 200 假空页；失败没有半段写入或错误发信 |
| 发信 | 冻结、确认/跳过、过期、重复点击、worker 重试、注销代发边界 |
| 资源 | 查询次数、N+1、并发信号量、body 上限、磁盘阈值、无渲染联网 |

数组和时间类型是接口契约的一部分，尤其 time.Time/null/pointer/omitempty。274 nullable 普通页日期、数组组、casefold 都有真实编码回归；可以当写法参照，但不要只复制断言实现本身。

## 8. 测试机与后台运行

所有编译/测试先在测试机；本机仅编辑、只读分析、格式化和取回生成物。测试机连不上才本机兜底，并在报告明确写原因。

```bash
# 整组：Go 格式/静态分析/漏洞/测试/apigen + Web 安装、测试、构建、预算
bash scripts/remote-check.sh

# 单组回归，命令从仓库根执行；Go 的包路径要先 cd server
bash scripts/remote-check.sh run bash -c 'cd server && go test ./internal/待验证包 -count=1'

# 在测试机生成契约，随后取回 gen/ 与 docs/api-reference.md
bash scripts/remote-check.sh run bash -c 'cd server && go run ./cmd/sjtuow apigen'

# 对拍：四组合、严格失败；前缀必须实际匹配页，不存在的筛选不能算绿
bash scripts/remote-check.sh run bash e2e/parity/run.sh --only=具体前缀 --wide --strict

# 变异与整组有先后关系时串成一条后台命令
bash scripts/remote-check.sh run bash -c 'uv run python handoff/rounds/本轮/mutate.py && sh scripts/check.sh'

# 断连后接日志
bash scripts/remote-check.sh attach
```

调用助手工具的后台模式，写输出文件，等完成通知再读，期间继续写报告/看代码。不要把长测试前台阻塞，不自己加 sleep 循环刷状态。remote-check 内部已有断连续看与排队；同一时间只跑一个。避免连排多次六分钟对拍。

默认 SSH 别名 sjtu-ow-test，连接经用户的 `189.24.110.12:2222` 转发到 IPv6 测试机。不要连这台转发机的 22 端口；用户名和密钥只读本机 SSH 配置，不抄进仓库。测试机目录 `/srv/sjtu-ow-check/`，日志 runs/，工作检出 repo/。测试期间别停 warp-svc/komari-agent。

remote-check 会把**全部工作区未提交改动**打包，与你有没有 git add 无关。因此交班必须干净；也不要让未经范围审查的旁枝草稿留在仓库里污染检查。

生成物取回后先看 git diff；只允许预期生成文件变化。不要用宽泛 scp 覆盖整个 web/，不要把测试机的临时媒体/数据库/截图都搬成版本控制文件。

## 9. 与 Claude 的交接方式

每轮结束提供：后端接口路径/方法、输入输出新增字段、空值/错误语义、允许哪些身份、旧模板依据、实际日志、生成物提交、哪几页可以开始接入。

## 10. 运维边界与上线条件

正式站在 `169.58.217.180`，本项目目录 `/srv/sjtu-ow`，对外端口 22887；机器上还有其他服务。**用户授权继续开发，不等于授权生产部署。** 新栈 IP 试用站部署也要用户同意，不能把跑临时 parity 容器说成已经部署试用站。

正式站磁盘清理、换冬令时 cron、异地备份等看 STATUS/AGENTS 和用户授权；不要因为 healthz 磁盘项 503 就把阈值降低、全局 Docker prune 或替换数据库。2026-10-25 前换 cron 有真实时限，但仍需用户点头。

## 11. 最容易再次踩的坑

1. **错表 + 吞错 + 绿单测**：测试用错表名创建假旧库，导入仍失败但函数返回 nil。用真实 Django 种子证明。
2. **只看数量**：一篇文章数量对了，普通页、SEO、所属集合、隐私仍可能错；核对字段、ID 和关联。
3. **只看接口方法存在**：存在 POST 不等于上传格式和权限适用于编辑器；Raw 路由也可能不在生成清单。
4. **把模型字段当输出字段**：Page 有 last_published_at，SitePageOut 以前没带；Store 以前扫描了也没赋。
5. **把 caps 当功能限制**：后台能力和 can_use 两套语义；投稿资格不等于邮件验证或发表能力。
6. **把 live 当 public**：Wagtail 祖先限制能约束整棵树；搜索、列表、详情、sitemap 各有门，逐个验。
7. **Go/SQLite 小写当 Python casefold**：ß、希腊字母、组合字符有差异；沿用生成映射和旧站 golden，不再退回 ASCII lower。
8. **更新首页时加假数据**：旧站固定空区块允许没有内容，不要对拍时补人工占位文章/空卡。
9. **跨域 N+1**：每名队员/每条安排循环查游戏 ID 或分队状态，用查询预算和不同规模样本检验。
10. **读页面顺便写状态**：GET 不发布、不发信、不消费待发信；已允许的一次性 notice 例外沿原机制。
11. **新增响应删老字段**：API 兼容和 FE 迁移是硬规则；不要为了 API「漂亮」打断已在写的页面。
12. **测试机检查带脏草稿**：快照包含未提交文件，git add 不决定测试范围。
13. **提前声称完成**：测试桩、SSR 输出、真实接口、Caddy 对拍、用户旅程是不同层的证据。
14. **署名套用 GPT**：标题中文、详细正文、具体真实 GLM 型号与有效官方关联邮箱，绝不替别的模型署名，也不把未知型号猜成某个 GLM 版本。

## 12. 一轮完成前最后核对

- request 的每项完成或明确记录未完成，不扩到别的页面组。
- 设计/实现/测试一致，旧站相关条款逐项核对。
- Go 检查和 Web 整组通过，生成契约已取回且 CI 守卫不会再产生 diff。
- 新规则关键变异被真实测试抓到，无效编译变异不冒充。
- 日志写具体 run ID/退出码，失败后修复过程保留，没跑的写未验证。
- report 说明兼容、迁移、风险边界、给 Claude 的接入动作。
- review 明确「自查通过」，不声称独立复核。
- STATUS 只改后端归属部分；进度不另写到本指导。
- git add 只列自己文件，不 git add -A/.；一轮一个中文详细提交。
- 提交后 pull --rebase；若轮次撞号，改自己目录/标题/STATUS/提交标题，不占用别人轮次。
- push main 后看 CI，红了优先修；不要推红然后交班。
- git status 干净，再把控制权交给 Claude 或用户指定的下一位助手。
