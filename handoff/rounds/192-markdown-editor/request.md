# 192 正文改成 Markdown，后台换成 Markdown 编辑器

## 背景

用户 10-04：「然后文章等界面，不能改成标准的 markdown 编辑器吗，现在这个根本不舒服」。问了两件事，用户选：

- 编辑器和渲染：**EasyMDE + markdown-it-py**（推荐项）
- 范围：**文章、网站页面、赛事和内战的说明**

现在文章和普通页面的正文是 Wagtail 的 StreamField（段落块用 Draftail 富文本，图片、引用、视频各是一个块），赛事详细说明是 Draftail 富文本，内战说明是纯文本框。写一篇文章要不停地加块、切块，粘贴进来的格式也乱。

## 本轮范围

1. **存储**：这四个字段（`ArticlePage.body`、`StandardPage.body`、`Tournament.description`、`Scrim.description`）改成存 Markdown 原文的文本字段，字段名不变。迁移把现有内容转成 Markdown：StreamField 的段落（Wagtail 存的 HTML）、图片块、引用块、视频块，赛事说明的富文本；文章和普通页面**没发布的修订**（草稿、定时发布的版本）也一起转，否则后台打开草稿看到的是一串 JSON。内战说明本来就是纯文本，原样留着
2. **渲染**（一个函数，前台页面、后台预览、字数、搜索、审核都用它）：markdown-it-py，CommonMark 加表格、删除线；**单个换行就是换行**；**不收 HTML**（写了也原样显示成文字）；`#`、`##` 是二级标题，`###` 及以下是三级标题（页面标题已经是一级）；单独一行的图片显示成带图注的大图（方括号里的字是图注），只显示本站的图片，别的网址变成链接（前台的内容安全策略不放外站图片）；单独一行的 B 站视频链接（`bilibili.com/video/`、`b23.tv`）显示成播放器；链接只允许 Markdown 默认放行的协议
3. **编辑器**：EasyMDE 2.21.0 原样放进 `static/vendor/easymde/`（MIT，记进 `THIRD_PARTY_NOTICES.md`），不从外站加载任何东西（不下载 Font Awesome，图标用 Wagtail 后台自带的）。工具栏中文：加粗、斜体、删除线、二级标题、三级标题、引用、无序列表、有序列表、链接、图片、B 站视频、表格、分隔线、预览、并排预览、全屏、写法说明。**预览由服务器渲染**，和前台看到的一模一样。图片可以点按钮、拖进来、直接粘贴，上传进图片库的「投稿图片」集合，用 Wagtail 自己的图片校验（格式、5 MB），要有往这个集合加图的权限；插进正文的是最长边 1600 的缩略图地址。底部显示字数（和文章头的字数同一个算法）
4. **读正文的地方都跟着改**：文章页（目录锚点）、普通页面、赛事页、内战页、字数和阅读时长、站内搜索、AI 审核送审的文字、上线准备里检查协议有没有【】、`load_legal_pages` 直接存 Markdown、新内战邮件里的说明（转成纯文字）
5. 前台 `c-prose` 补上 Markdown 多出来的东西：行内代码、代码块、表格、删除线
6. 设计 5.2、8.1、9.1、12 章数据表、13.2 正文组件、13.16 搜索、15 章跨站脚本，附录 D v6.70；README、手册里讲到怎么写正文的地方

不做：栏目介绍（`ArticleIndexPage.intro`）、战队简介、评论仍是原来的样子；不做从图片库里挑图插入（只上传），留给以后。

## 验收标准

- 四个地方的编辑页都是 Markdown 编辑器，工具栏、预览、上传图片能用，浏览器里没有内容安全策略报错
- 迁移把本机开发库里的演示文章、页面、赛事说明转成 Markdown，前台显示和原来一致（标题、列表、加粗、链接、图片、引用、视频）
- 写进去的 HTML、`javascript:` 链接、外站图片都不会原样出现在页面上
- 每条新规则拆掉会红（mutate.py）；整组检查全绿；正式站升级、全量预渲染
