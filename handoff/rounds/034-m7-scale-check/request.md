# 034 按设计的规模假设做一次实测

设计 15.1 有两张表：规模假设和性能目标。023 轮核查第 15 章时，性能那几行我标的是「**未验证**」，理由是「需要真实服务器和真实负载」。

那个理由只对了一半。**网络延迟确实要真机才能量，但服务端处理时间在本地量是有意义的**——它把我们的代码和网络分开了。而且真正要担心的不是绝对毫秒数，是**数据量上去之后查询数会不会爆**。

## 任务

### T1 造出设计假设的数据量

- 单个赛事 200 支战队报名（设计上限）
- 名单成员 1200 人
- 单次内战 100 人报名（设计上限）

### T2 量服务端处理时间和查询数

公开页面、后台页面、开放 API、分队算法，逐项对照设计 15.1 的目标。

**查询数比毫秒数更重要**：本地 SQLite 快，100 次查询也就十几毫秒看不出问题，但那说明有 N+1。

### T3 发现的问题当场修，并补回归测试

## 验收标准

1. `ruff` / `pytest` / `makemigrations --check` / 生产 `check --deploy` 干净
2. 贴出逐项实测数字（时间 + 查询数）
3. 修掉的问题要有变异测试证明回归测试咬得住
4. 清理规模数据并查全库计数
5. git 提交，信息以 `034:` 开头
