# 094 邮件统一成信的样子：称呼、正文、落款，HTML 好看

## 背景

093 问用户「整队报名时给队员发邮件要不要留」，用户 2026-10-03：

> 要发邮件的。所以邮件模板你也搞个漂亮点的，要遵守邮件礼仪。最后的祝福语用 祝好！

现在的样子：业务邮件（战队 6 种、赛事报名 8 种、内战 2 种、内容审核 2 种）都是在 Python 里用 f-string 拼一段纯文本，没有称呼、没有落款；HTML 版是 `core.mail` 自动把段落包成 `<p>`，没有任何排版。注册、找回密码的验证码邮件是 allauth 模板，纯文本有一行「上海交通大学守望先锋社区」开头、「谢谢使用本站。」结尾，HTML 是裸的 `<p>`。主题大多不说是哪件事（「报名已提交」「赛事已取消」）。Wagtail 投稿审核的通知用 Wagtail 自带模板。

## 本轮范围

**做**（设计 10.3「邮件格式」，先写文档）：

1. 一套信的格式，纯文本和 HTML 两版内容一致：
   - 主题：「事情：对象」，一眼看出是哪件事（「报名已提交：2026 秋季校内杯」），前缀照旧由 `core.mail` 统一加
   - 称呼：「昵称，你好：」，不知道是谁（验证码发到还没注册的邮箱）写「你好：」
   - 正文：第一段先说结论，然后是细节；关键信息（战队、赛事、游戏 ID、状态、时间）排成一张小表；要对方做的事一个按钮，按钮下面附原始链接
   - 结尾：「祝好！」，落款「上海交通大学守望先锋社区」和日期
   - 页脚：这封信为什么发给你、自动发送请勿直接回复、网站地址
2. HTML 版：600px 宽的卡片，页头深色条加站名和一道橙线（和网站页脚一个调子），按钮深红；全部内联样式、表格布局，图片不用（很多邮箱默认不显示图片）；声明只用浅色，避免邮箱自动反色把字弄糊
3. 全部业务邮件改成用这套格式；主题按上面的规则改
4. allauth 的验证码邮件、「这个邮箱还没注册」「这个邮箱已经注册过」改成同一套格式，验证码大字显示
5. 后台「SMTP 测试邮件」用同一套格式
6. Wagtail 的投稿审核通知：纯文本换成我们的称呼和落款（覆盖它的 `base.txt`），HTML 自动套同一个外壳
7. 后台能看样张：`/_styleguide/emails/` 列出每一种邮件，用假数据渲染 HTML 和纯文本（和样张页一样只给能进后台的人）

**不做**：退订（设计 10.2 第一版不做）；邮件里放图片或校徽；改发送机制（队列、重试、前缀都不动）。

## 验证

| 任务 | 验证 |
|---|---|
| 格式 | 测试：每种邮件的纯文本都有「昵称，你好：」开头、「祝好！」、落款和日期、为什么收到；HTML 有同样内容、按钮链接、内联样式，没有外部图片和 `<style>` 之外的脚本 |
| 主题 | 测试：每种业务邮件的主题带着对象（赛事名、战队名、内战名） |
| 不知道名字 | 测试：给没注册的邮箱发的信写「你好：」 |
| 一人一封 | 测试：原来的「收件人互相看不见」照旧 |
| allauth | 测试：验证码在纯文本和 HTML 里都有，HTML 里是大字 |
| Wagtail | 测试：投稿审核通知有我们的称呼和「祝好！」 |
| 样张 | 测试：能进后台的人能看，普通用户 404；每一种都能渲染 |
| 变异 | 上面每条改坏，对应测试要红 |
| 截图 | 无头 Edge 截几封 HTML 邮件（报名、验证码、审核汇总） |
