# 129 赛事开始前提醒参赛队员

## 背景

继续用户 2026-10-04 睡前的要求（假定各种身份走流程）。以参加赛事的队员身份：

- 整队报名时，队员只在被报名那一刻收到一封「你已被报名参加」，状态是「待审核」；通过还是驳回只发给队长，队员不知道自己到底参没参上
- 比赛前没有任何提醒。内战有开始前 2 小时的提醒，赛事没有；赛事的「比赛时间」只用来展示
- 队长收到的「报名已通过」也不写比赛时间

## 本轮范围

1. 填了比赛时间的已发布赛事，开始前 24 小时（全站设置「社区参数」可改）给已通过报名名单里每个占名额的队员各发一封「赛事提醒」：比赛时间、所在队伍、报名用的游戏 ID，附赛事页面
2. 做法照内战提醒：发布、保存赛事时安排延时任务；任务重读赛事，时间推后就改期，取消了就不发，`reminder_sent_at` 防重复；到时还没有已通过的报名就不记为已发送
3. 「报名已通过」的信写比赛时间
4. 邮件样张页加「赛事开始提醒」
5. 设计 v6.24（8.1、10.2、10.3、12.4.1、12.8.1、默认值表）

顺带：`scripts/remote-check.sh` 的退出码改在任务脚本外面写（128 的遗留：任务脚本本身起不来时本机会一直等）。

## 不做

- 把通过、驳回也发给整队报名的每个队员：队长和队员的分工是 8.3 定的，提醒已经解决「到底参没参上、几点开始」
- 发过提醒后又改了比赛时间时再发一次：和内战一致，只发一次

## 验证

测试：发布时按设置的提前量安排；没填时间不安排；每个已通过的队员各收到自己的一封，第二次不发；待审、驳回的不发也不记为已发送；退出名单的、停用的不发；时间推后改期、取消后不发；通过信写时间、驳回信不写；样张页。变异逐条改坏。

## 验收标准

测试机上整组检查全绿；变异全部被抓到；推送 `main`，CI 绿；演示站升级。
