# 204 做完事顺带的信，先问一句再发

## 起因

用户 10-05：「然后所有的发信都必须手动点发信，这个逻辑也要改！」问了三件事，用户选：

- 验证码（注册、找回密码、改邮箱）：**照旧自动发**
- 到点发的提醒（赛事、内战开始前，入队申请等太久）：**照旧到点自动发**
- 做完事顺带的信（审核报名、队长处理申请、取消活动……）：**操作完给一个「发信」确认，可以不发**；后台和前台成员自己的操作都这样

现在这些信在事情做完（数据库提交）时直接进发信队列，做事的人看不到信写了什么、发给谁，也没法不发。

## 要做的（设计 10.5，v7.8）

1. **哪些信要问**：设计 10.2 里由某个人的操作顺带发出的 15 种——收到入队申请、入队申请结果、被移出战队、队员退出战队、成为队长、战队解散、报名已提交、你已被报名参加、报名状态变化、赛事取消、已编入临时队伍、移出临时队伍 / 队伍解散、临时队伍成员退出、内战取消、头像被撤下。不问的：验证码、SMTP 测试信、到点的提醒和自动关闭、AI 巡查提醒、「要求修改内容」（写说明点发送本身就是发信）、群发（本来就有预览页）
2. **怎么问**：事情照常做完；信写好但先不发，页面转到「发信」：每封信的主题、发给谁、信的样子（和真发出去的一样）、勾选框（默认都勾上）；「发出勾选的信」或「都不发」，然后回到原来要去的地方。后台的操作在后台的样子里问，前台的在前台的样子里问
3. **信在做完事那一刻写定**：内容和收信人都定下来，预览的就是发出去的；同一件事给几个人发同样的信（取消赛事给每个队长）合成一封、写几个人
4. **没选就走开**：信留着等，7 天后作废。个人中心顶上、后台首页待办里提示「有 N 件事的信还没决定发不发」，点进去还能发或不发
5. **只问做事的人**：别人打不开（404）；做完事人已经不在（删除账号时退出了临时队伍，要告诉赛事管理员）的，没人可问，照旧直接发
6. 页面上原来写「对方会收到邮件」「已报名的人会收到邮件」的地方改成说接下来问要不要发信
7. 不经过网页的（worker、命令行、测试里直接调 service）照旧直接发

## 验收

- 每种要问的信：做完事不发、页面转到「发信」；勾了的发出去，没勾的不发；「都不发」一封不发
- 别人打不开、发过的不能再发、过了 7 天不能发；做事的人退出了登录的直接发
- 验证码、到点提醒照旧直接发
- 规则拆掉就红；整组检查、三个浏览器走查通过（走查里的报名、申请入队、编队都要过「发信」这一步）
