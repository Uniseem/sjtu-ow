# 009 修 008 复核发现的字体问题

> 用户不在，008 由 Claude 实现、Claude 自查。本轮继续由 Claude 实现，并按同样的纪律写 `report.md` 和 `review.md`。等用户回来，008 和 009 都可以交给 Grok 复核。

## 背景

`handoff/rounds/008-m2-fonts/review.md` 自查出 4 个必须修、4 个建议修的问题。字体功能本身能用，问题集中在**「跟随正文」这条链路两处口径不一致**和**文件清理**上。预渲染（原计划 009）顺延到 010——预渲染会把字体样式表的地址写进静态 HTML，必须先把字体这边理清楚。

设计依据：`docs/design.md` v1.5.5，13.12 整节、12.4.3–12.4.5。

## 本轮范围

**做**：A1–A4（必须修）、B1–B4（建议修）。
**不做**：半静态渲染（010）、AI 审核（011）、任何新功能。

## 任务

### T1 文件清理（A1、A4、B1）

1. **A1**：同一 (字体, 字重, 样式) 重新上传时，先删掉旧的原始文件再存新的。
2. **A4**：Google Fonts 重新导入同一字体时，先删掉这个字重旧的分片文件。
3. **B1**：重新切片成功后，旧分片**不要立刻删**——已经加载旧样式表的页面还在用。改成延迟一天删除（和旧样式表保留一天一致），删之前再确认没有任何字重还在引用这些文件。

### T2 「跟随正文」口径统一（A2、A3）

设计 12.4.5：`mode = inherit` 的区域用的是**正文字体**加这个区域的字重。生成样式表已经按这个口径（`css.used_pairs()`），但这两处没跟上：

1. **A2**：`services.is_face_in_use()` 只看 `mode=custom`，导致「一级标题跟随正文 700」时，700 那个字重可以被删掉。改成和 `used_pairs()` 同一个口径。删除字重成功后**重新生成样式表**，否则线上 CSS 会指向已删除的文件。
2. **A3**：`run_face_processing()` 末尾同样只看 `mode=custom`，导致「先设正文字体、再补传 Bold」时处理完不会自动生效。一并改掉。

### T3 后台小改（B2、B3、B4）

1. **B2**：`next_css_name()` 撞唯一约束时重试（并发添加字体不应该报 500）。
2. **B3**：字体库列表和详情页显示这个字体占多少磁盘（原始文件 + 分片）。
3. **B4**：排版设置的字体下拉，除了「有处理完成字重的字体」，还要包含**当前区域已经选中的字体**，否则字重被删光后界面上看不到自己选的是什么。保存时的校验不变。

## 测试要求

至少覆盖：重复上传后旧原始文件不在磁盘上；「跟随正文」用到的字重不能删、提示可读；删除未被使用的字重后样式表重新生成；补传字重处理完样式表自动更新（含新字重的 `@font-face`）；旧分片延迟删除（到期前文件还在、到期后删掉、仍被引用时不删）；`next_css_name` 并发重试；字体下拉包含已选中但没有可用字重的字体。
