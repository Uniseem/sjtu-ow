# 118 后台的功能：复查第二部分（后台这边，二）

## 背景

115 轮复查（`handoff/rounds/115-admin-review/findings.md`）里后台还剩的功能问题。117 做了文字和菜单，这一轮做第 21（不含直接处置）、24、25 条和 3.7 的停用标记。剩下的小项（操作记录、稿件的 AI 判断、排版预览的位置、赛事人数下限的提示、逐行查询、自定义页面写法统一）放 119。

## 本轮范围

1. **后台首页的待办**（#24）：首页最上面一块「待办」，按这个人能管的事列出数量和入口，数量为零的不列，全为零写「暂时没有待办」：
   - 内容编辑、超级管理员：待复核的内容、待审核的头像、等待审核的稿件（Wagtail 工作流里进行中的）
   - 赛事管理员、超级管理员：待审核的报名、已发布赛事里等待编队的个人报名
   - 内战管理员、超级管理员：报名已截止、还没开始、还没保存分队的内战
   - 超级管理员：生成失败的静态页面
   - 纯投稿者照旧只看「我的投稿」
2. **内容审核**（#21，设计 5.5.4）：
   - 列表加时间筛选（最近 24 小时、7 天、30 天、全部，按提交时间）
   - 「全量扫描」按钮：把现有的昵称、个人宣言、已发布的文章和普通页面、战队简介、评论送一遍审（去重和每日上限照常），在后台排队执行，不卡页面；原来的 `moderate_scan` 命令改成调同一个函数
   - 处理记录不再被下一次覆盖：每次处理写一条 Wagtail 操作记录（谁、什么时候、处理成什么、说明），详情页列出全部
   - 「直接处置」（发信要求修改、清空战队简介、要求改昵称、停用账号）**不做**，等用户定（复查第五部分）
3. **内战分队页**（#25）：
   - 「复制」按钮，一键把结果复制到剪贴板（不支持时选中文本，提示手动复制）
   - 排序（按报名时间、按段位）保存后保留，当前排序标出来
   - 有查看联系方式权限的人（设计 4.1：赛事管理员、内战管理员）在报名表里看到联系方式
4. **「账号已停用」标记**（3.7）：报名审核的列表（名单里有停用账号时标出）和详情的名单、队伍编排页的散人池和临时队伍、内战分队页的报名表和分队卡片

## 验证

每条有测试，变异逐条改坏（`mutate.py`）；按角色看首页待办；截图看首页、内容审核、分队页。

`AGENTS.md`「常用命令」那组全绿；变异全部被抓到；推送 `main`，CI 绿；演示站升级。
