# 202 自动保存（上）：机制、个人中心、后台的设置类页面

## 起因

用户 10-05：「后台头像上传也有问题，逻辑不对，现在这个很容易误导用户，应当是上传后自动就保存替换，其他的更改也一样，全站的后台都是，都给我改成自动保存，无需手动保存」。

问清楚的三件事（用户的回答）：

- 文章、网站页面这类有草稿的：「存成草稿，点发布才上线」
- 新建的东西（写文章、新建赛事、新建内战、新建分组）：「必填项没填好也要自动保存！」
- 赛事内战改时间的信：改成手动发（201 已做）

个人中心的头像：现在选了图要再点「上传」，下面紧跟着资料表单的「保存」，很容易选了图点「保存」，图没传上。

子任务把个人中心和后台每个有表单的页面列了一遍（哪些是改值、哪些是动作、数据库层面哪些字段必须有、保存时的副作用、特殊字段、相关测试），结论见报告。量太大，分两轮：

- **202（这一轮）**：自动保存的机制（脚本、服务器端的规则、状态显示、没脚本时的退路）、个人中心（基本资料、头像、游戏 ID 和联系方式的编辑）、后台的设置类页面（全站设置、用户、战队、图片、图片集合改名、分类、成员分组、排版设置）
- **203**：文章、网站页面、首页置顶、栏目介绍（草稿）、赛事、内战（新建即草稿、发布时才查必填）、分队和编队、队长的战队管理

## 要做的（设计 13.17，v7.6）

1. **脚本** `static/js/autosave.js`（后台和前台都加载）：表单写了 `data-autosave` 就自动保存——文字停 0.8 秒、勾选和下拉马上，把整张表单发给同一个地址（请求头 `X-Autosave: 1`）；页面上一行状态「正在保存…」「已保存 15:32」「有 N 项没存」「保存失败，正在重试」；字段的错误写在字段下面；离开页面时还有没存的就提醒；点别的表单（动作）之前先把没存的存掉；表单里的「保存」按钮有脚本时藏起来
2. **服务器** `core/autosave.py`：认出自动保存的请求、回 JSON（存了没有、哪些字段没存和为什么、新建以后的地址、要换掉的页面片段）。**规则**：整张表单没问题就整张存；有问题时，改了的、自己没问题的字段照存，有问题的字段保持原来的值；几个字段一起才能判断的规则不满足时，这几个字段这次都不存
3. **少折腾**：操作记录同一个人连续改同一条 30 分钟内合成一条；AI 巡查同一处还没看的旧文字被新文字替换（只看最后的样子）；排版设置的全站重新生成改用合并的
4. **个人中心**：基本资料自动保存；**头像选好图就上传换上**（不再有「上传」按钮）；游戏 ID、联系方式的编辑框自动保存（新增仍是「添加」：没填完的游戏 ID 存不了）
5. **后台**：全站设置（密钥框离开时才存；侧栏的「发送测试邮件」等先存再试）、用户（停用、启用改成单独的按钮，别的自动保存）、战队、图片、图片集合改名、排版设置；**分类、成员分组新建也是第一次改动就建好**，名称空着的不在前台出现（可以有好几个）；成员分组的成员行填好人就存
6. 没有脚本时表单照旧有「保存」按钮，整张提交

## 验收

- 每个页面：自动保存的请求存对了、回的 JSON 对；有问题的字段不存、别的照存；没脚本的整张提交照旧
- 头像选了图就换上
- 新建分组、分类第一次改动就有了，名称空着前台看不到
- 操作记录、AI 巡查不会被一次次自动保存刷屏
- 新规则拆掉就红；整组检查、浏览器走查（含新加的自动保存走查）通过；有迁移，正式站升级前备份
