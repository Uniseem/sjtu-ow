# 303 修复最低 Go 版本导致的 CI 失败

## 背景

302 界面删减已提交并双推。首次 CI 的 Web 通过，Go 1.26.9 在漏洞扫描命中 GO-2026-6809，退出 3；编译 VPS 使用的 1.26.10 已通过扫描。用户本聊天明确要求更新 AGENTS 并继续修复关联问题，无需逐项确认。

## 本轮范围

把 `server/go.mod` 的最低 Go 版本提升一个补丁版本到 1.26.10，使 GitHub Actions 的 `go-version-file` 选中修补版本。更新当前工具链说明和交接记录，不新增模块、不改业务代码或界面，不部署。另开一个中文提交，保留已推送的302历史。

## 任务和验收标准

1. 在编译 VPS 后台运行完整 `scripts/check.sh`，要求退出 0，漏洞影响项为 0，生成接口无差异。
2. 确认 Docker 构建器已有 `golang:1.26-alpine`，无需改为另一个系列或修改生产容器。
3. 推送两端，读取本轮精确提交 SHA 的自动 CI。沿用302的界面和浏览器证据，不重复未变更界面的专项。
