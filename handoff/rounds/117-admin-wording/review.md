# 117 复核结果（自查）

## 结论

自查通过。复查第 22、26、27 条和第四部分做完；另外修了查的时候发现的两处（页面树看到别人的草稿、没人能批的工作流），都先复现再改。

## 验证记录

- **英文**：改完后用同一个脚本重新渲染，服务端只剩 4 条误报（Django 自己的 `%s KB`、`%s MB` 译文和原文相同，django-filter 内部的 `exact`，本站的「SMTP 密码」），脚本里的 0 条
- **编译**：`.mo` 用 Python 的 `gettext` 读回（上下文、复数、多行、转义）；输出和条目顺序无关；`.po` 改了没重编测试会红
- **菜单**：六个角色逐个读侧栏。超级管理员：页面、图片、社区（7 项，按设计顺序）、成员分组、文章分类、文档、用户（用户、用户组、功能权限）、报告、设置、帮助；内容编辑有报告和帮助；赛事管理员只有页面、图片、社区里的赛事和报名审核；内战管理员只有页面、图片、内战活动；认证作者只有页面、图片；投稿者只有后台首页、图片
- **页面树**：在事务里建一篇别人的草稿，赛事管理员、内战管理员、认证作者改前都能在「资讯」里看到标题，改后看不到，内容编辑仍能看到；测试分别检查两层过滤
- **工作流**：本机开发库迁移后「Moderators approval」停用、根页面上的绑定删掉，「内容审核」不受影响；根页面、根集合叫「根目录」
- **重跑**：30 处变异全部被抓到

## 发现的问题

必须修：无。

建议修（留给后面）：

1. 报告页面只藏了菜单，网址对所有后台用户开着（Wagtail 按对象权限过滤）。要严格按 14.1「直接访问也被拒绝」，得包一层中间件或改 Wagtail 的视图，这轮没做，设计里写明了例外
2. 「较早的页面」报告里，没人发布过的页面「最后发布者」一栏显示英文 `None`（Wagtail 的模板）；用户组编辑页里屏幕阅读器读的权限名是数据库里的英文（`Can add group`），看不见，没改
3. 排版设置的字重选项是 `100 Thin`、`400 Regular` 这类英文名，设计界通用，没改

## 判断里最没把握的

1. **认证作者也被过滤**：14.3 的过滤原来只管纯投稿者。认证作者能直接发布，但只能改自己的文章（没有「修改」权限），我按「看不到不能管的草稿」放进过滤；如果你希望认证作者能看到别人的待审稿件（比如帮忙看稿），要退回
2. **报告和帮助对认证作者藏起来**：认证作者写文章时可能用得上 Wagtail 的编辑指南和快捷键说明，但设计 14.1 写的是只给超级管理员和内容编辑，按设计做
3. **停用自带工作流**：按「审批组为空」判断；如果以后有人给它配了审批组，迁移和 `init_site` 都不动它
