# 005 M1 下半：个人资料、联系方式与功能权限

## 背景

004 复核通过（见 `../004-m1-accounts/review.md`），但发现一个必须修的问题，列在本轮 T1。

设计依据：`docs/design.md` v1.5.3，重点读 3.5、3.6、4.2、4.3、12.3.2–12.3.5、13.4、13.5 节和附录 A。

## 本轮范围

**不做**：投稿者组同步（M2）、战队、赛事、内战、组队大厅、开放 API、AI 审核、预渲染。

## 任务

### T1 修复：SMTP 密码的加密要覆盖所有写入路径

现状：`smtp_password` 是普通 `TextField`，只有 `SiteSettingsAdminForm.save()` 调用 `encrypt_value()`。复核时用 ORM 写入，数据库里存的是**明文**。

要求：

1. 把加解密下沉到**自定义模型字段**（或模型层的 `save()` / `from_db()`），保证任何写入路径都加密、读取透明解密
2. 后台表单保留「留空 = 不修改已保存密码、不回显原值」的行为
3. 历史明文要有明确处理：识别出不是密文时，要么在下次保存时自动重新加密，要么报一个说明清楚的错误，不能出现「密钥错误」这种误导性的报错
4. 测试：**用 ORM 写入后查原始数据库值必须是密文**；密文往返正确；明文历史值的处理路径有覆盖

### T2 游戏 ID 与段位（设计 3.5.2、12.3.2、附录 A）

1. `GameAccount` 模型：`battletag`（全站不区分大小写唯一，用表达式唯一约束）、三个位置的段位分数、`ranks_updated_at`
2. 段位编码按附录 A：分数 = 大段序号 × 5 + (5 − 小段)，前 500 为 40，未定级为空。提供编码和显示的双向转换函数，并写测试覆盖全部大段和边界
3. BattleTag 格式校验按 3.5.2 节（名称 2–12 字符、不含空格和 `#`、数字 4–6 位）
4. 每人最多 5 个游戏 ID（读 `SiteSettings.max_game_accounts`）
5. 被别人占用时的提示文案按 3.5.2 节
6. 删除限制：本轮还没有内战报名和车帖，服务函数里留出检查的位置并写清楚注释说明哪个里程碑接入，**不要写假的 TODO 实现**

### T3 联系方式（设计 3.5.3、12.3.3）

1. `ContactMethod` 模型：类型（QQ / 微信 / 手机号 / 其他）、值、(user, type) 唯一
2. 各类型的格式校验按 3.5.3 节
3. 查看权限用 Django 权限 `accounts.view_contactmethod`；前台任何页面都不显示别人的联系方式

### T4 个人中心（设计 13.4 路由、13.5）

实现 `/me/`、`/me/game-accounts/`、`/me/contacts/`、`/me/security/` 四个页面（`/me/teams/`、`/me/registrations/` 留到有战队和赛事之后）：

1. 基本资料：昵称、是否来自 SJTU（可修改，修改后自动换组）
2. 游戏 ID 与段位：每个 ID 一张卡片，段位徽章 + 更新时间；新增、编辑、删除都用 HTMX 在卡片内完成
3. 联系方式：行内增删改
4. 账号安全：修改密码、修改邮箱入口（复用 allauth 页面）
5. 资料不完整时，所有个人中心页面顶部显示提示条，列出缺少的项目
6. 左侧菜单（手机端为顶部标签），所有页面移动端可用，不能出现内联 style

### T5 功能权限（设计 4.3、12.3.4、12.3.5）

1. `FeatureGroupRestriction` 和 `FeatureUserRule` 两张表
2. `accounts.permissions.can_use(user, feature)`，判定顺序严格按 4.3.2 节：单用户规则 > 任一所在组的限制 > 默认全开
3. 后台两个 `ModelViewSet`（超级管理员可见），用户详情页给出快捷入口
4. 本轮还没有可以接入的功能点，用测试覆盖判定逻辑即可；被禁止时的前台提示文案在 4.3.2 节，先写成可复用的辅助函数

### T6 `init_site` 完整化（设计 4.1、4.2）

1. 创建全部用户组：内容编辑、赛事管理员、内战管理员、认证作者、投稿者、交大用户、校外用户
2. 分配本轮能分配的权限：进入后台（`wagtailadmin.access_admin`）、查看联系方式（`accounts.view_contactmethod`，给赛事管理员和内战管理员）
3. 其余权限等对应功能出现后再补，命令里写清楚
4. 命令必须幂等：重复执行不重复创建、不覆盖管理员手工调整过的成员关系
