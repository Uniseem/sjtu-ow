# 297 最小充分验收与上线前收口

## 背景

用户要求用最少量测试、最高效的方法完成剩余内容并上线。295 已完成代码主体、一次最终整组和两次初版真实旧库演练，但最后的编辑器、表单、排序及迁移增量尚未在最终源码上闭环；完整剩余对拍、账号边界、组件、错误页和双引擎六旅程也未全部完成。296 已明确不做磁盘清理和异地备份。

## 本轮范围

- 复用 295 的断点和日志，只跑尚未完成或受最终增量影响的专项，不重跑已有且未受影响的通过项。
- 修复剩余页面、编辑器、表单、排序、账号边界和浏览器旅程的真实失败。
- 在最终源码上跑一次整组，以及两次真实旧库演练并删除副本。
- 更新 295 的独立复核结论、STATUS 和本轮报告；提交推送并等待精确提交 CI。
- 全部上线前门通过后，下一轮立即按 cutover 剧本上线。

不配置 R2，不清理磁盘，不做试用站，不改冻结旧站，不放宽像素阈值、业务限流或权限规则，不新增依赖。

## 任务

1. 运行 295 `remaining.sh`：剩余后台/资源对拍、组件、账号正常与错误边界、错误页、Chromium/WebKit 三种旅程、最终整组。
2. 仅针对失败项读日志、修复并重跑受影响专项；同因批量修复，避免逐页重复跑。
3. 最终源码稳定后，以最新正式站备份重新执行两次真实旧库演练；正式站只读，数据直达测试机，用完删除。
4. 对照 final-batch 完成标准逐项审计，不用窄测试替代缺失证据。

## 验收标准

- `remaining.sh` 所有步骤退出 0；若工具误判，必须有严格、可审计且不放宽业务要求的修复或经用户批准的差异记录。
- 最终源码整组退出 0，精确提交 CI 成功。
- 两次最终真实旧库演练迁移、媒体/字体、逐表对账、规则和实际页面全部通过；第二次不超过 900 秒；真实数据全部删除。
- STATUS 不再把本轮完成项记为待办，并清楚列出下一轮割接动作。

## 即时收口

用户随后要求「先结束吧，push」。按此停止测试机当前批次，保留失败和未验证项，阶段性提交；不把本轮写成已完成或可割接。
