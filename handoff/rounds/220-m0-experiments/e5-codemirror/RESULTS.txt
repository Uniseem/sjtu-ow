default-src 'self'; script-src 'self'; style-src 'self'; ... (no unsafe-inline, no nonce). Real headless Chrome over CDP.

1. Editor in the page (document root), the way EasyMDE is used today:
   NOT styled. style-mod injects a <style> element into the document; the browser blocks it
   ("style-src-elem inline" violation, console error). Computed style: .cm-editor display:block, .cm-content
   white-space:normal, .cm-scroller overflow:visible, no theme, no highlighting (screenshot-document-root.png).
   Typing, toolbar actions (bold/quote/h2 through transactions) and undo still work: the document model does not
   depend on CSS; it just looks broken.
2. Editor mounted in a ShadowRoot (new EditorView({root: shadowRoot, parent: shadowRoot})):
   fully styled and 0 violations. style-mod uses one constructable stylesheet (document.adoptedStyleSheets = 1,
   <style> elements = 0) because its root is not a Document (style-mod.js: `if (!root.head && root.adoptedStyleSheets ...)`).
   display:flex, white-space:break-spaces, overflow-x:auto, our EditorView.theme (min-height 224 px, monospace font) applied,
   markdown highlighting visible, focus and selection fine, Input.insertText with Chinese text works, toolbar buttons
   (outside the shadow root) act on the view, undo works, selection read back through the shadow root's getSelection.
   (screenshot-shadow-root.png)
Conditions for "pass": mount in a ShadowRoot; browser needs adoptedStyleSheets (Chrome 73+, Firefox 101+, Safari 16.4+;
the back office is a desktop tool); site tokens reach the editor because CSS custom properties inherit into shadow trees,
but page CSS selectors do not, so the editor theme is written with EditorView.theme.
Fallback if a browser is ever a problem: style-src-elem 'unsafe-inline' for /admin only (style-src-attr stays 'none').
Size: 502 KB / 174 KB gzip (lang-markdown pulls the HTML/CSS/JS language packs in for HTML blocks); fine as a lazy chunk
loaded only by the article/page/tournament/scrim edit screens.
