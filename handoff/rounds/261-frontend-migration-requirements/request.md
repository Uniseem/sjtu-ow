# 261 前台迁移要求文档

## 背景

用户 2026-10-10：「目前这个新的前端迁移的一塌糊涂。请你给出完整的迁移要求文档。」随后：「接进 STATUS 和 AGENTS，作为 261 提交推送。之后开始写前端吧」。

259 已经把正式站割接到新栈，260 报告「前台 16 页面与专用组件全量移植上线」。本轮先核查正式站和代码的真实状态，再把「前台要做成什么样、怎么证明做完了」写成一份可以逐页验收的要求，作为之后重做前台的依据。

## 本轮范围

做：

1. 核查：对正式站发只读请求（状态码、标题、接口返回）、在内置浏览器里看几页；读 `web/` 和相关的 Go、Caddy 代码
2. 写 `docs/frontend-migration.md`：现状、保留和重写清单、不变量、前端架构要求、前台和后台每页的验收、后端和部署缺口、验收方法（和旧站对拍）、待拍板事项、阶段计划、流程纪律
3. 接进 `handoff/STATUS.md`（文件头、「重构接到这里」、「现在该谁动手」、新的「前台页面进度」表、「还没定的」、轮次表）和 `AGENTS.md`（开工前读什么、重构一节、文档维护表、新的坑）

不做：

- 不改任何代码，不动正式站（回滚与否等用户拍板）
- 不改 `design.md`、`design-next.md`、12 号文档（拍板以后再改）

## 任务

| 编号 | 任务 | 验证方式 |
|---|---|---|
| T1 | 正式站核查 | `curl` 各地址的状态码和 `<title>`、战队接口的返回、一键退订的方法；浏览器看战队页和登录页 |
| T2 | 代码核查 | 路由表数占位页、各页面数读写请求、找色板类和不存在的组件类、看生成的接口函数和会话透传、核对 Vue 的 `createApp` 挂载行为 |
| T3 | 写要求文档 | 每条现状标注来源（实测 / 读码）；每页给出旧模板、数据接口、现状、要点 |
| T4 | 接进 STATUS、AGENTS | 下一个人从 STATUS 和 AGENTS 都能找到这份文档 |

## 验收标准

- 文档里的每条现状都能在报告里找到对应的命令输出
- 测试机整组（`bash scripts/remote-check.sh`）退出码 0（本轮只改文档，仍按规矩跑）
