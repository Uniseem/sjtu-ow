# 197 AI 审核的设置搬进后台（v7.1）

## 背景

用户 10-05：「把 ai 的设置也放到后台去，我不想改什么 env，只想在后台改」。

到 196 为止，AI 巡查要在服务器 `.env` 里设 `MODERATION_API_KEY`（自建或聚合平台再设 `MODERATION_BASE_URL`，关思考模式之类的参数是 `MODERATION_EXTRA_BODY`，另有 `MODERATION_TIMEOUT`、`MODERATION_MAX_OUTPUT_TOKENS`），改完重启 web 和 worker；后台只能开关、选模型、设上限和提醒邮箱。正式站一直没设密钥，巡查在空转。

## 本轮范围

1. 设计 5.5.3、12 章全站设置表、15 章密钥一行、16.3 环境变量表，`docs/admin.md` 4.6，附录 D v7.1：这五项改成「全站设置 → AI 审核」里填，不再读环境变量
2. `SiteSettings` 加五个字段：接口密钥（和 SMTP 密码一样加密存储、表单不回显、空着不改）、接口地址、附加请求参数（JSON）、超时、最多输出 token
3. 迁移：加字段；升级时环境变量里要是设过，搬进数据库（之后不再读）
4. `moderation` 的配置、服务商、「没配密钥不送审」、上线清单、巡查记录页和 `init_site` 的说明都改读全站设置
5. 后台全站设置页右侧加「试一下 AI」，填好密钥、保存后在同一页就能试
6. 附加参数校验：必须是 JSON 对象，不能带会改掉请求本身的键（`messages`、`tools`、`tool_choice`）
7. 去掉 `settings/base.py` 里的这几个环境变量、`.env.example` 里的两行；README、AGENTS（硬规则 8 的密钥列表、两条过时的坑）跟着改

## 验收标准

- 后台填了密钥就能送审，不用碰 `.env`、不用重启
- 密钥在数据库里是密文，页面上看不到，空着保存不会清掉
- 原来测 `settings.MODERATION_*` 的测试改成测全站设置；新规则有「拆掉就红」的测试
- 整组检查全绿；正式站升级（先备份）
