# 201 赛事内战的改动手动发信，群发可以重复发、第二封起写明之前发过几次

## 起因

用户 10-05 回答自动保存的问题时说：「赛事和内战也改成类似文章那种要手动点发信才行的。而且全站的发送邮件不要限死只能发一次，但是第二封开始在信件开头注明当前文章或者活动之前已经发过多少次邮件了，这次发送可能是有修改。」

现在：

- **改了比赛 / 内战时间**（v6.34）：已发布的赛事、内战在后台一保存、开始时间变了，就自动给报名的人发「时间改了」。下一轮（202）要改成自动保存，调一个时间会一路发好几封
- **通知全体成员**（v6.19）：每场赛事、内战、每篇文章只能发一次（数据库有唯一约束，`send_waiting` 也按只有一条写）；发过之后文章的按钮藏起来，赛事内战的按钮还在、点进去才说「同一场只发一次」
- **要求作者修改**（v6.17）：本来就能再发，但信里不说之前发过

子任务把这些发信的地方和「只发一次」的记号都列了一遍（结论见报告）。

## 要做的（设计 8.1、9.1、10.2、10.3、10.4，v7.5）

1. **保存赛事、内战不再发信**：已发布的赛事、内战改了开始时间（新时间还没到）时，只**记下报名的人原来知道的时间**（`moved_from`，改了几次也只记最早那个；改回原样就清掉），重排开赛提醒照旧。编辑页的「接下来」写「比赛时间从 X 改到了 Y，报名的人还不知道」，旁边就是「通知报名的人」
2. **「通知报名的人」**（新，赛事和内战）：和「通知全体成员」一样先预览再发；收信的人是原来收「时间改了」的那些人（赛事：有效名单里的人和散人池；内战：全部报名者），不能退订（和本人报的活动有关）。信：「赛事有更新：赛事名」/「内战有更新：内战名」，时间改过就写「原来 X，现在 Y」，没改就说信息有更新、以活动页面为准；可以写一段说明（选填，最多 500 字）。发出后 `moved_from` 清掉。列表「更多」和编辑页都有
3. **群发可以重复发**：去掉「同一场只发一次」，发送记录不再唯一；文章发过以后按钮照样在。已经安排了「上线时通知」的文章不再重复安排（只能有一条在等）。按钮和预览页写「已发过 N 次，上次某时发给 M 人」
4. **第二封起信的开头写明**：同一场赛事、内战、同一篇文章的信（全体成员和报名的人都算），从第二封起在称呼下面、正文前面加一块提示：「关于这场赛事「X」，之前已经发过 N 次邮件，这次可能有修改，请以这封为准。」纯文本版同样一段；预览页看得到。「要求作者修改」同一条内容第二封起也写（「之前已经就这条内容发过 N 次修改提醒」）
5. 自动发的信（开赛提醒、内战提醒、队长提醒、AI 巡查提醒、取消通知）照旧只发一次：它们不是有人点了发的
6. 后台手册、样张信、操作记录的名字跟着改

## 验收

- 已发布赛事、内战改时间保存后：没有信，记下了原来的时间，编辑页有提示；改回原样提示消失
- 「通知报名的人」发给对的人、信里有原来和现在的时间和说明；发完提示消失
- 同一场能发第二次、第三次；第二封起信的开头写着之前发过几次；第一封没有这块
- 文章「上线时通知」只能安排一条；上线时那一条发出
- 新规则拆掉就红；整组检查、浏览器走查通过；有迁移，正式站升级前备份
