# 174 后台用户列表的批量删除、批量停用关掉

## 背景

继续自主推进。173 对停用账号时顺着看后台「用户」列表：设计 3.7 说用户不做物理删除、停用要写原因并自动取消待审批的入队申请；115 去掉了单个用户的「删除」按钮，编辑页停用时要求填原因、调 `after_deactivation`。

但 Wagtail 在用户列表上自带三个批量操作：分配角色、**删除**、**设置启用状态**。在测试机上试了一下，以超级管理员勾一个用户、批量删除、确认：

```
BULK ['/admin/bulk/accounts/user/assign_role/', '/admin/bulk/accounts/user/delete/', '/admin/bulk/accounts/user/set_active_state/']
GET delete 200
POST delete 302 victim: None
```

用户被物理删除了（连带删掉他的游戏 ID 等），违反 3.7；批量停用直接改 `is_active`，不要求原因、不取消申请。

## 本轮范围

1. 用户列表去掉「删除」「设置启用状态」两个批量操作（按钮不显示，地址 404），保留「分配角色」
2. 设计 3.7（v6.58）

## 验证

测试：列表上没有这两个按钮、还有分配角色；对这两个地址提交，用户还在、`is_active` 不变。变异逐条改坏。

## 验收标准

测试机上整组检查全绿；变异全部被抓到；推送 `main`，CI 绿；演示站升级。
