# 182 上线准备：恢复演练和转正式站的步骤

## 背景

用户 10-04：「不要再关心细枝末节了，看看整体上有没有办法上线」。

在演示站上查了一遍（后台「上线清单」的每一项、备份、定时任务、外部资源、国内打开速度）：代码这边没有挡着上线的事，挡着的是只有用户能给的东西（发信账号、协议里社团要填的事实、超级管理员、演示数据怎么处理）。

我这边能做、STATUS「服务器上」一直没做的两件：

1. **在另一台机器上做一次恢复演练**（目标 4 小时内恢复）。备份每天在跑，但从没真的拿它恢复出一个站点
2. **从演示站转正式站的步骤**：上线那天要把演示数据清掉、换成干净的库。这一步没写过、也没走过

## 本轮范围

1. 在测试机上照 README 从零搭一个站，把演示站当天的真实备份恢复上去，看页面、数据是否完整，每步计时
2. 在恢复出来的站上演练转正式站：留最终备份并拷出备份卷、清空库和上传文件、重新初始化、去掉测试环境标记，检查
3. README 写「演示站转正式站」一节（走通的命令）；STATUS 的上线计划改成现在的样子：哪些要用户做、哪些我来做
4. 演练用的机器和数据用完删掉

演示站的三把密钥不离开演示站：演练站用自己的密钥，恢复时 `--skip-key-check`（演示站没存 SMTP 密码和对象存储密钥，没有加密内容会丢）。

## 验收标准

恢复出来的站点首页、列表、登录页正常，用户、战队、文章、评论、图片数量和演示站一致；转正式站后库是空的、没有测试环境横幅、搜索引擎可以收录；步骤写进 README；不改网站代码。
