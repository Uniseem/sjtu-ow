# 199 后台每页的权限并进 placed

## 起因

196 自查挑的刺：「门只有一道是自动查的」。`backoffice.nav.placed` 只管进不进后台（`can_enter`），每页自己的权限靠视图开头那一行；`nav.py` 里标签的 `allowed` 只决定画不画链接。新加一页忘了那一行，能进后台的人就都能打开。STATUS 的 `next` 里写着这一条和「清 195 留下的审核通知代码」。

这轮先让一个子任务把全部 92 个后台地址的视图逐个核了一遍（视图自己的判断和所在标签的 `allowed` 比）：

- 大部分和标签一样（同一个服务函数）
- **比标签松的**：选图对话框（没有判断，只靠结果过滤）；「发送测试邮件」「测试对象存储」看 `core.change_sitesettings`，标签是超管（默认没有组有这个权限）
- **比标签严、要留着的**：图片集合只给超管；新建、删除分类和成员分组要 `add_`/`delete_` 权限；文章的「通知全体成员」要能管别人的文章；Markdown 传图、图片上传要有能加图的集合；文章、页面、图片各自的对象权限
- 四个视图先取对象再判权限（分类、成员分组的编辑，分队页两个），没权限的人能从 404 和 403 看出编号存不存在

「195 留下的审核通知代码」：查了，`content/notifications.py` 从 127 起只有新文章通知，没有「审核通过 / 退回」的信；195 自查指错了文件。相关的只有 `templates/wagtailadmin/notifications/base.txt`，它让 Wagtail 自己的通知（超管在 `/wagtail/` 里重开工作流、页面评论）也套本站的信，留着。

## 要做的（`docs/admin.md`，设计 v7.3）

1. **`placed(大类, 标签, …, allowed=None)` 把门**：进门之后再看这一页的权限，默认就是标签的 `allowed`（和画不画链接是同一个函数），不够就 403，视图不会被调用。比标签严的页面写 `allowed=`（图片集合三页 `allowed=access.is_superuser`）
2. **新后台（`backoffice/views/`）里和标签一样的判断删掉**：超管页的 `_superuser`、网站页面和图片的 `_allowed`、评论的 `_moderator`、赛事内战的 `_tournament_manager` / `_scrim_manager`、分类和成员分组的「能改」；只留比标签多的那部分（`add_` / `delete_`、对象权限）
3. v7.0 以前就有的页面（报名审核、巡查记录、头像、分队、编队、字体、静态页、活动数据、手册、赛事内战的动作）自己的装饰器和判断不动，和标签是同一个判断，多一道
4. 测试：后台每个地址（「通知全体成员」除外，它按种类自己放）用「能进后台、但这一标签不给他」的人请求，都在门口 403、视图不被调用；`allowed=` 比标签严的生效；原来四处先 404 的现在先 403
5. 文档：`docs/admin.md` 原则 4、2 章「进门」、4 章开头、6 章测试；设计 10.3 里「Wagtail 的投稿审核通知」改成现在的说法；STATUS 去掉「清 195 留下的审核通知代码」

## 验收

- 新加一页只要用 `placed` 放进某个标签，标签不给的人就打不开，不用视图再写一行
- 拆掉 `placed` 里的这道检查，测试会红；把集合页的 `allowed=` 去掉，测试会红
- 原来的测试全过；整组检查、`journey.py pages`、`journey.py admin` 通过

## 不做

- 网站页面的预览没有对象权限判断、首页置顶和栏目介绍不看页面权限（内容编辑本来都有这些权限）：记下，留给以后
- 评论的未知动作是 403、赛事内战是 404：不统一
