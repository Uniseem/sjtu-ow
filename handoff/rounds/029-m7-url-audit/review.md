# 029 复核结果

## 结论

**通过。** 27 个地址全在，5 个公开页面能渲染。第一版测试恒真，变异测试抓出来并改掉了。

## 这轮最值得记的一条

**断言恒真比断言太弱更隐蔽。**

前四次同类问题（019/021/023/026），断言至少还在测某样东西，只是测的不是要紧的那样。这次不一样：

```python
try:
    resolve(path)
except Resolver404:
    pytest.fail(...)
```

这段代码看起来无可挑剔——它明确地在说「这个地址必须能解析」。但因为 `wagtail_urls` 是兜底，`Resolver404` **永远不会抛出**，整个 try/except 是死代码。

**光读代码发现不了**，读起来完全合理。只有变异测试能发现。

做法上的结论：**凡是「断言某件坏事不会发生」的测试，必须做一次变异测试**。断言正向结果（等于某个值）出错时至少会红；断言反向（不抛异常、不包含某字符串）如果条件恒真，就是一条永远绿的死测试。

## 认可的判断

1. 断言 view 名字而不是「能解析」。失败信息直接点出「落到 wagtail_serve 了」，下一个人不用重新推理一遍。
2. 公开页面额外断言正文非空。`resolve` 成功、状态码 200、但模板炸了渲染出空页面，是 019 踩过的那种坑。
