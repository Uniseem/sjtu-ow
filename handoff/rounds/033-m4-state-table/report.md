## 结论

**完成，没有发现新问题。** 设计 8.5 的 9 行状态流转表逐格走了一遍，30 个测试，全部符合。

018 轮从这张表里读出来的三个洞当时已经修了，这轮把它们和其余所有格子一起钉住。

## 为什么值得单独做一轮

015 轮的 26 个测试覆盖得不算少：8 项提交校验、一次性列出所有问题、数据库兜底、名单冻结、同步、三种审核模式的主流程、撤回重提、截止时间。

**但 018 轮我从表里读出三个洞时，这 26 个测试一条都没红。**

原因是它们测的是「常见路径走得通」，而表里的很多格子是「某个人在某个模式下**不能**做某件事」。这类格子不会在正常使用中被走到，只会在有人越权时才起作用——正是最需要测试、也最容易没有测试的地方。

## 覆盖的格子

| 设计 8.5 的行 | 测了什么 |
|---|---|
| 待审核 → 通过 → 已通过 | 本站模式管理员能、上游模式上游能；**本站管理员在上游模式不能**、**上游在本站模式不能** |
| 待审核 → 通过 → 待上游确认 | 两级审核本站管理员能；**上游不能跳过本站这一级** |
| 待审核 → 驳回 → 已驳回 | 本站和两级模式管理员能、上游模式上游能 |
| 待上游确认 → 确认 → 已通过 | 上游能；**本站管理员不能** |
| 待上游确认 → 驳回 → 已驳回 | 上游能 |
| 已通过 → 撤销通过 → 已驳回 | 本站模式管理员能、上游和两级模式上游能；**本站管理员在后两种模式不能** |
| 三种状态 → 撤回 → 已撤回 | 待审核 / 待上游确认 / 已通过各测一次；已驳回和已撤回不能再撤 |
| 三种状态 → 同步名单 → 待审核 | 三种状态各测一次，版本加 1、日志里有完整名单 |
| 已驳回 / 已撤回 → 重新提交 | 两种状态各测一次，**复用同一条记录**、版本加 1 |

表格下面那几条说明也测了：备注必填（驳回和撤销各一次）、截止后队长不能动但管理员可以、撤回后名单不占名额、每次变化都写日志（前后状态、操作方、版本、备注、时间）。
