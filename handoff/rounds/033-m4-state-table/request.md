# 033 报名状态流转表逐格核查

用户说：

> 上游的报名会下发到我们这里，具体的接口他们也还没写……先把本站自己的报名系统搞清楚就好。

设计 8.5 有一张 9 行的状态流转表，每行还分「谁可以操作」。015 轮覆盖了 8 项提交校验和常见流程，**但没有按这张表逐格走过**——018 轮从表里读出来的三个洞（上游在本站模式越权、两级审核被跳过、审核不幂等），当时一条测试都没红。

这轮把表变成测试。

## 任务

9 行 × 三种审核模式，每格测两件事：**该能操作的人能操作**，**不该能的人被拦住**。

加上表格下面那四条说明：
- 驳回和撤销必须填备注
- 截止后队长不能动，管理员和上游不受限
- 已驳回和已撤回的名单不占名额
- 重新提交复用原记录、版本加 1
- 每次状态变化都写日志

## 验收标准

1. `ruff` / `pytest` / `makemigrations --check` / 生产 `check --deploy` 干净
2. 变异测试：破坏状态机的守卫，确认对应的格子会红
3. git 提交，信息以 `033:` 开头
