# 173 停用、注销的账号的入队申请收尾；注销时每张表怎么处理写成清单

## 背景

继续自主推进。172 对完导出，接着对注销（同是 058 做的）：注销时每张带个人信息的表怎么处理？对下来大都处理了；入队申请在注销时由 `leave_all_teams` 撤回了。但从队长这边看还有个洞：

- `approve_application` 不看申请人的账号还在不在用。管理员在后台用户管理里停用一个账号（不走注销），他等着的入队申请还挂在队长的待审批列表里，队长点「通过」，停用的账号就进了战队
- 7 天提醒、14 天自动关闭也照样算这些申请；自动关闭时还给申请人发信
- 发信那一层不认已注销账号的地址（`deleted-…@deleted.invalid`），哪条路径漏了就会多一封发不出去的信，后台待办里记成「邮件没发出去」

## 本轮范围

1. 队长通过时，申请人的账号已停用或注销：关闭这条申请（「申请人的账号已注销或停用」）并提示，不编进战队
2. 待审批列表、7 天提醒不算这些申请；14 天自动关闭照样关，但不发信
3. 发信时跳过 `.invalid` 地址
4. `accounts.services.ON_DELETION`：每个指向用户的字段注销时怎么处理（删除、撤回、保留并显示「已注销用户」），测试数一遍
5. 设计 3.8、7.3（v6.57）

## 验证

测试：停用后待审批列表看不到、通过会被拦下并关闭、不进战队；不提醒、关闭时不发信；`.invalid` 地址不发；清单和库里的字段一致。变异逐条改坏。

## 验收标准

测试机上整组检查全绿；变异全部被抓到；推送 `main`，CI 绿；演示站升级。
