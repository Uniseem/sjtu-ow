# 269 实现报告

## 结论
找回密码和改邮箱流程已实现，按用户「先更新文档然后 push」收口。远端整组、浏览器回归与本次六页四组合严格对拍通过；F3 仍为部分完成，没有部署正式站。

## 实现
- 三步找回密码页面：邮箱 → 验证码 → 新密码。保持旧地址与中文表单；无邮箱或未确认码时真实跳回相应入口，不在页面里伪装成功。
- 保留 combined confirm 接口，新增 verify/state/complete。正确码换 32 字节随机凭证，库里只存 SHA-256，期限沿用原码 3 分钟；单独的 HttpOnly/SameSite Cookie（生产 Secure），不进入 JSON、URL、浏览器存储或登录会话。重发、改密码、换邮箱作废旧凭证；完成事务内重验、删除凭证和全部旧会话，不自动登录。
- 改邮箱页显示当前邮箱和待验证地址，支持重发/取消；缺少最近重新认证时去确认身份，draft 经安全站内 next 带回，用户再提交。验证码页识别 change 模式，从后端读真正待验证邮箱，不信查询串的地址；确认调用换绑接口，成功提示由当前会话消费一次。
- 修复原 ConfirmEmailChange 错码计数跟错误响应一起回滚的问题：计数和第三次删除先提交，再返回校验错。申请时空令牌不能绕过重新认证。
- 生成 API 客户端与参考手册；新增凭证状态、一次性消费/重发失效、原截止时间、三次错码持久化回归。没有新增依赖。
