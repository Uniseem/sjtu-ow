# 282 内容公开门矩阵

## 背景

用户授权自主决策连续推进，281已补内容投影。当前需闭环公开出口：文章详情、普通页、列表/首页/相关文章/作者计数、置顶、sitemap、评论读写。旧设计5.6明确撤下或受限文章的全部前台评论接口404，后台处理入口另走后台。frontend-migration的文章页要求未发布404，公开数据接口不承担草稿预览。

## 本轮范围

- 后端范围例外：新增独立 pages.is_public 标记，折叠旧页/祖先访问限制，保留search_public语义；已有库迁移继承现有缓存，普通页补导入限制。
- 所有公开内容出口使用 live+is_public；搜索额外保留search_public；草稿作者/编辑/超管也不能从公开详情读草稿，后台详情保持已有身份权限。
- 评论读取、创建、回复、编辑、删除、点赞、隐藏/恢复、置顶/取消置顶共用文章公开门；错文章编号的置顶不能动另一篇。拒绝后数据库不变，数据库失败不吞。一般邮箱/功能/管理能力门保持独立。
- 本轮不实现Wagtail受限页的密码/用户组解锁界面；本轮接口是公开投影，受限页只在已有授权后台读取。割接前仍需核对真实旧库是否存在需保留的受限页访问流程，不能把公开API守门称为已迁完所有Wagtail限制能力。
- 必要的现有夹具/前端回归按公开接口语义修正；长期前后端分工不变。旧站只读，不加依赖、不部署。
- 对拍唯一异常的隐私页桌面深色字形/行距不一致，而其他三组合像素差0；本轮追加截图工具范围例外，等待字体就绪与绘制帧再拍，旧站/阈值/比较规则不改。单独复验异常项，保留首轮原始失败证据，不能重跑一次就抹去它。

## 验收标准

1. 导入本页/祖先/其他分支限制，文章/栏目/普通页均正确；发布状态不改变。迁移复制缓存且可重复升级，不把搜索隐藏当成访问私密。
2. 访客/成员/作者/编辑/超管/停用的真实HTTP矩阵；公开详情草稿/受限/缺失404；列表/首页/置顶/sitemap/作者计数/关联推荐不含私密内容；后台可用，匿名/无能力不能用。
3. 评论各动作在撤下/受限/缺失文章上拒绝；数据库快照前后逐列相同。公开文章关闭评论只禁发表/编辑，仍可读/点赞/删除与合法管理。回复错误文章/置顶错文章拒绝，管理动作也不得绕过公开门。
4. 测试机后台专项、可编译规则变异、整组、必要浏览器与公开内容回归对拍；真实结果写report/review/STATUS，一个中文提交推main并核验对应CI。真实评论写旅程另轮推进，未跑写未验证。
