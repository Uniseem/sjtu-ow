# 227 M1 第六轮：任务队列和定时器

## 背景

226 把日历、退订的旧签名和字段加密接上了。M1 还缺 worker 赖以活着的那一半（12 号文档 5.10）：三条车道的任务表、只有一个 worker 能起来、启动时把上次杀掉的「运行中」放回队列、上海时区的定时项。224 留下的过期限流桶、幂等回执、过期会话，也由每天 04:00 的清理来删。

## 本轮范围

### 做

1. **`jobs` 表**（5.10 的列）：`mail` / `default` / `slow` 三条车道。`Enqueue` 在调用方的写事务里插入。`EnqueueOnce` 按现行站 `core/tasks.py`：同样的 `dedupe_key` 已经有一条在等，到期时间相同就不再排；`earlierCounts` 时，已有一条不晚于这次的也不再排。
2. **认领和重试**：每条车道一次取一条到期的、优先级高的。邮件失败按 1 分钟、5 分钟、30 分钟重试，三次之后记失败；别的车道失败一次就记失败。启动时把 `running` 改回 `ready`（可能重做，和现在一样）。
3. **只有一个 worker**：库里一行锁，心跳 120 秒内第二个起不来；心跳断了可以接手。心跳同时写 `worker_status`。
4. **定时器**（`Asia/Shanghai`，记在 `schedule_runs`）：每 30 秒的定时上线和巡查、每天 03:00 备份、04:00 清理、04:40 旧前端文件、每周日 04:30 `PRAGMA optimize` 和 `wal_checkpoint(TRUNCATE)`。错过了补跑一次，不补历史每一次。04:00 清掉已完成超过 30 天的任务、过期会话、超过 24 小时的幂等回执、旧的限流桶。备份、上线、巡查、删旧前端文件这四件还没有对应的表和目录，先把点挂上，处理函数等后面的轮次注册。

### 不做

- 信纸、SMTP、待发信、healthz 的对外页面、apigen。
- 把 `sjtuow worker` 真正跑起来（和 `serve` 一起，等这几样都有了再挂）。
- 入队申请、空草稿那些还没有表的清理。

## 验收标准

`cd server && gofmt -l .` 为空，`go vet`、`staticcheck`、`govulncheck`、`go test ./...` 全绿；测试机整组全绿。不加依赖。
