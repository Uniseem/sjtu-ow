# 057 事件表剩下的触发；后台设置的过时标签

## 背景

056 对照设计 13.13.4「触发重新生成的事件」表，14 行里 8 行没做全，补了和首页、参赛记录相关的。剩下：

| 事件 | 应该重新生成 | 现状 |
|---|---|---|
| 内战报名、修改报名、取消报名 | 活动详情（报名统计和名单） | 不刷新 |
| 用户修改昵称 | 该用户所在的战队主页、报名的内战活动详情、署名的文章 | 不刷新 |
| 文章发布、修改、移动、撤回 | ……、**关联赛事的详情页** | 关联赛事的详情页不刷新 |
| 游戏模式修改 | ……、组队大厅外壳 | 不刷新 |

另外后台「全站设置」里 9 个字段的说明文字是「后续里程碑使用」，两个分组标题带「（后续里程碑使用）」。这些参数早就在用了（比如战队人数上限、AI 审核开关），会让管理员以为改了没用。

## 任务

1. 上表四行补上
2. 改昵称的触发**只在昵称真的变了时**才跑：登录会更新 `last_login` 并保存用户，不能每次登录都刷新一堆页面
3. 设置字段的说明改成说清楚这项管什么；分组标题去掉「后续里程碑使用」
4. 每条都有测试，逐项变异

## 验收标准

本地四项检查干净；推送后 CI 绿；测试机重建后看后台设置页的说明文字。
