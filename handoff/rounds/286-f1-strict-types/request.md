# 286 Web严格类型门

## 背景与范围

用户授权自主规划推进。F1/A4要求每轮vue-tsc --noEmit严格模式，266已批准vue-tsc依赖；当前Web没有tsconfig和类型检查入口。本轮补全工作区的可执行类型门，按真实报错修类型。

- 增加已批准vue-tsc及其必要TypeScript/Node开发类型，核对MIT等许可证；只在测试机安装、生成锁文件并检查，回传准确文件。
- 覆盖apps/site、packages/api/shared/ui及配置/测试的TS/Vue源码；不靠排除业务目录、关strict、any/ts-ignore来获得绿色。未重写页面仍保留功能/迁移状态，类型通过不代表页面已完成。
- 接入pnpm test，使测试机整组和当前CI同一句执行类型门；修正实际契约、nullable值、模板/事件类型和可证明的边界，不手改gen，必要生成契约由apigen。
- 实际类型诊断发现后台用户详情使用裸User，JSON包含PasswordHash；本轮必要范围包含该未被页面读取的敏感字段禁止序列化及回归。其余已存在的JSON字段保持兼容，前端按真实字段读角色/用户资料。生成器查询接口保持严格键集合，调用Requester时转成普通记录，避免放宽索引签名。
- 用户本轮自主推进作为web/前端检查/规格的范围例外，长期分工不变。不改旧站，不部署，不扩大到其他页面功能重写。

## 验收

测试机后台严格类型检查、正/负向类型探针（API字段/nullable/组件或Vue模板错误必须红）、整组Go/Web、浏览器回归；有运行时改动则加相关真实旅程/对拍。记录失败诊断及最终真实日志。中文提交推main，检查精确SHA CI。
