## 任务

### T1 修正：站点主机名（006 复核发现）

现象：`content/services.py` 把 Wagtail 站点记录的主机名写死成 `localhost`，之后不再同步。实测文章详情页输出 `<link rel="canonical" href="http://localhost/news/…">` 和同样的 `og:url`，上线后分享链接和规范网址都会是错的。

按设计 16.4 节改：

1. `init_site` **每次执行**都按 `SITE_URL` 设置默认站点记录的主机名和端口（`https` 默认 443、`http` 默认 80，带端口时用给定端口）
2. 命令输出里打印设置结果，方便部署时确认
3. README 的部署步骤说明这一点
4. 测试：`SITE_URL` 变化后执行命令，站点记录同步更新；文章详情的 `canonical` 和 `og:url` 用的是新主机名

### T2 修正：视频嵌入只支持 B 站（设计 5.2、13.10、15.2）

1. 自定义嵌入规则（embed finder / oEmbed 配置）支持 B 站视频链接，至少覆盖 `bilibili.com/video/<BV号>` 和 `b23.tv` 短链
2. 前台渲染沿用你在 006 里的做法：只取播放器 iframe 的地址，不把第三方的内联样式带进页面
3. **CSP 的 `frame-src` 去掉 YouTube 和 Vimeo，只保留 B 站播放器域名**
4. 编辑器里粘贴不支持的视频链接时，给出明确的中文提示，而不是静默失败
5. 测试：B 站长链和短链都能解析出播放地址；不支持的链接给出可读的错误；`frame-src` 里没有 B 站以外的站点

### T3 投稿（设计 5.4、14.3）

1. **「投稿者」组自动同步**（5.4.2 节）：条件是邮箱已验证且 `can_use(user, "article_submit")` 为真；以下事件发生时自动重算：邮箱验证通过、用户被启用或停用、`article_submit` 相关的组限制或单用户规则变化、用户换组
2. **组权限**：对开放投稿的栏目有「新建」权限、在「投稿图片」图片集合里上传和选择图片、没有「发布」权限
3. **审核工作流**：`init_site` 创建「内容审核」工作流，只有一个步骤，审核人为「内容编辑」组，绑定到文章栏目
4. **前台入口**：`/submit/` 按 13.4 节——有权限就跳到后台新建稿件页（栏目默认选中开放投稿的第一个栏目），没权限就显示原因（未登录 / 邮箱未验证 / 没有投稿权限）
5. **后台定制**（14.3 节）：
   - 用 `construct_main_menu` 钩子，投稿者只保留「后台首页」和「图片」，隐藏页面树菜单
   - 后台首页给投稿者显示「我的投稿」面板和「新建投稿」按钮
   - 用 `construct_explorer_page_queryset` 钩子，投稿者只看到已发布页面和自己的稿件；**侧边栏页面树是否也被过滤要实测并写进报告**
   - `author` 字段只有内容编辑能看到和修改
   - 分类下拉只给投稿者列出 `allow_submission = true` 的分类
   - 图片上传限制：`WAGTAILIMAGES_MAX_UPLOAD_SIZE` 5MB、`WAGTAILIMAGES_EXTENSIONS` 只允许 JPG / PNG / WebP，投稿者只能传到「投稿图片」集合
6. **审核邮件**：用 Wagtail 自带的工作流通知，确认它走的是我们的队列邮件后端，并在报告里贴出实际收到的邮件

### T4 回归确认

投稿者进后台后**不能**看到赛事、内战、用户、功能权限、设置这些菜单，也不能通过直接访问网址进入。写测试锁住。
