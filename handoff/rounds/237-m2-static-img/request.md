# 237 M2 第七轮：把 /static/img/ 接到新站

## 背景

样张和样式里的占位图、校徽写的是 `/static/img/…`（现行站由 `/static/css/app.css` 里的相对地址解析到同一处）。新站的样式从 `/assets/` 发出，相对地址对不上；独立的 SSR 服务也只发构建产物，不发这个目录。并排截图之前先把图接上。

12 号文档 3.4：`/static/img/*` 是固定地址，缓存一天。字体库（D4）在 M8，不在这轮。

## 本轮范围

### 做

1. 样式里的 `url("../img/…")` 改成 `url("/static/img/…")`，和浏览器在现行站上请求的地址一样。
2. 独立 SSR 服务对 `/static/img/` 从仓库的 `static/img/` 发文件（svg / png / ico），`Cache-Control: public, max-age=86400`。路径越出这个目录的不发。
3. 浏览器检查请求一张占位图，确认是 SVG、状态 200。

### 不做

- 并排截图、字体（D4）、`/media/`。
- 正式站。

## 验收标准

测试机上整组通过，浏览器检查通过。四处变异先红再改回：去掉目录限制、把山脊那张图的地址改回相对路径、把缓存改成 `max-age=0`、让构建产物按源码的目录深度去找图。
