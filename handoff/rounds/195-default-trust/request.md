# 195 默认信任：头像上传即生效，成员投稿直接发布

## 背景

用户 10-05：「AI 审查的逻辑改为增量巡查……默认信任所有用户！」问了「默认信任」到哪一步，用户选**头像和投稿都直接公开**（「头像上传就生效，投稿提交就发布，不再等内容编辑审；AI 增量巡查发现不妥的发信给你，你再去隐藏或撤下」）。194 做了 AI 巡查，本轮做这两样。

现在：头像上传后「审核中」，内容编辑在「审核 → 头像」通过才换上；普通成员（投稿者）的稿件只能「提交给内容审核」，内容编辑在 Wagtail 工作流里通过才发布，只有认证作者能直接发布。

## 本轮范围

1. **头像上传即生效**：上传、处理完立刻换上（记录直接是「已通过」，没有审核人），旧的自己传过的那张删掉，显示这个人的页面重新生成。去掉「审核中」「撤回」、待审头像的通知信、首页「N 张头像等待审核」和审核标签上的件数、后台的「通过 / 不通过」。后台「审核 → 头像」默认列出正在用的、最近上传的在前，留「撤下」（撤下照旧发信告诉本人）。已经在审核中的头像，迁移时直接换上
2. **投稿直接发布**：「投稿者」组在文章栏目上有「发布」权限，写完点「发布」就上线；「内容审核」工作流从文章栏目解绑、停用（迁移做，`init_site` 不再建），正在审核中的稿件取消审核、回到草稿，作者自己发布。去掉审核标签里的「稿件」和首页「N 篇稿件等待审核」
3. **只能发布、撤下自己的文章**：Wagtail 的「发布」权限按栏目给，有它的人能撤下栏目里任何一篇已发布的文章（它的撤下检查不看是谁写的）。文章上加一道：内容编辑和超级管理员以外的人只能发布、撤下自己的文章。这也堵上了现在认证作者能撤下别人文章的口子
4. 编辑页的「投稿须知」、`/submit/` 页、个人中心头像一块的说明跟着改；后台手册里讲审稿、审头像的步骤改掉；用户协议草稿里「投稿需要经过审核后才会公开」改掉（正式站上协议页如果还是原样草稿，重新导入）
5. 设计 4.1、5.4、5.5.1、10 章通知表、14.1、14.3、19 章，细节 2.3，附录 D v6.73

不做：认证作者这个角色还留着（他们比普通成员多「推荐」标签页：网址、SEO 描述、定时发布）；后台重写（196 起）。

## 验收标准

- 成员上传头像马上换上；成员发布自己的文章、撤下自己的文章可以，撤下别人的不行（网址直接访问也不行）；内容编辑能撤下任何一篇
- 每条新规则拆掉就红；整组检查全绿；正式站升级
