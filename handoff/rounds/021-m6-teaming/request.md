# 021 内战分队

M6 的第二部分，也是 M6 的收尾。设计 9.3–9.6。

## 范围

勾选上场、分队算法、手动调整、复制结果。`ScrimSignup` 的 `is_selected` / `team` / `assigned_role` / `rating_used` 四个字段在 020 已经建好，这轮填上业务逻辑。

## 任务

### T1 分队算法（设计 9.4）

**角色限定**

```
每队位置需求 R：5v5 = {坦克 1, 输出 2, 支援 2}，6v6 = {坦克 2, 输出 2, 支援 2}

对每一种把玩家分成 A、B 两队的方式（固定第 1 个玩家在 A 队，避免 A/B 互换的重复）：
    对 A 队：列出所有合法的位置分配（每人只分到自己能打的位置，且满足 R），
             算出每种分配的总分和各位置分数
    对 B 队：同上
    任意一队没有合法分配就跳过
    在 A、B 的分配组合里找评分最小的

评分（越小越好，按顺序比较）：
    1. 两队总分之差的绝对值
    2. 各位置对位分数之差的绝对值之和

所有分法里选评分最小的；并列时随机选一个
```

- **性能**：6v6 共 462 种分法、每队最多 90 种分配。设计明确要求「先按总分对每队的分配方案去重和排序再配对」，**保证 1 秒内**。
- **无解时**要说出具体原因，比如「能打坦克的玩家只有 1 人，6v6 需要至少 4 人」。
- **重新生成**：并列时再点一次要能得到另一个等价方案。

**不限位置**：每人取所选游戏 ID 上已填段位里的最高分，穷举所有分法选总分差最小的，不分配位置。

### T2 勾选上场

后台「内战 → 分队」页。报名列表显示昵称、游戏 ID、能打的位置和对应段位、报名时间，可以按报名时间或段位排序。勾选时实时显示「已选 X / 需要 Y 人」，**只有正好等于每队人数两倍时「生成分队」才可用**。

实时计数不要引入新的前端框架——**注意 Alpine 是 CSP 构建，属性里的表达式不会求值**（020 的教训）。用原生 JS 或 HTMX。

### T3 生成与保存

生成后显示两队结果，管理员可以调整再保存。保存时记录每人的队伍、位置和**使用的段位分数**（`rating_used`），并盖 `teams_generated_at`。

### T4 手动调整（设计 9.5）

两队并排，按位置分组，每人显示昵称、分到的位置、段位。可以换队；角色限定下可以改位置。实时显示两队总分和分差；**位置人数不符合规格时标红提示，但仍然允许保存**。

设计说「拖拽」。项目里已经有 `Sortable.min.js`（`static/vendor/`）。如果拖拽在 CSP 下做不稳，**退化成下拉选择也可以接受，但要在报告里说清楚，不要假装做了**。

### T5 复制结果（设计 9.6）

```text
【周五内战】2026-10-09 20:00 · 角色限定 5v5

A 队（总分 113）
坦克：玩家甲 Genji#51234 钻石 3
输出：玩家乙 Ashe#22811 大师 5 / 玩家丙 Echo#90876 钻石 1
支援：玩家丁 Ana#11223 钻石 2 / 玩家戊 Lucio#33445 白金 1

B 队（总分 111）
……
```

**包含游戏 ID**（方便在游戏里建房间邀请）。不限位置规格不分位置，格式相应简化。

## 测试要求

至少覆盖：5v5 和 6v6 的角色限定分队各一次（断言每队位置数符合 R、每人分到的位置自己能打）、评分函数的两级比较、不限位置分队、**无解时的具体原因**（坦克不够、某人一个位置都打不了）、重新生成能给出不同的等价方案、人数不对时不能生成、**性能：6v6 在 1 秒内**、保存后 `rating_used` 和 `teams_generated_at` 正确、手动调整后位置数不符也能保存、复制结果的文本格式（**逐字比对**）、非管理员进不去分队页。

## 验收标准

1. `ruff` / `pytest` / `makemigrations --check` / 生产 `check --deploy` 全部干净
2. **用 10 人和 12 人的真实数据生成分队，贴出耗时**（设计 M6 验收要求 1 秒内）
3. 贴出一次 5v5 和一次 6v6 的分队结果，**显示每队各位置的人和分数、两队总分和分差**
4. 贴出复制结果的文本，和设计 9.6 的格式逐字对照
5. 贴出一次无解的提示
6. 真实浏览器走一遍：勾选 → 生成 → 调整 → 保存 → 复制，控制台无错误
7. 回归 + `docker build` + `caddy validate`
8. 清理验证数据，**并查一次全库计数确认干净**
9. git 提交，信息以 `021:` 开头
