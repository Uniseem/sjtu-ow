# 181 守卫普查补上「软拒绝」

## 背景

继续自主推进，接 179。STATUS 从 059 起一直挂着一条：042 的脚本认不出「`messages.error` 提示一句、再跳回去」这种拒绝，这类守卫要手动补验，一直没人补。179 用的还是同一套识别规则，所以这类守卫也没扫到。

这类写法在本站不少：限流（「今天的入队申请太多了」）、后台删除前的拦截（「还有报名，不能删」）、后台表单的 `add_error`（停用必须写原因、改了报名方式但已经有人报名）。它们返回 200 或者跳转，不是 4xx，也不抛异常，042 的规则看不到。

## 本轮范围

1. `mutate_guards.py` 复制到本轮目录，多认一种「软拒绝」：`if` 的直接内容里有 `messages.error` / `messages.warning`，或者调了 `add_error`。`--soft` 只跑这一种（不重跑 179 的 254 个）
2. 在测试机上跑完，列出来的每一处都要有结论：被抓到；没被抓到的补测试（用「能进后台但不该有这个权限」的人测）；改了也测不出来的写明理由
3. 补的测试再逐个改坏，确认会红
4. STATUS 里那条「要手动补验」改掉

## 验收标准

列出的守卫全部有结论；补的测试拆掉守卫会红；测试机上整组检查全绿；推送 `main`，CI 绿。
