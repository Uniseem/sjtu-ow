# 014 M4 第一部分：赛事

> 用户外出期间，本轮仍由 Claude 实现 + 自查。

## 背景

M3 已完成。M4「赛事与报名」是目前最大的一块，拆成三轮：**014 赛事本身（本轮）**、015 报名事务与状态机、016 后台审核与邮件。

设计依据：`docs/design.md` v1.5.7，重点读 8.1、8.2、12.8.1、13.4、13.13、附录 C。

## 本轮范围

**做**：T1–T7，只做赛事本身。
**不做**：报名（015）、上游 API 推送赛事（M5）、Webhook（M5）。凡是需要 `Registration` 的地方（取消时通知已报名队长、有报名后禁止改审核模式、详情页的已通过战队列表）都留成**一个明确的接口**，015 接上。

## 任务

### T1 数据表（设计 12.8.1）

`Tournament` 按 12.8.1 建表，含检查约束 `1 <= roster_min <= roster_max <= 20`、`registration_opens_at < registration_closes_at`，以及 `external_id` 不为空时 (source_client, external_id) 的部分唯一约束。`source_client` 指向 M5 的 `ApiClient`，本轮先留空字段（可空，等 M5 建表后再接 FK）。

### T2 后台管理（设计 8.1）

「社区 → 赛事」，赛事管理员和超级管理员可用：

1. 创建、编辑全部字段。
2. **已经有报名之后不能改审核模式**（本轮留接口）。
3. 参赛人数下限大于全站战队人数上限时给出警告（不阻止保存）。
4. 状态动作：发布、结束、取消。发布过的赛事不能删除，只能取消；从未发布过的草稿可以删除。
5. 取消时通知所有有效报名的队长（本轮留接口）。

### T3 前台页面（设计 8.2）

- `/tournaments/`：公开，只显示已发布和已结束的，分成「报名中」「即将开始报名」「已截止」「已结束」四组；已取消的不在列表里。
- `/tournaments/<id>/`：公开，显示封面、标题、简介、比赛时间、报名时间和当前阶段、人数要求、是否仅限交大、详细说明；已取消的详情页保留并显示「已取消」；草稿在前台 404。
- **报名入口**做成占位区域 `tournament-actions:<id>`：未登录提示登录；不是任何战队的队长提示「需要由队长为战队报名」；是队长显示「为战队报名」（本轮按钮先指向 015 的占位路由并说明即将开放）；已报名显示状态和「查看报名」（015 接）。
- 已通过的战队列表：本轮显示「暂无」，015 接上。

### T4 半静态与 sitemap

赛事列表和详情进预渲染；创建、修改、发布、取消、结束时重新生成；草稿和已取消的详情页不生成（已取消的从静态目录删除，但 Django 仍可访问）；已发布和已结束的进 sitemap。报名开始 / 截止时间到达时也要重新生成——用延时任务在这两个时间点排队（设计 13.13.4）。

### T5 AI 审核

赛事的详细说明在创建和修改时送审（`tournament_description`）。

### T6 初始化

`init_site` 给「赛事管理员」组分配赛事的增删改查权限（本轮只有赛事，报名等 015 再加）。

### T7 导航

顶部导航的「赛事」已经指向 `/tournaments/`，本轮让它真正可用。

## 测试要求

至少覆盖：人数上下限和报名时间的约束、草稿前台 404、已取消详情可访问且列表不显示、四个分组的划分、发布过的不能删除、草稿可以删除、人数下限警告、`tournament-actions` 占位的三种身份、预渲染事件、sitemap、详细说明送审、后台权限（普通用户进不去、赛事管理员可用）。
