# 004 M1 上半：账号、邮件与全站设置

## 背景

M0 已完成并通过复核（见 `../003-m0-hardening/review.md`）。M1 内容较多，拆成两轮：

- **004（本轮）**：账号体系、全站设置与 SMTP、异步邮件、worker 心跳接入健康检查
- **005（下一轮）**：个人资料（游戏 ID、段位、联系方式）、个人中心页面、功能权限、`init_site` 初始化全部用户组和角色

设计依据：`docs/design.md` **v1.5.3**，重点读 3.1–3.4、3.6、10.1、10.2、12.3.1、12.4.1、13.13.3、16.6 节。

## 本轮范围

**做**：下面 T1–T4。
**不做**：个人资料页面、游戏 ID / 段位 / 联系方式的模型和页面、功能权限、投稿者组同步、战队、赛事、内战、开放 API、AI 审核、预渲染。

## 允许新增的依赖

本轮可以加 **django-allauth** 和 **cryptography**（设计 2.2 节已列出）。除此之外仍然不新增依赖，确有需要就在报告里说明理由并停下等确认。

## 任务

### T1 账号（设计 3.1–3.4）

1. 接入 django-allauth：邮箱登录、**强制邮箱验证**、6 位验证码注册、验证码找回密码、修改邮箱（新邮箱验证通过后才替换）
   - 具体设置项按 allauth **当前版本的官方文档**来，**把用到的设置项和 allauth 版本号列进报告**，不要照搬旧版本写法
2. 注册表单字段和校验按 3.1 节的表格：邮箱、密码（至少 8 位 + Django 校验器）、确认密码、昵称（2–16 字符）、是否来自 SJTU（必选）、同意用户协议（必勾）、**单独**同意个人信息存储在境外（必勾，和上一项分开两个勾选框）
   - 两个同意分别写入 `agreed_terms_at` 和 `agreed_cross_border_at`
3. 注册后按 `is_sjtu` 自动加入「交大用户」或「校外用户」组；以后修改 `is_sjtu` 时自动换组。本轮 `init_site` 只需要建这两个组，其余角色组下一轮
4. 会话 14 天；登录时设置提示 Cookie `ow_logged_in=1`（不含任何身份信息，有效期与会话一致），登出时删除（设计 13.13.3）
5. `WAGTAILADMIN_LOGIN_URL` 指向 allauth 的登录页
6. allauth 的所有页面覆盖成站点布局（`templates/account/`），中文文案，手机尺寸可用，不引入内联 style
7. 限流：注册、登录、验证码发送、找回密码都要有；**把实际生效的限流值写进报告**

### T2 全站设置与 SMTP（设计 3.6、12.4.1）

1. `SiteSettings`（Wagtail 全站设置）：**一次性建好 12.4.1 节列出的全部字段**，避免以后反复迁移。本轮只使用 SMTP 相关字段和邮件主题前缀，其余字段在后台可见，帮助文本注明「后续里程碑使用」
2. SMTP 密码用 Fernet 加密存储（`FIELD_ENCRYPTION_KEY`），后台表单不回显原值，留空表示不修改
3. 后台「发送测试邮件」按钮：发给当前管理员自己，直接显示成功或失败原因
4. 发信使用后台配置，不读环境变量；没配置 SMTP 时给出明确提示而不是静默失败

### T3 异步邮件与 worker（设计 10.1、16.6）

1. 自定义**异步邮件后端**：代码里调用 Django 标准发信函数时先入队，由 worker 按后台 SMTP 配置发送。allauth 和 Wagtail 的邮件要自动走这条路，不用逐个改造
2. 发送失败重试 3 次，间隔 1 分钟、5 分钟、30 分钟
3. 业务通知一律在 `transaction.on_commit` 之后入队
4. 每封邮件同时有纯文本和 HTML 两个版本，主题统一加前缀
5. **worker 心跳**：worker 每 30 秒往缓存写一次心跳；`/healthz` 接入心跳（超过 2 分钟没更新 → 503）和任务积压（有任务等待超过 10 分钟 → 503）
   - 心跳怎么实现由你决定（周期任务自己重排、或 worker 进程内的后台线程），在报告里说明选择和理由
   - **003 的「数据库忙不算故障」逻辑不能回退**
6. 开发环境继续把邮件打到控制台；生产的 `DiscardLogEmailBackend` 被真实实现取代后可以删掉

### T4 文档

README 增加：怎么在后台配置 SMTP、怎么在本地跑通完整注册流程、worker 必须运行（否则验证码发不出去）。

## 测试要求

至少覆盖：

- 注册校验：两个勾选框都必勾、昵称长度边界、密码强度、邮箱大小写不敏感唯一
- 验证码流程：未验证邮箱不能登录；验证后可以登录
- 自动归组：`is_sjtu` 为真进「交大用户」组，修改后换组
- 提示 Cookie：登录后存在、登出后消失
- 异步邮件：调用发信函数后任务入队而不是直接发送；worker 执行后按 SMTP 配置发送；失败会重试
- 健康检查：心跳过期 → 503；任务积压 → 503；数据库忙 → 仍然 200
- SMTP 密码加密往返：存进去是密文，读出来是原文

## 验收标准

逐条实际执行，真实输出贴进 `report.md`：

1. `ruff check` / `ruff format --check` / `pytest` / `makemigrations --check` / 生产配置下 `check --deploy`
2. 本地用控制台邮件后端跑通全流程：注册 → 拿到验证码 → 验证 → 登录 → 退出 → 找回密码 → 改邮箱（贴关键输出）
3. 停掉 worker 后 `/healthz` 返回 503 且 detail 指明心跳过期；重启 worker 后恢复 200
4. 写锁被占用时 `/healthz` 仍然返回 200（003 的行为不能回退）
5. 浏览器打开注册、登录、找回密码页面：控制台 0 条报错，手机尺寸下可用（贴截图或说明）
6. `ow_logged_in` Cookie：登录后存在、登出后消失
7. SMTP 密码在数据库里是密文（贴一行查询结果，密文本身可以截断）
8. `docker build` 成功、`caddy validate` 通过
9. git 提交，信息以 `004:` 开头
