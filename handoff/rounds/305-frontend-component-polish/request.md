# 305 前后台组件、外观与动效打磨

## 背景

用户 2026-11-09：「开始优化前端（包含后台）。每一个组件，每一个细节都仔细打磨，包含外表和动画」。开工工作区干净，`git pull --rebase` 后基线为 `5fa90766`。本轮覆盖前台、后台及共享组件，沿用 AGENTS 的连续修复授权。

## 范围

先逐文件建立组件清单和共享样式归属，再完善控件、导航、浮层、卡片、表格、反馈、编辑器与编队组件的外观和操作状态。保留现有中性底色、交大红和低饱和橙，不恢复装饰图、介绍性小字或额外数字装饰。新动效服务于悬停、按下、展开、确认和状态变化；不让整页弹入，不改变业务、权限、保存和发信规则。

设计先写 `design-next.md` 及前后台细节。颜色、时间、缓动和尺寸集中在既有样式包，不新增运行依赖，不修改冻结旧站或生成接口，不部署生产。

## 任务

1. 组件清单逐项映射到共享样式和真实场景，避免只改几个首页控件；别名和无可视外观的组合组件单列说明。
2. 打磨默认、悬停、按下、焦点、选中、错误、只读、禁用和处理中状态；核对浅深色、375/768/1280宽度、键盘和触屏。
3. 统一交互动效并尊重减少动态效果，保持可用性和时序。初读已发现全局减少动态效果规则会清零无脚本提示的8秒延时，以及勾选控件的焦点样式不够明确；先在实际浏览器复现再修正。
4. 专查后台筛选、表格、选图、弹窗、编辑器工具栏和拖拽面板的布局及溢出。已有的必要不可用状态继续保留。
5. 以生产构建建立可重跑的组件/交互检查，留存改前、改后和动效中间状态截图，报告只写实际覆盖和结果，不将源码盘点称作逐组件真实操作验收。

## 验收

所有构建、检查和浏览器都在机器管理仓库指定的编译 VPS 后台执行，日志落文件。先留基线，再检查实际组件状态、键盘焦点、触屏点击范围、动态效果与减少动态效果、CSP、激活、布局和对比度，最后整组及相关浏览器操作全绿。一个中文提交、双推并检查精确 SHA 的自动 CI。未运行的范围写「未验证」，不恢复旧批取消的迁移矩阵。
