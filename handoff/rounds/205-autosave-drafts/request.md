# 205 自动保存（中）：文章和网站页面存草稿

## 起因

用户 10-05：「……其他的更改也一样，全站的后台都是，都给我改成自动保存，无需手动保存」。问过：有草稿的内容「存成草稿，点发布才上线」；新建的东西「必填项没填好也要自动保存！」。202 做了机制、个人中心和后台的设置类页面，203、204 插进了用户新提的两件事；设计 13.17 里写给「203」的那一半拆成两轮：**205 是有草稿的内容**，206 是赛事、内战、分队、队长的战队管理和定时任务。用户 10-05：「继续做 205」。

现在文章、网站页面（关于我们、两份协议）还是「保存草稿」「发布」两个按钮；首页置顶和资讯栏目介绍点「保存」就直接上线。

## 要做的（设计 13.17，v7.9）

1. **文章**（写文章、改文章）：改了就自动存成草稿，「保存草稿」按钮去掉，「发布」照旧是按钮，发布时才查必填（标题、分类）
   - 新写的文章第一次改动就建好（草稿），页面地址换成编辑页接着写；标题、分类空着也存。分类在数据库里允许空（迁移），发布照旧必须选
   - 列表和后台首页「我的文章」里标题空着的写「（无标题）」
   - 网址片段：还没发布过、网址还是自动生成的，跟着标题变（原来第一次保存时定下，自动保存以后打第一个字就定死了）；编辑在网址框里自己改过的不跟
   - 同一个人接着改：覆盖自己的上一份草稿修订（30 分钟内），不刷出几十份修订；操作记录 30 分钟内合成一条
2. **网站页面**（关于我们、用户协议、隐私政策）：同上，改了存草稿，「发布」才上线
3. **首页置顶、资讯栏目介绍**：改了存成首页、栏目的草稿，「发布」才上线（原来保存就上线）；页面写有没有没发布的改动
4. Markdown 编辑器：每敲一个字发一次「change」，自动保存会一个字存一次；改成打字只发「input」，离开编辑器时才发「change」
5. 不改：发布、撤下、删除、通知全体成员照旧是按钮；草稿不触发 AI 巡查和静态页（只在发布时）

## 验收

- 改了就存成草稿，前台看不到，发布后才看到；新文章空着标题分类也建得起来，发布时拦下
- 同一个人连续改只有一份草稿修订；别人接着改另起一份
- 还没发布的文章网址跟着标题走，自己改过的不跟
- 首页置顶、栏目介绍改了不上线，点发布才上线
- 规则拆掉就红；整组检查、三个浏览器走查通过（走查里写文章那一步按自动保存走）
