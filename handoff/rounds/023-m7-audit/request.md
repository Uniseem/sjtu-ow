# 023 第 15 章逐条核查

M7 的验收标准是「**第 15 章的目标全部达到**」。这轮把 15.1–15.5 的每一条拿出来对照现在的代码，能测的写成测试**永久守住**，不能测的说明理由。

这不是再做一遍功能，是**审计**：前面 22 轮各自验证过自己那部分，但没有人把整章拉通看过一遍，也没有东西防止以后改坏。

## 范围

设计 15.1（性能）、15.2（安全）、15.3（隐私）、15.5（日志保留期）。15.4 的恢复演练 022 做过一次；15.6 是交接文档，不是代码。

## 任务

### T1 N+1 查询

15.1 明确要求「列表页注意避免 N+1 查询……开发时开启查询计数检查」。**现在一条这样的检查都没有。**

给每个公开列表页和后台列表页写查询计数测试：资讯列表、赛事列表、战队列表、组队大厅、内战列表、内战详情、后台报名审核、后台分队页。做法是**先造 3 条数据量一次、再造 10 条量一次，断言查询数不随数据量增长**。

### T2 首页体积

15.1：首页 HTML + CSS + JS 压缩后合计不超过 300KB（不含图片和字体）。量一遍，写成测试。

### T3 安全响应头与 Cookie

逐条核对 15.2 的「传输」「内容安全策略」两行：HSTS、Cookie 的 `Secure`/`HttpOnly`/`SameSite`、前台 CSP 禁止内联脚本和 `eval`、`frame-src` 只允许 B 站。用**生产配置**核对，不是开发配置。

### T4 业务限流

15.2 列了具体数字：发车每人每小时 10 次、申请入队每人每天 20 次、创建战队每人每天 3 次、状态片段每 IP 每分钟 120 次。**逐条核对实际配置对不对得上**，对不上就是 bug。

### T5 上传限制

只允许 JPG、PNG、WebP，**不允许 SVG**，有大小限制。核对配置并测试。

### T6 预渲染页面不含个人信息

15.2：预渲染页面「不包含任何个人信息和 CSRF token」。真生成几个页面，搜里面有没有 CSRF token、昵称、邮箱。

### T7 联系方式的可见范围

15.3：联系方式只有赛事管理员和内战管理员能看，**不通过 API 提供给上游**。018 验过 API 那一半，这轮把前台和后台的另一半也验了。

### T8 AI 审核送出去的内容

15.3：送给 DeepSeek 的只有公开内容，**不含邮箱、联系方式、游戏 ID 和用户 ID**。核对实际构造的请求体。

### T9 日志保留期

15.5 的表和 022 的 `cleanup_old_data` 对一遍：API 日志 90 天、Webhook 180 天、任务 30 天、AI 审核记录「已处理 180 天、未处理一直留着」。**最后这条 022 没做**，核对一下。

## 测试要求

以上每条能测的都要有测试。N+1 的测试要用「数据量翻倍、查询数不变」的写法，不要写死一个数字——写死的数字会因为无关改动天天红。

## 验收标准

1. `ruff` / `pytest` / `makemigrations --check` / 生产 `check --deploy` 全部干净
2. **贴出 15.1–15.5 的逐条核查表**，每条写明：符合 / 不符合 / 不适用，不符合的说明怎么处理的
3. 贴出首页体积的实测数字
4. 贴出 N+1 测试在数据量 3 条和 10 条时的查询数
5. 贴出生产配置下的安全响应头
6. 回归 + `docker build` + `caddy validate`
7. 清理验证数据，**并查一次全库计数确认干净**
8. git 提交，信息以 `023:` 开头
