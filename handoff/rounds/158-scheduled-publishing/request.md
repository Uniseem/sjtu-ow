# 158 定时发布真正生效

## 背景

继续自主推进。以内容编辑的身份：想让一篇赛事公告周五晚上 8 点自动上线，在编辑页右侧「状态」面板点「设置计划」，填「上线日期/时间」，点发布，Wagtail 显示「已计划」。但到点后它不会上线：Wagtail 的定时发布要有人定期跑 `publish_scheduled`，本站的定时任务表（设计 16.5、`deploy/crontab.example`）和 worker 都没有跑。「过期日期/时间」同样不生效，过期的公告一直挂着。

设计 12.5 写了「定时发布是 Wagtail 自带的」，154 的后台手册也告诉认证作者可以用，而且位置写错了（写成在「推荐」里，实际在「状态」面板的「设置计划」）。

## 本轮范围

1. `content.services.publish_due_pages()`：有到了上线时间的版本、或过了下线时间还在线的页面时，执行 Wagtail 的 `publish_scheduled`；没有就只是两条查询，什么也不做
2. worker 每 30 秒（和心跳同一个循环）调用一次；出错只记日志，不影响心跳。理由：16.5 说应用内的定时事项走任务队列、不依赖 cron；定时发布能从好几个入口设（编辑页、审核通过、批量操作），给每个入口挂延时任务容易漏，轮询一处都不漏
3. 上线、下线走 Wagtail 自己的发布和取消发布，已有的信号会重新生成静态页、列表页和首页（13.13.4）
4. 后台手册：内容编辑加一步「定时上线和下线」；认证作者那一步改对位置
5. 设计 12.5、16.5（v6.50）；README

## 验证

测试（把时间往后拨，不真等）：计划上线的文章到点后上线、首页和列表页排进重新生成；过期的文章到点后下线、静态页排进删除；没有到点的事时不执行命令；worker 循环调用它，它出错时心跳照写。变异逐条改坏。演示站上建一篇计划在一两分钟后上线的草稿，看它自己上线，再删掉。

## 验收标准

测试机上整组检查全绿；变异全部被抓到；推送 `main`，CI 绿；演示站升级并实测。
