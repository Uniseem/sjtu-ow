# 097 成员个人主页（基础版）

## 背景

用户 2026-10-03（在看试验分支时）：

> 之后就是，要求成员可以点击进去，每个人都有一个个人主页，你先做好点进去的基础页面，具体的设计我们后面再讨论

细节文档 4.6 原来写的是「以后」：要定隐私范围、要多一类预渲染页面。用户现在要做，但设计后面再讨论，所以这一轮只做**能点进去、内容可靠的基础页**，样式用现有组件，不做新的视觉设计。

做在 `main` 上（功能，不属于 `claude/flat-muted-ui` 的视觉试验），做完把 `main` 合进试验分支，用户本地看到的是试验风格加个人主页。

## 本轮范围

**做**（设计 6.4、细节 4.6，先写文档）：

1. 地址 `/members/<编号>/`：只有成员展示页上的人（未停用、验证过邮箱）有；其他人和不存在的编号都是 404
2. 页面内容只放隐私总则（细节 1.8）里本来就公开的：头像（底图首字）、昵称、个人宣言、常用位置和段位（本人关了就不显示）、所在分组和职务、现役战队、退役记录（哪支队、起止年月）、发表的文章。**不放**游戏 ID、联系方式、邮箱、是否交大、注册时间、参赛和内战记录（赛事名单本来不公开，8.2）
3. 能点进去的地方：成员展示页的名片和小卡、战队主页的现役成员卡和退役列表、文章的作者卡、站内搜索的成员结果
4. 先不进半静态渲染（实时渲染），加 `noindex`，不进 sitemap：设计定了再说要不要被搜索引擎收录、要不要预渲染
5. README、细节文档 1.6（名片可点）、4.6

**不做**：页面的视觉设计（后面讨论）、本人编辑主页（资料还在个人中心改）、关注 / 留言、参赛记录。

## 验证

测试：成员能打开、不是成员 404；页面有昵称、宣言、位置、分组职务、战队、退役记录、文章；没有游戏 ID、邮箱、联系方式；关了段位就没有段位；`noindex`；各处链接；查询次数有上限。变异逐条改坏。截图。

## 验收标准

`AGENTS.md`「常用命令」那组全绿；变异全部被抓到；推送 `main`，CI 绿；再合进试验分支。
