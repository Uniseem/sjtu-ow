# 079 复核结果（自查）

## 结论

**通过（自查）**，待独立复核。

## 验证记录

1. 整组检查全绿；变异 12/12，第一条单独确认了新的对比度测试自己会红（不是靠已有的令牌一致测试）
2. **对比度公式对不对**：测试里先用两个公认的值校准——黑白 21:1、`#767676` 对白 4.54:1（WCAG 常用的「刚好及格的灰」）。公式和 WCAG 2.1 的相对亮度定义一致（0.04045 分界）
3. **组合表是不是真的覆盖了用到的地方**：`text-fg-3` 在模板里出现 21 处，样式表里用 `--tone-fg-3` 做文字色的 18 处（另有 3 处是图形的底色或边框），底色只可能是 `canvas`、`surface`、`sunken`、`red-tint`（浅色区域）或 `night`、`night-2`（`.on-night` 里，语调变量会翻转），这六种都在表里
4. **写死的色值**：`@theme` 以外原来有 8 处，现在 0 处，测试拦着
5. **截图**：控件边框、搜索框、第三级文字按预期变深，其他没变

## 发现的问题

- 样张页的色块列表是把色值又写了一遍，`ink-3` 改了它不会跟着变。加了测试让它和令牌一一对上（`white`、`black` 不展示）
- 页头的搜索框原来用的是发丝线，在深色页头上几乎看不出是个输入框。改成 `night-control` 以后能看出来了，这是本轮最明显的视觉变化

## 判断里最没把握的

1. **`night-2` 上的 `night-control` 只有 3.27:1**，刚过线。抽屉里的搜索框底色就是 `night-2`。再暗一点就不达标，以后调深色令牌时要注意
2. 装饰性的线（`line`、`line-strong`，标签、名额格、票根虚线）没有要求 3:1。标签的外框不是「认出这是可以点的东西」唯一的线索（文字本身就在），名额格有数字，所以按 WCAG 1.4.11 不需要；但如果以后有人拿 `line-strong` 画控件，测试拦不住，只能靠设计表里「装饰性」那句话
3. 「已结束」的实心方块这类图形也用 `ink-3`，图形只要 3:1，新值 4.8，没单独列进表
