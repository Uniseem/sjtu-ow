# 179 守卫普查：059 之后加的守卫也逐个拆一遍

## 背景

继续自主推进。复核指南「优先级 2」：042 写了 `mutate_guards.py`，机械地找出所有「条件成立就拒绝」的守卫（`if` 里直接抛异常、往 `problems` 里加一条、或者返回登录跳转 / 403 / 4xx），一个一个把条件换成 `False` 跑测试；059 跑完当时的 218 个，补了 84 条测试。

之后又过了一百多轮。127 起每轮都给自己新加的规则跑变异，但 060–126 之间加的守卫、以及后来顺手改动的老守卫，没有再统一扫过。现在用同一个办法列出来是 254 个（042 那份应用清单里没有 071、072 之后加的 `comments`、`search`，这次补上）。

## 本轮范围

1. 把 `mutate_guards.py` 复制到本轮目录（042 的文件不改），应用清单加上 `comments`、`search`
2. 在测试机上单独开一个工作树后台跑（不占 `remote-check.sh` 的锁），3 个并行
3. 没被抓到的守卫逐个看：真没测到的补测试（用「能进后台但不该有这个权限」的人测，不只用超级管理员）；改了也测不出来的（等价变异、多重保护的第二道）写明理由
4. 补的测试再跑一遍对应守卫，确认会红
