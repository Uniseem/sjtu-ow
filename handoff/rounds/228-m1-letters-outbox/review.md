- **主题**：`[SJTU-OW]` 加一次；已经带前缀的不加第二次。`<title>` 仍是不带前缀的主题。
- **地址**：中文百分号还原成字，`%2F` 留着。
- **发送**：名单外的跳过；没配主机报「后台尚未配置 SMTP」；假 SMTP 能走完一封；连上不说话的端口在超时内放弃。拆掉名单（变异 D）后去连 `127.0.0.1:1`。
- **待发信**：同一批同一封合并收件人，`.invalid` 不进名单。确认只认领一次，第二次什么都不发。7 天前的行普通确认看不到，操作人注销后由系统代发。拆掉合并（变异 B）后变成两行。拆掉条件更新（变异 C）后第二次又发出去。

## 发现的问题（都已当场修掉）

- `message.go` 和 `render.go` 用了 `time.Time` 却没导入 `time`，第一趟编译失败。
- 测试找 `Content-ID`，标准库写出的是 `Content-Id`。两种都认。
- 确认先按 `state = 'waiting'` 把已决定的行滤掉，再做条件更新。只拆条件更新，测试仍然是绿的。查询改为把这批都读出来，认领只留条件更新这一处。
- `PrefixSubject` 里有一行 `subject = subject`（从 Python 的 `subject or ""` 误搬的），`go vet` 报自赋值。删了。
- 合并收件人用循环，扫到第一行就退出。`staticcheck` 报这个循环没有意义。改成只查一行。

## 判断里最没把握的

- **HTML 只对结构，不对全文。** `html/template` 的空白和 Django 模板对不齐，34 封信的对拍留到 M7。这轮能保证的是页头、两张图、验证码、祝好、没有脚本。
- **没配 SMTP 算失败，名单外算成功。** 前者进邮件车道的 1/5/30 分钟重试，后者记跳过。和现行站一致：没配是配置错了，名单是故意不发。
- **日期在真正发出去的时候才写。** 冻住的是信的 JSON，不是已经排好的 HTML。同一封在确认页上等几天，日期是发出那天。
