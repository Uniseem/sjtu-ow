# 228 M1 第七轮：信纸、发信、待发信

## 背景

227 把任务队列立起来了。M1 还缺信本身（12 号文档 5.11）：每一封都是同一张信纸，主题前缀只加一次，头图随信走；登录的人做完事，信先冻住等他点头，没人在场（worker、命令）就直接进邮件车道。34 种信的正文是各领域的事，这轮只做信纸、发送和待发信。

## 本轮范围

### 做

1. **信纸**（`internal/platform/mail`）：结构和现行站 `core/letters.py` 一样。纯文本先称呼、再结论、事实、验证码、条目、段落、按钮、祝好、落款、日期，最后用「——」写明为什么收到。HTML 照 `templates/email/layout.html` 和 `letter.html`：交大红页头、`cid:ow-mark`、`cid:ow-horizon`、白卡片、页脚。两张 PNG 嵌进二进制，发出去时挂在信里。主题前缀默认 `[SJTU-OW]`，已经有前缀的不加第二次。按钮下的地址把中文百分号还原成字。
2. **发送**：SMTP 连接和读写 20 秒超时。没配主机就报「后台尚未配置 SMTP」。`EMAIL_ALLOWLIST` 非空时，不在名单里的地址直接跳过。一封信一个收件人进 `mail` 车道，失败沿用队列的 1/5/30 分钟重试。
3. **待发信**（`held_letters`）：`app.Ctx.Letters` 有批次就冻住，同一批、同一封信合并收件人；没有批次就入队。确认时按编号条件更新，第二次点不再发。7 天内才算还在等；30 天前的行由 04:00 的清理删掉。注销邮箱（`.invalid`）不发。

### 不做

- 34 种信的构造函数和样张页（各领域、M7）。
- 确认页的界面（M8）。全站设置里的 SMTP 表还没有，发送函数收下配置，不自己去读表。
- `/healthz`、apigen、`serve` / `worker` 命令。

## 验收标准

`cd server && gofmt -l .` 为空，`go vet`、`staticcheck`、`govulncheck`、`go test ./...` 全绿；测试机整组全绿。不加依赖。
