# 284 账号真实旅程

## 背景

用户要求规划后自主推进、不再询问常规决策。283 已完成评论真实 Go/Caddy 旅程，F3 账号组目前仍主要依赖桩浏览器证据。本轮接着补账号真实旅程，按现行设计与迁移文档 6.1、9.3 验收。

## 本轮范围

- 临时数据库、真实 Go 服务及 worker、生产 SSR、真实 Caddy、Chromium；本地 SMTP 收件器接收测试邮件，验证码只从实际 SMTP 邮件读取。
- 注册、邮箱验证、登录/退出、改密码、三步找回密码、重新认证及更换邮箱；核对真实持久化、会话失效、错误提示与跳转。
- 发现挡住上述流程的问题时修复对应前后端，并增加针对性回归及必要变异。用户自主推进授权作为本轮 `web/`、账号后端与验收脚本跨范围例外，长期 OWNERSHIP 不变。
- 实际 SMTP 暴露 Go 发信编码的顶层 MIME 头落进正文；本轮修 `server/internal/platform/mail/` 并用收件端标准解析器核对纯文本、HTML、内嵌图片。该修复属于账号真实收信流程的必要范围。
- 不改旧站、不引入依赖、不向外部邮箱发信、不部署正式站；个人中心完整旅程、全部账号视觉对拍及其他 F5–F10 页面留后续轮次，不把本轮局部通过记成 F3 全量完成。

## 验收标准

1. 新账号真实浏览器注册、收到 worker 经 SMTP 发出的六位码、验证即登录，持久化验证状态和正确用户会话。
2. 登录错误不丢输入；退出 GET 不退出、POST 退出；改密码保留当前会话并作废其他会话，旧密码失效。
3. 重置码核验后才进入新密码页；重置凭证不进入 URL/JS 存储；重置成功不自动登录，原会话失效；新密码可登录。
4. 改邮箱先重新认证并保留邮箱草稿，未验证时旧邮箱仍有效；新邮箱码验证后替换，取消修改可用。
5. 浏览器无未捕获异常、CSP 违规和服务器 500；每一步记录真实日志与退出码。所有编译/检查在测试机后台运行，提交前整组及浏览器检查通过，检查最终提交 CI。
