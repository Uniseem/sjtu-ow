# 056 首页的赛事与内战、战队参赛记录

## 背景

055 复核提出「搜一遍还有没有别的『以后再做』的占位」。搜出来三处用户能直接看到的：

- **首页**「正在报名的赛事」「近期内战」两块永远显示「即将开放——将在后续里程碑接入」。`HomePage.get_context` 里写着 `context["open_tournaments"] = None`、`context["upcoming_scrims"] = None`，注释是「M4 / M6 data hooks: leave keys in context so templates stay put」。M4、M6 做完时**没人回来接上**。测试机首页现在就是这样
- **战队主页**「参赛记录」同样是「即将开放」。设计 7.2 要求显示「报名状态为『已通过』的赛事列表」
- 后台全站设置里几项参数标着「后续里程碑使用」（放 057）

顺着查了设计 13.13.4 的「触发重新生成的事件」表，14 行里 **8 行没做全**。本轮做和首页、参赛记录直接相关的：

| 事件（设计 13.13.4） | 现状 |
|---|---|
| 赛事创建、修改、发布、取消、结束 → 首页 | 只刷新详情和列表 |
| 赛事或内战改回草稿 → 首页 | 同上 |
| 内战创建、修改、发布、取消 → 首页 | 同上 |
| 报名变为「已通过」或从「已通过」变走 → 赛事详情、战队主页 | **什么都不刷新** |
| 报名开始、截止、活动开始等时间点 → 详情、列表、首页 | 赛事只排了详情和列表；内战什么都没排 |

## 任务

1. 首页：
   - 「正在报名的赛事」：当前在报名期内的已发布赛事，截止早的在前（设计 5.1）
   - 「近期内战」：未来 7 天内开始的已发布内战，早的在前（设计 5.1、附录 C「首页近期内战范围 未来 7 天」）
   - 空的时候写实话（没有正在报名的赛事 / 未来 7 天没有内战），不再说「后续里程碑」
2. 战队主页「参赛记录」：这支队报名状态为「已通过」的赛事；草稿赛事不显示
3. 上表的触发全部补上。**写 request 之后又发现**：后台内战的「发布」「标记结束」「取消」三个按钮调用的服务函数都不刷新页面，只有编辑表单保存才刷新（赛事那边三个按钮都刷新）。同属「内战创建、修改、发布、取消」那一行，一并修。时间点：赛事报名开始和截止时刷新首页；内战进入 7 天范围时和开始时刷新首页
4. 测试：内容对（该出现的出现、不该出现的不出现）；每个触发都有测试；逐项变异确认

## 不做（057）

报名、改昵称、文章关联赛事、游戏模式这几行触发；后台设置的过时标签。

## 验收标准

本地四项检查干净；推送后 CI 绿；测试机上首页和战队页显示正确。
