# 协作流程

这个目录记录项目**怎么一轮一轮做出来的**：每轮要做什么、实际做了什么、复核发现了什么。仓库的入口说明在根目录 `AGENTS.md`，本文件只讲轮次怎么做。

## 两种做法

| 做法 | 用在 | 分工 |
|---|---|---|
| **分工** | 001–007 | 一方（Claude）维护设计、写 `request.md`、复核写 `review.md`；另一方（Grok）实现、写 `report.md`。用户在两边说「继续」 |
| **连做** | 008 起到现在 | 同一个助手写 `request.md` → 实现 → `report.md` → **自查**写 `review.md`。用户外出或让助手连续推进时用 |

**连做的自查不能替代独立复核。** 自查找到过很多真问题，但也判断错过（例子见 `REVIEW-GUIDE.md`）。连做的轮次在 `STATUS.md` 里标「自查通过」，不标「复核通过」，等有人按 `REVIEW-GUIDE.md` 独立复核后，把结论追加到对应轮次的 `review.md`。

## 目录结构

```
AGENTS.md                          仓库入口：先读什么、命令、硬规则、文档维护表
docs/design.md                     唯一的设计依据
handoff/README.md                  本文件：轮次怎么做
handoff/STATUS.md                  当前进度，规定下一步做什么（进度只写这里）
handoff/REVIEW-GUIDE.md            独立复核指南
handoff/rounds/<序号>-<名字>/
    request.md                     本轮要求
    report.md                      本轮实现报告
    review.md                      本轮复核结果
    其他文件                        可选：脚本、原始输出等证据
```

轮次目录按 `001`、`002`、`003` 递增，名字用英文小写加短横线，比如 `031-m7-offsite-backup`。

## 一轮的流程（连做）

1. 读 `STATUS.md` 的「下次开工的第一件事」，确定本轮做什么
2. 新建轮次目录，写 `request.md`：背景、范围（做什么、**明确不做什么**）、验收标准
3. 实现。涉及设计变化的，先改 `docs/design.md` 并在附录 D 记一行
4. 跑验收命令（`AGENTS.md`「常用命令」那组），写 `report.md`，**只放真实输出**
5. 自查：换个角度重新验证（自己重跑、把实现改坏看测试红不红、对照设计原文逐条核对），写 `review.md`
6. 更新文档（见 `AGENTS.md` 最后的表）：`STATUS.md` 每轮必更新；改了用法更新 `README.md`
7. 一个 git 提交，**提交信息用中文**，第一行以轮次号开头，比如 `046: 提交信息改用中文`；推送到 `origin` 的 `main`

分工做法下，第 2、5 步由设计复核方做，第 3、4 步由实现方做，每步做完把 `STATUS.md` 的 `next` 改成对方。

## 硬规则

1. **`docs/design.md` 是唯一设计依据。** 实现方发现设计有问题，写进 `report.md`「设计偏差」，需要用户拍板的先问
2. **报告里的验收输出必须是真实执行过的命令输出。** 没跑的写「未验证」
3. **每轮结束更新 `STATUS.md`**，一轮一个提交
4. **不新增依赖**；确实需要，在报告里说明理由并停下来等确认
5. **不在本轮范围外改动。** 顺手发现的问题写进报告「顺带发现」，由后续轮次处理
6. 不确定的地方**问，不要猜**
7. **历史轮次的文件写完不改。** 后来发现写错了，在原文位置加一段「NNN 轮更正：……」，保留原文。这样能看出当时为什么那样判断
8. **「等某个条件才能做」要先问一句：能不能拆，有没有一部分现在就能做。** 023、034、035、038 都栽在这里

## 文件格式

实际报告可以按内容调整小节，但下面这些信息不能少。

### request.md

```
# <轮次号> <标题>
## 背景        为什么做这一轮
## 本轮范围    做什么 / 明确不做什么
## 任务        逐条，每条带验证方式和期望结果
## 验收标准    要跑哪些命令、期望输出
```

### report.md

```
# <轮次号> 实现报告
## 结论        一句话：完成 / 部分完成 / 未完成
## 逐条结果    对应 request 的每条任务
## 验收输出    真实命令输出
## 设计偏差    和 docs/design.md 不一致的地方
## 未完成 / 顺带发现 / 需要确认
## 改动文件
```

### review.md

```
# <轮次号> 复核结果
## 结论        通过 / 需返工 / 部分完成
## 验证记录    实际跑了什么，结果如何
## 发现的问题  必须修 / 建议修
## 判断里最没把握的
## 文档更新    改了 design.md、README.md、STATUS.md 的哪些地方
```
