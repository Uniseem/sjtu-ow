# 前台细节规格（v5.2）

| 项目 | 内容 |
|---|---|
| 版本 | v5.2 草案，2026-10-03 |
| 和 `design.md` 的关系 | `docs/design.md` 13.2 节定体系（颜色、字号、组件），**本文件定每一页、每个部件的细节**：每一项显示什么、缺了怎么办、太长怎么办、太多怎么办、谁能看到。两份都是设计依据，13.2 节指向这里；同一件事只写在一处 |
| 来由 | 用户 2026-10-03：「现在你模块大体都没问题，但是你细节都没考虑，比如成员展示，他的常用位置，他的个人宣言，他的段位怎么放？比如一个战队，如果有现役和退役，你要怎么处理？一个人如果有多个 title，你又怎么展示？所以我希望你先把这些东西单开文档，全部自己想一遍然后记录，把每个细节都处理好。自己写文档，自己做决策」；同时要求头像改成方的、文章封面改成截图那种（图铺满页头、字压在图上居中、一排信息小块、底边弧形）。随后又说：「每个战队或者头像框的话，图片的占比应该大一些，是图片主导的。然后站点各个组件的设计，能不能往我们的 svg 图片的那种设计方向上靠一点」（见 1.9、2.2、4.2、5.1、5.3） |

每一条写成「**决定**」加理由。标「以后」的是想过、这一版不做的，理由写在后面。

## 1. 总则

### 1.1 宽屏怎么用（v5.2）

- 页面铺满窗口，最宽 1920px，左右留白手机 16px、平板 24px、桌面 40px
- **卡片网格**按宽度自动排：图片卡每张至少 22rem，名片至少 12rem，战队卡至少 15rem，成员小卡至少 16rem；屏幕越宽每行越多、单张越大
- **读的东西不随屏幕变宽**：正文一栏 44rem（约 40 个汉字一行）。宽屏多出来的地方用来放图、目录、作者、相关内容，不拉长行
- **看和操作的页面居中**：赛事、内战、战队的详情页，报名、建队、申请等表单，个人中心，搜索结果，内战列表（一行一行的，不是卡片），整块内容放在居中的 80rem（1280px）里，横幅背景照样铺满，横幅里的字和下面的内容对齐在同一条线上。用户 2026-10-03 看了赛事详情：「这种页面，也要居中一些啊，现在这个中间一片空白」。铺满宽度的只有卡片网格（资讯、赛事、战队、成员列表和首页）
- **不留半屏空白**：一块内容在宽屏上只占一边时，另一边放和它有关的东西（首页「近期」的大图卡和内战列表等高；成员分组左边是组名和简介、右边是名片；文章右边是目录）。找不到有关的东西，就把内容居中，不贴着左边
- **对齐**：一页只有一条主对齐线。标题区居中的页面（文章、关于），正文也居中；标题区靠左的页面（栏目页、详情页），内容也从同一条线开始

### 1.2 信息缺了怎么办

**决定：缺什么就不显示那一行，不写「未填写」「暂无」，不留空位。** 理由：卡片里一半是「暂无」，看起来比少一行更空。只有两种例外：

- 整块都没有内容时写一句话（`c-empty`），比如「这个分组暂时没有成员。」
- 数字是 0 时照写 0（「0 条评论」「0 / 10 人」），因为 0 本身是信息

同一行卡片高度不同时，网格让它们一样高（`align-items: stretch`），内容从上往下排，底部留白在卡片里面。

### 1.3 太长怎么办

| 内容 | 上限（录入时） | 卡片里 | 详情页 |
|---|---|---|---|
| 昵称 | 16 字 | 一行，超出省略号 | 完整 |
| 队名 | 16 字 | 一行，超出省略号 | 完整 |
| 个人宣言 | 30 字 | 一行，超出省略号 | 完整 |
| 职务 | 每个 10 字，见 4.3 | 标签，最多 3 个，多的写「+N」 | — |
| 战队简介 | 500 字 | 两行，超出省略号 | 完整，保留换行 |
| 文章标题 | Wagtail 默认 255 | 两行，超出省略号 | 完整，均衡换行（`text-wrap: balance`） |
| 文章摘要 | 200 字 | 列表两行；封面上最多三行 | — |

省略号都用 CSS（`text-overflow` / `line-clamp`），HTML 里是完整的字，屏幕阅读器和搜索都读得到。被省略的地方加 `title` 属性，鼠标停上去能看全。

### 1.4 太多怎么办

| 内容 | 卡片里最多 | 多出来 |
|---|---|---|
| 一个人的战队 | 2 支 | 「等 N 支战队」 |
| 一个人的职务标签 | 3 个 | 「+N」 |
| 一支战队的退役成员 | 页面上先显示 12 个 | 「显示全部 N 人」（`<details>`，不靠脚本） |
| 一支战队的参赛记录 | 全部 | — （一学期几场，不会多） |

### 1.5 颜色和底图怎么分给人和队

**决定：没有图的头像、队标用五张「底图」之一，按 ID 固定**（2.2）。五张底图各有一个主色（红、橙、蓝、绿、金），小到 24px 时看起来就是那个颜色的方块，大到整张卡片的上半部时是一幅小风景。图片加载不出来时退回对应的标签色（`primary-soft`、`accent-soft`、`info-soft`、`ok-soft`、`warn-soft`）。

- 人：`用户 ID mod 5 + 1`；队：`战队 ID mod 5 + 1`。同一个人、同一支队在全站永远是同一张
- 这些颜色**不表达任何含义**（不是段位、不是身份），只为好认，不在图例里解释

### 1.6 可点的东西

- 整张卡可点时（文章卡、战队卡）用 `c-stretch`：标题链接撑满整张卡，卡里其他链接（如作者、分类）浮在上面单独可点
- 名片（成员）**不可点**：本站没有个人主页（见 4.6），只有里面的战队名是链接
- 悬停：卡片描边加深；图片放大到 1.03；标题变 `primary-text`。手机上没有悬停，不依赖它传达信息

### 1.7 深浅色、动效、无障碍

- 所有新部件只用令牌，两种模式都看过截图才算完
- 图里的东西会动（占位图），界面本身不动；「减少动态效果」时全停
- 头像是装饰（`aria-hidden="true"`），名字一定以文字出现
- 位置图标旁边一定有文字（「坦克」），不只用图标；段位写成文字（「钻石 3」）
- 一页一个 `<h1>`；卡片标题是 `<h3>` 或普通文字，不跳级

### 1.8 隐私总则

公开页面（任何人、预渲染）只出现**本人选择公开、或本来就公开**的东西：

| 信息 | 公开页面 | 理由 |
|---|---|---|
| 昵称、个人宣言、常用位置 | 显示 | 本人填来就是给人看的 |
| 段位（大段 + 小段） | **默认显示，本人可以关**（3.3） | 用户要求展示段位；段位不能定位到人 |
| 游戏 ID（BattleTag） | **不显示** | 能直接搜到战网账号，属于账号标识 |
| 联系方式、邮箱、是否来自交大、注册时间 | 不显示 | 同 `design.md` 6.1 |
| 所在战队、分组、职务 | 显示 | 本来就公开 |
| 退役记录（在某队的起止时间） | 显示，本人或队长可以删 | 见 5.4 |

### 1.9 组件往插画靠

本站的占位图（`design.md` 13.2.5）是扁平的层叠风景：渐变的天、一处柔光、一层层的山脊和剪影、半透明的几何形。用户要组件也往这个方向靠。**决定：**

- **图主导**：代表一个人、一支队的卡片（名片、战队卡），上半部是一整块正方形的图（头像底图或队标），信息在图下面，图占卡片一半以上
- **底图**：头像、队标没有上传图时，用 1.5 的五张底图（同一套画法的小风景），首字白色压在上面（2.2）
- **战队主页的队头**是这支队的底图横幅（深色压层），大队标放在上面（5.3）
- **页脚上沿**是一道三层的山脊剪影，从页面底色里升起来、和页脚连成一体；两种模式都是深色（页脚本来就是深色条）
- **空状态**上方放一张小风景，不再是只有一句话的方框
- **不往插画靠的**：按钮、标签、表单、表格、导航。它们是工具，图案会干扰操作和阅读
- **底图和山脊不动**：一页可能有几十个头像，全都动太耗电；会动的只有大图（首屏、栏目头、封面、卡片里的文章和赛事图）

## 2. 头像与队标

### 2.1 形状

**决定：头像、队标全部改成圆角方形**（用户要求）。圆角按尺寸：

| 尺寸 | 边长 | 圆角 | 用在 |
|---|---|---|---|
| `sm` | 28px | 4px | 文章作者行、评论、账号菜单 |
| 默认 | 44px | 8px | 列表行 |
| `md` | 56px | 8px | 成员小卡、战队成员卡、作者卡 |
| `lg` | 88px | 8px | 名片、战队卡队标 |
| `xl` | 128px | 8px | 战队主页的队标 |

圆角只用已有的 4px、8px 两档（13.2.4）。上传的队标本来就是裁成正方形的（7.1），方形不会再切掉四角。

### 2.2 没有图时画什么

- **底图**（1.5、1.9）：五张静态的小风景（红色的晚霞山峦、橙色的沙丘、蓝色的夜景、绿色的松林、金色的海面），和占位图同一套画法（`hue-1.svg` … `hue-5.svg`），按 ID 取一张，铺满方块
- **首字**：名字里第一个汉字或字母（跳过开头的符号、表情、空格），字母转大写；整个名字都是符号时写「?」。白色、加粗，字号约为边长的 40%，带一层很淡的阴影，压在任何一张底图上都看得清
- **上传的队标**：放在这支队的底图上，等比缩放到方块的 84%。透明背景的队标透出底图，方形不透明的队标盖住底图

### 2.3 用户上传头像

**以后。** 现在用户没有头像字段。加上传要做裁剪、审核（图片审核比文字贵得多，5.5 只审文字）、存储清理；首字加颜色已经能区分人。等社团觉得需要再做。

## 3. 个人资料：新增三项

个人中心「基本资料」里加三项。都可以不填。

### 3.1 个人宣言

- 一句话，最多 **30 字**，单行（去掉换行和首尾空格）
- 显示在：名片（引号括起来，`fg-2`，一行省略）、战队主页的成员卡、文章末尾的作者卡
- 和昵称一样**送 AI 审核**（5.5，新的送审类型「个人宣言」）：先发后审，疑似问题进后台复核，管理员可以清空。理由：公开显示的用户文字，昵称已经这样处理
- 不允许链接（含 `http`、`www.` 的拒绝保存，提示「个人宣言里不能放链接」）。理由：防止把成员页当广告位
- 清空：本人随时可以清空

### 3.2 常用位置

- 三个位置（坦克、输出、支援）里选：**主位置**（单选，可不选）+ **也能打**（多选）
- 存成一个有序列表：主位置在前，其余按坦克、输出、支援的固定顺序。三个都选时显示「全能」标签
- 显示：位置图标 + 文字；主位置用实心底（`surface-2` 底、`fg` 字），其余描边
- **不从内战报名记录里推算**。理由：报名位置受当场缺人影响，不代表本人偏好；本人填的才准

### 3.3 段位怎么显示

数据现状：一个人最多 5 个游戏 ID，每个 ID 三个位置各有段位（3.5.2）。

**决定：**

1. **取每个位置在所有游戏 ID 里最高的段位**。理由：小号段位低，展示最高的是大家的习惯
2. **显示哪些位置**：填了常用位置就只显示这些位置的段位，主位置在前；没填常用位置就显示有段位的全部位置（最多三个）
3. **主段位**：名片上最显眼的一个，取主位置的段位；没有主位置取最高的那个
4. 写法：`位置图标 大段 小段`（「支援 钻石 3」）；前 500 写「前 500」；未定级不显示
5. **公开开关**：「在成员展示和战队主页公开我的段位」，默认打开；关掉后公开页面不出现段位（位置、宣言照常）。队长在战队管理页、赛事和内战管理员照常看得到（原有规则）
6. **过时的段位**：段位超过 180 天没更新，名片上灰一点（`fg-3`），`title` 写「段位更新于 2026.03.01」。理由：赛季会重置，旧段位不准，但删掉又可惜

`design.md` 6.1「不显示段位」、7.2「段位不在战队主页显示」随这一条改掉。隐私政策正文（`/privacy/`）补一句：段位默认公开，可以在个人中心关闭。

## 4. 成员展示页（`/members/`）

### 4.1 版式

- 栏目头（背后是成员页的场景图）→ 分组目录（锚点）→ 每个分组一块 → 「全部成员」
- 每块在宽屏上**左右两栏**：左 15rem 是组名、简介、人数，往下滚时停在顶上；右边是卡片网格。手机上上下排

### 4.2 名片（分组里的人）

**图主导**（1.9）：上半部是正方形的头像图（这个人的底图 + 大首字），占卡片一半以上。下面依次：

1. 昵称（一行）
2. 职务标签（这个分组里的，见 4.3）
3. 个人宣言（引号、一行）
4. 位置 + 主段位：主位置实心标签，其余描边（三个都选写「全能」），后面跟主段位
5. 战队：最多两支，链接；多了「等 N 支战队」

任一项没有就不显示那一行（1.2）。卡片不可点。卡片至少 12rem 宽，手机一行两张。

### 4.3 一个人有多个职务

两种情况：

- **在多个分组里**，每个组一个职务（数据库就是这样存的：一人一组一条）：**每个分组只显示这个组里的职务**。理由：分组本身就是上下文，「赛事组」里写「社长」反而乱。一个人在三个组里就出现三张名片，这是对的——每个组的成员表都应该完整
- **在同一个组里身兼几职**：职务一栏用顿号分开写（「社长、主播」），页面上拆成几个标签。后台说明文字写清楚「多个职务用顿号分开，每个最多 10 字」。理由：改成一组可以有多条记录会动唯一约束和排序，收益不大

「全部成员」里的小卡显示这个人**所有分组里的职务**（按分组排序，最多 3 个 + 「+N」）；在某个分组里但没有职务时，显示分组名。

### 4.4 全部成员

- 按加入时间编号（`001` 起，原规则）
- 小卡：头像 `md`、昵称、主位置图标 + 主段位、职务或分组标签、右上角编号
- 不放宣言（地方小，名片里有）
- 每行至少 16rem 一张

### 4.5 排序

- 分组：后台的排序
- 组内：后台的组内排序，再按昵称（原规则）
- 全部成员：加入时间

### 4.6 个人主页

**以后。** 点名片进个人主页（参赛记录、所在战队历史、文章）是自然的下一步，但要定隐私范围、要多一类预渲染页面。这一版名片上已经有主要信息。

### 4.7 筛选

**以后。** 「只看坦克」这类筛选在预渲染页上要么靠脚本、要么每种组合一个静态页。成员规模（几十到一两百人）一页看得完。

## 5. 战队

### 5.1 战队卡（列表、首页）

**图主导**（1.9）：上半部是正方形的队标图（这支队的底图；有队标就把队标放在上面，没有就是大首字，2.2）。下面依次：

1. 队名（一行）
2. 一行事实：「6 / 10 人 · 2025.09 成立」（首页没有上限，写「6 人」）
3. 简介两行（只在战队列表）
4. 状态：「招募中」加缺的位置（「招募中 · 缺 坦克、支援」）；不招募写「暂不招募」（只在战队列表）

### 5.2 招募位置（新增）

- 队长编辑战队时，在「招募中」下面勾选**缺的位置**（可以不勾，表示都要）
- 显示在战队卡和战队主页；关掉招募时不显示
- 入队申请页上，缺的位置排在前面并标「缺」

### 5.3 战队主页

自上而下：

1. **队头**：一条横幅，背后是这支队的底图（1.9，深色压层、白字）；上面是大队标 `xl`、队名、一行事实（队长、现役人数 / 上限、参赛次数、成立日期）、招募状态和缺的位置。「申请加入」在队头下面的面板里（它要按访客显示，预渲染页上是单独填充的区域）
2. **简介**（完整，保留换行）
3. **现役成员**：卡片网格。每张：头像 `md`、昵称、「队长」标签、个人宣言（一行）、位置 + 主段位、「2025.09 入队」。队长第一，其余按入队先后
4. **退役成员**（有才显示）：紧凑的一行一个：头像 `sm`、昵称、「2024.03 – 2025.06」。离队晚的在前。超过 12 人先收起
5. **参赛记录**：已通过的报名，每行赛事名（链接）和状态（原规则）
6. 已解散的战队：只写「该战队已解散」，不显示成员和退役名单（原规则）

### 5.4 现役和退役

**决定：离开战队的人记成「退役成员」，单独列出；现役就是现在的成员。**

- **什么时候记**：队员**退出**、被队长**移除**时，记一条：战队、用户、离队时的身份、入队时间、离队时间、怎么离开的（退出 / 移除；只在后台和管理页看得到，公开页面不写原因）
- **不记的**：战队**解散**时不记（整支队都没了，页面只写「已解散」）；**注销账号**时连同记录一起删（3.8 删除个人信息）
- **回来了**：退役的人重新入队，删掉那条退役记录，入队时间按新的算。理由：同一个人同时出现在现役和退役里会让人困惑；早先那一段经历不重要到要保留
- **能删**：队长可以在管理页把某条退役记录从名单上去掉（比如因为违规被移除的人）；本人可以在「我的战队」里去掉自己的记录。删了就是真删
- **人数上限只算现役**（原规则不变）
- 以前已经离队的人没有记录（以前直接删了），这一版起才有

### 5.5 管理页

- 成员表多一列「位置」；段位照旧显示（队长本来就能看）
- 新的「退役成员」表：昵称、入队、离队、方式（退出 / 移除）、「从名单去掉」按钮
- 战队资料表单加「缺的位置」

## 6. 文章

### 6.1 列表里的文章卡

- 图（16:9，占位图会动）→ 分类标签 · 日期 → 标题（两行）→ 摘要（两行）→ 作者（头像 `sm` + 昵称）· 约 N 分钟
- 置顶的在分类前加「置顶」标签（原规则）

### 6.2 文章页的封面（用户要求，参照截图）

**决定：封面铺满页头宽度，字压在图上居中，底边是向下的弧形。**

- 高度：桌面 `clamp(28rem, 64vh, 42rem)`，手机按内容撑开（至少 22rem）
- 图：文章封面，没有就用这篇的占位图（会动）。铺满，按中心裁切
- 压层：两种模式都是深色（`scrim`）：上面一层从 `black` 50% 渐到透明（页头下面那一段字也看得清），下面一层从透明渐到 `black` 75%。字用白色。理由：封面可能是任何图，和带封面的横幅一样（13.2.5）
- 图上的字，居中，从上往下：面包屑（首页 / 资讯 / 分类）→ 分类标签 → 标题（2rem → 3.5rem，均衡换行）→ 摘要（有才显示，最多三行，`white` 86%）→ 一排信息小块
- **信息小块**（半透明深底、白字、全圆角）：作者（头像 + 昵称）、发布日期、「更新于 MM.DD」（发布后改过且相差超过一天才显示）、「约 N 分钟」、「N 字」、「N 条评论」（点了跳到评论区）。浏览量**不做**（站点不做访问统计，`design.md` 19 第 13 条）
- 底边：图的下沿是一道向下的弧（左右圆角，水平半径 50%，竖直 2.5rem），下面直接是页面底色
- 手机：小块换行排；弧度变小（1.25rem）

### 6.3 字数和阅读时间

- **字数**：正文纯文本里的汉字数 + 英文单词数（一个英文单词算一个字），不算标点和空白；图片说明、引用出处也算
- **阅读时间**：`字数 ÷ 400`，向上取整，至少 1 分钟；每张图加 10 秒、每个视频加 1 分钟（不另外标）
- 在保存时不存，渲染时算（文章是预渲染的，只算一次）

### 6.4 正文排版

- 一栏 44rem，居中；字号 1.0625rem（桌面 1.125rem），行高 1.85，**两端对齐**（中文排版习惯，右边不参差）
- 二级标题：1.5rem，上方留 2.5em，左边一条 4px 的橙色竖条；三级标题 1.25rem，没有竖条
- 段落之间空一行；列表缩进 1.5em
- 图片：撑满一栏，8px 圆角；图注在下面居中，`fg-3` 小字
- 引用：左边 3px `line` 竖线、`fg-2`；出处另起一行右对齐「——出处」
- B 站视频：16:9，8px 圆角
- 链接：`primary-text`，下划线

### 6.5 目录

- 正文里有 **3 个或以上**二级 / 三级标题时生成目录
- 宽屏（1280px 起）：正文右边一栏，停在顶上，当前读到的不高亮（高亮要脚本，**不做**）；三级标题缩进
- 窄屏：封面下面一个可以展开的「目录」（`<details>`）
- 标题的锚点在渲染时加（`h-1`、`h-2` 依次编号，不用标题文字，避免中文锚点和重名）

### 6.6 文章末尾

依次：

1. **作者卡**：头像 `md`、昵称、个人宣言、「在本站发表了 N 篇文章」
2. **关联赛事**（有才显示，原规则）
3. **上一篇 / 下一篇**：同一个文章栏目里按发布时间的前后两篇，各一张小卡（分类、标题）；没有就不显示那一边
4. **评论**（原规则）
5. 页面最下面：同分类的更多文章（原规则，图片卡）

**分享按钮不做**：用户多在微信、QQ 里打开，浏览器自带分享；复制链接要脚本，收益小。

### 6.7 关于、用户协议、隐私政策

和文章同一套正文排版，但**没有封面**：标题区居中（三页切换的标签、标题、最后更新日期），正文一栏居中，两端对齐。理由：这三页是条文，不需要图；居中和文章一致。
