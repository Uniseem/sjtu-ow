## D. 新栈的想法（还没进设计）

- **注册表同时生成文档**：每个接口的方法、路径、门、限流、查询预算，也生成一页给干部看的「谁能做什么」表（现在的 `docs/admin.md` 4 章手写），门改了文档自动跟着改
- **`audit_log` 一张表统一操作记录**（12 号文档第 7 节已有）：后台可以按对象查「这个战队/赛事/文章谁在什么时候改过什么」，比现在分散在 Wagtail 日志、自定义动作里好用
- **查询预算**：每个接口在注册表里声明最多几条查询，测试里包一层计数，比三份和十份数据的两次比较（现行站 `assert_no_n_plus_one`）更直接
- **幂等键的保留时间**：24 小时？现行站的自动保存去重钥匙存 24 小时（`django_cache`），新栈放 `idempotency_keys` 表，worker 定期清
- **错误页**：502/503/504 用 Caddy 直接给的 `maintenance.html`（照旧）；SSR 连不上 api 时 SSR 自己渲染一个 503 页（带 `Retry-After`）
- **`/healthz`**：新栈的四项（数据库可写、worker 心跳、任务积压、磁盘）等价搬；加两项：`ssr` 能连上 `api`、`flock` 没被占住超过 N 秒
- **Sentry 不接**：500 落日志（带请求编号）+ 后台待办显示近 24 小时的 500 次数；设计里删掉 Sentry 那行
- **Litestream**（Apache-2.0）割接后再议：持续复制到 R2，把「整站数据只在一台机器上」缩短到分钟级
- **外部探活**：UptimeRobot 之类每分钟访问 `/healthz`（用户配）
- **把 220 的实验程序当种子**：`e3-sqlite` → M1 的 `WriteTx` 双进程测试；`e4-goldmark` → M4 的黄金用例；`e1-ssr-csp` → M2 的 SSR 服务骨架；`e5-codemirror` → M8 的编辑器；`e2-webp` → `internal/platform/images` 的基准测试
- **国内访问速度**：服务器在法国，国内首字节 1.0 秒。重写不改这一点。如果割接后访客抱怨，选项是 CDN（Cloudflare 回国慢）或换国内近的机房，**和重写无关**，别混进来
- **站点图标、占位图、校徽图层、邮件页头图**这些预生成的静态文件（`core/placeholders.py`、`core/icons.py`、`core/emblem.py`、`core/email_art.py`）是 Python 画的：新栈里生产不需要它们（成品图提交在仓库里），但「改了画法就重新生成」的命令还在 Python 里。割接后 Python 代码会删，要决定：留一个 `tools/` 下的离线脚本（只在开发机跑，不进镜像），还是改成 Go。**倾向于留 Python 离线脚本**，反正不上生产

## E. 流程上的想法

- **轮次号**：接着 221 往下编（221 是设计草案和这份笔记）；每轮仍是 request → 实现 → report → review → STATUS，一轮一个提交，直接推 `main`。新栈的轮次目录名用 `NNN-m1-write-tx` 这样带里程碑的名字，翻起来好找
- **新栈的命令和检查**：M1 的那一轮把 `AGENTS.md`「重构进行中」一节里的占位换成真命令（`go test`、`go vet`、`staticcheck`、`govulncheck`、`pnpm …`），`scripts/check.sh` 和 `remote-check.sh` 同时认两套（Python 和 Go/Node）直到割接
- **CI**：加一个 Go 任务和一个 Web 任务，现有的 Python 任务不动；Action 按 SHA 固定、`permissions: contents: read`（14-7）
- **文档不重复写**：设计层面写 `design-next.md`，实现细节写 12 号文档，进度写 STATUS，想法和尾巴写这里。发现两处写了同一件事，删掉一处、指过去
- **每个新规则「拆掉就会红」的测试**（硬规则 7）在新栈同样适用。Go 版的变异器先做一个够用的（AST：把「条件 → 返回错误」的守卫条件换成 `false`），不追求通用
- **复核**：每个里程碑完成后，不用等检查点，可以让子代理做一次只读复核（217 的做法），但要控制并行数量，别全压在测试机上
