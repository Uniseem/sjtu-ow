1. Wagtail 整条超管侧门：04-1（双登录入口 + 不限次）、04-3/04-4/04-5（/wagtail/ 用户编辑绕过账号服务）、04-6（系统组可删）、04-7/08-10（文档库收 HTML/SVG 同域运行）。**写进需求：认证入口全站唯一，所有登录路径共用同一套邮箱验证门和限流；后台不引入第二套用户管理界面。**
2. pillow-heif/libx265 GPL（14-4）：Go 图像栈自选库即无此问题；「依赖许可证审查」保留为构建流程检查项。
3. Django 特有机制引发的：15-2（save() 钩子里联网占写锁）、07-1（Wagtail 缩略图 exif_transpose 抛错）、13-1（数据库缓存 LRU 清掉限流计数）、16-1（测试污染）、14-8（__pycache__ 进镜像）——新栈不复存在，**但对应不变量要写成设计要求**（见 B）。
4. 12-4（EasyMDE 的 CodeMirror CVE）：换编辑器消失；选型时查 CVE 写进要求。
5. 14-6（.env.example 过时）、14-9（分片旧库）、16-3（JS 子串测试）：CI/测试策略重设时一并解决。
6. 08-7（Google Fonts 请求内同步下载）：若新栈改构建期子集化则整个模块消失；保留则必须异步。
7. 01-8（legacy_body 转换错）：仅当割接不做 v6.70 以前备份的迁移才消失——**需要决定迁移范围**。

**B. 必须作为新栈设计要求写进需求的（现行站踩过的坑）**
1. **统一上传管线**（头像/队标/投稿图/字体全覆盖）：像素上限、大小上限、每日次数与磁盘总量配额（含压缩炸弹）、格式白名单、解码失败即拒、重新编码去除 EXIF/GPS、替换时删旧文件、共享文件引用计数删除。
2. **外链/富媒体解析与写路径解耦**：不在写事务和请求线程里同步联网；解析带超时、失败缓存；预览接口限流。
3. **限流体系**：计数独立于页面缓存、不得被淘汰策略清零；IPv6 按 /64 聚合；每个写接口默认有限流；慢客户端不占满服务进程（请求体上限 + 读超时）。
4. **并发编辑**：每个可编辑实体带版本/修订号，且「同人覆盖」也要检测；保存回执幂等、丢失可恢复；会话/CSRF 轮换后自动保存能自愈；编排/分队页同样带版本，离开未保存要提醒。
5. **静态化一致性**：下线与渲染的竞态——渲染前检查最新状态、下线原子删文件；私有/需登录内容绝不出静态文件；清单原子写；失败有状态与重试。
6. **备份与恢复**：临时名+原子改名；失败状态独立告警；异地上传必做；恢复不留明文临时文件；「新服务器一条命令从异地恢复」作为验收项。
7. **配置与密钥**：构建期不得注入默认密钥；缺关键配置启动即失败；CI 供应链 pin SHA、最小权限、下载校验+重试。
8. **权限模型**：子资源（评论等）沿父资源检查可见性；权限矩阵变更不得导致登录路径崩溃/递归；权限关闭时前台入口一致消失。
9. **数据完整性**：删除保护要数所有引用形态（草稿、定时修订、计划任务）；导入/导出字段与隐私政策承诺一致。
10. **运维时序**：cron 显式时区（绝不按某地夏令时换算——现行站 10-25 死线）；worker 长任务要有优先级/抢占，不阻塞验证码信；/healthz 积压口径明确。
11. **测试**：CSP 等安全头按响应断言；POST 必带 CSRF、预渲染秘密标记全覆盖、限流数字钉住；变异测试方法带进新栈。
12. **可保留的结论**：217「查过没问题」部分——无 XSS/CSRF、分队算法与暴力穷举一致、pip-audit 干净——重构时作为对照基线复验。

**C. 割接前现行站最小修复集**（217 建议修法顺序 + 时限项）：04-1、07-1（连带 07-2/07-3/02-1 统一图片管线）、03-1 → 15-2/01-2、13-1、02-2/02-4、14-2 → 丢数据组（11-1、11-2、12-1、12-2、05-1、06-2、09-1、10-1）→ 14-1、04-2、14-4（需拍板）；另加 **09-9（10-25 时区死线）**和用户侧 **R2 异地备份**（割接前整站数据只在这一台服务器上，风险最高）。
