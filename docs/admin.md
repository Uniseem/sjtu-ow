# 后台（v7.0 起自己写的后台）

用户 2026-10-05：「后台界面你为什么一直拘泥于啊这种布局呢？全部按照你的喜好推翻重写，而不是一直在框架的基础上改！」随后：「先调研然后列出已有结构和逻辑的文档，然后规划新的架构并且写入新的文档，之后根据新的文档一次性写完所有代码」。

这份文档是**后台的设计依据**（`design.md` 第 14 章指到这里），和 `design-details.md` 之于前台一样。重写前的样子记在 `docs/admin-inventory.md`，那里的「必须保留的规则」在新后台里一条不少。

## 1. 原则

1. **后台是站点的一部分，不是另一个系统**：同一套设计体系（13.2 的颜色、字体、`c-*` 组件、深浅色），同一个 `app.css`，同样的手机适配。189–193 是在 Wagtail 的界面上换皮，布局、交互、术语都还是 Wagtail 的；v7.0 起后台页面全部是本站自己的模板和视图，**不再用 Wagtail 的管理界面**
2. **Wagtail 只当内容引擎**：页面、修订、定时发布、图片和集合、全站设置模型、操作记录照用（在代码里调），用户看不到 Wagtail 的任何界面
3. **一页一件事**：列表页上方是筛选，行上是这一条能做的事；编辑页左边是表单、右边是这条的状态和相关操作；危险操作单独确认
4. **每个人只看到自己能用的**：入口、标签、按钮都按权限出现；直接敲网址也拦（视图自己再判一次）
5. **规则在服务层**：视图只收表单、调各应用 `services.py` 里已有的函数、显示结果；预渲染、邮件、AI 巡查、操作记录都沿用原来的函数和信号

## 2. 架构

| 部分 | 做法 |
|---|---|
| 应用 | 新应用 `backoffice/`：`urls.py`（全部后台网址）、`access.py`（进门和各页的权限）、`nav.py`（大类、标签和当前位置）、`forms.py`、`widgets.py`、`views/`（按大类分文件）、`templates/backoffice/` |
| 网址 | 新后台挂在 **`/admin/`**。Wagtail 的管理界面挪到 **`/wagtail/`**，只给超级管理员当「底层后台」应急用（编辑用户组的细粒度权限、看修订历史、重定向这类新后台不做的事），其他人访问跳回 `/admin/`；设置页里有一个入口 |
| 网址名 | 原来自定义页面的网址名不变（`registration_review_index`、`moderation_index`、`avatar_review`、`tournament_teams_board`、`scrim_split`、`announce`、`admin_activity`、`admin_manual`、`core_font_index`……），路径也不变，只是从 Wagtail 的钩子搬到 `backoffice/urls.py`；赛事、内战、战队、评论保留命名空间 `tournaments:`、`scrims:`、`teams:`、`comments:` 和原来的路径（`index`、`add`、`edit`、`copy`、`delete`）；新页面用命名空间 `backoffice:` |
| 模板 | `backoffice/base.html` 是独立的页面骨架（不套前台的页头页脚），用 `app.css`、`theme.js`；自己的布局类用 `b-` 前缀，写在 `assets/css/input.css` 的「后台」一节；表单字段、表格、按钮、标签、提示、分页都用前台已有的 `c-*` 组件 |
| 脚本 | `static/js/backoffice.js`：选图对话框、列表全选、筛选框改了就提交、危险按钮确认（`data-confirm`）、成员分组加一行。不写内联脚本。拖拽编队、拖拽分队、排版预览、Markdown 编辑器沿用原来的脚本；编辑器工具栏的图标原来借 Wagtail 页面里的图标集，新后台自己画了一套（`backoffice/templates/backoffice/parts/editor_icons.html`，照 13.2.9 的线条画法），编辑器样式跟着控件走（`static/css/markdown-editor.css`） |
| 内容安全策略 | `/admin/` 和 `/wagtail/` 用原来的后台策略（`core.middleware.ADMIN_CSP`）；Caddy 把这两个前缀都直接交给 Django，不找预渲染文件 |
| 进门 | `access_admin` 权限（和原来一样：验证过邮箱的成员、各角色、超管）；没登录跳登录页，登录了没权限 403 |

### 2.1 Wagtail 那边留下什么

- 留着、照用：页面模型和修订（`save_revision`、`PublishRevisionAction`、`UnpublishPageAction`、`DeletePageAction`，它们自己判权限、记操作记录、发信号）、图片和集合、`get_image_form`、全站设置模型、操作记录模型和 `register_log_actions`、页面权限（`OwnArticlesPermissionTester`）、`construct_explorer_page_queryset` 和对页面树的过滤（底层后台里也不让人看到别人的草稿）、账号页去掉的两个面板、用户批量操作的过滤、`admin.css` 的外观（底层后台也是站点的颜色）、通知信模板
- 去掉：给 Wagtail 界面做的菜单整理（`construct_main_menu` 三个、设置菜单、社区菜单、用户菜单）、八个大类的标签条（`core/admin_sections.py`、`templates/wagtailadmin/base.html` 的插入）、首页面板（问候、待办、上线清单、我的投稿）、页面列表和页头的群发按钮、用户列表的功能规则按钮、赛事、内战、战队、评论、功能规则的 `ModelViewSet`、文章分类和成员分组的 `SnippetViewSet`、文章编辑页的面板类。这些功能在新后台里重做

## 3. 布局

```
┌──────────────────────────────────────────────────────────────────────┐
│ ■ 管理后台   首页 内容 活动 成员 审核 数据 设置 手册      打开网站 昵称▾ │  b-top（深色条，13.2.6「深色条」）
├──────────────────────────────────────────────────────────────────────┤
│ 内容                                                                  │  b-head：大类名（小字）
│ 文章                                               [写文章]            │  标题 + 主要操作
│ 文章  分类  网站页面  图片                                             │  b-tabs：这一类的标签
├──────────────────────────────────────────────────────────────────────┤
│ [搜索…] [分类▾] [状态▾]                                                │  b-filters
│ ┌──────────────────────────────────────────────────────────────────┐ │
│ │ 标题           分类   作者   状态   更新于            操作          │ │  c-table
│ └──────────────────────────────────────────────────────────────────┘ │
│                         ‹ 1 / 3 ›                                     │  c-pager
└──────────────────────────────────────────────────────────────────────┘
```

- **顶栏** `b-top`：左边站点标志和「管理后台」（点了回后台首页），中间八个大类（只出现有权限的，当前的那个底下一道 `accent` 线），右边「打开网站」和账号菜单（个人中心、颜色模式、退出）。手机上大类变成第二行，横向滚动
- **页头** `b-head`：大类名、页面标题、主要操作按钮（右对齐，手机上换到标题下面）；编辑页的标题是这一条的名字，前面一个返回列表的链接
- **标签** `b-tabs`：这一类有两页以上时才有；「用户与权限」下面还有一排小标签 `b-subtabs`
- **内容区** `b-main`：最宽 80rem 居中；编辑页是两栏 `b-split`（表单 + 右侧 22rem 的状态栏），手机上一栏
- **消息**：Django 的消息显示成页头下面的 `c-notice`（成功、提示、警告、错误四种）
- **空状态**：`c-empty`，一句话说明加主要操作
- 深浅色跟前台一样（页头的颜色模式按钮）；后台没有页脚

## 4. 大类和页面

当前在哪个大类、哪个标签，由**视图自己声明**（`nav.placed(section, tab)` 装饰器），不再按网址前缀猜。

| 大类 | 标签（从左到右） | 谁能看到 |
|---|---|---|
| 首页 | — | 进后台的人 |
| 内容 | 文章、分类、网站页面、图片 | 文章：进后台的人（普通成员只看到自己的）；分类：能改分类的人（内容编辑）；网站页面：超管、内容编辑；图片：能选或加图的人 |
| 活动 | 赛事、内战 | 赛事管理员、内战管理员、超管 |
| 成员 | 用户与权限（小标签：用户、角色）、战队、成员分组 | 用户与权限、战队：超管；成员分组：能改分组的人（内容编辑） |
| 审核 | 报名、内容、头像、评论 | 报名：赛事管理员、超管（标签上写待审核件数）；内容（巡查记录）、头像：能复核的人；评论：能管评论的人（内容编辑、超管） |
| 数据 | 活动数据 | 超管、内容编辑、赛事管理员、内战管理员 |
| 设置 | 全站设置、字体库、排版设置、静态页面、操作记录 | 超管 |
| 手册 | — | 后台手册有内容的人 |

### 4.1 首页 `/admin/`

- 问候「你好，昵称」和身份；快捷按钮（写文章、新建赛事、新建内战、打开网站，按权限）——沿用 `core.admin_home.actions`
- **待办**：卡片，每件写是什么、几件、去处理——沿用 `core.admin_todo.todo_rows`；没有待办写「暂时没有待办」；不管任何一项的人没有这块
- **我的文章**：自己最近 5 篇（状态：草稿 / 已发布 / 定时），全部去文章列表
- **上线清单**：只给超管——沿用 `core.admin_setup`

### 4.2 内容

**文章** `/admin/articles/`（`backoffice:articles`）

- 列表：标题、分类、作者、状态（草稿、已发布、已发布·有改动、定时上线）、最后改动时间；筛选：搜标题、分类、状态、「只看我的」；内容编辑和超管看到全部，其他人只看到自己的文章（原来页面树对他们只显示已发布的和自己的，列表里别人的已发布文章没有可做的事，不列）
- 行上操作：编辑；已发布的「看文章」；能撤下的「撤下」（确认）；内容编辑、超管对已发布或定时的文章有「通知全体成员」（每篇一次，沿用 `announce`）
- 右上「写文章」：栏目能加子页面的人

**写文章 / 编辑文章** `/admin/articles/new/`、`/admin/articles/<id>/`

- 表单（`backoffice.forms.ArticleForm`）：标题、分类、封面（选图）、摘要、正文（Markdown 编辑器）、关联赛事；内容编辑和超管多「作者」「开放评论」；认证作者、内容编辑、超管多一组「网址和发布时间」：网址片段、SEO 标题、搜索描述、定时上线、定时下线。字段的增减和原来 `ArticlePageForm` 一样：普通成员（`plain_writer`）只能选开放投稿的分类；网址片段空着就按标题生成并避开保留字和同名
- 编辑时表单里是**最新的草稿**（有改动没发布时不是线上那版）
- 按钮：「保存草稿」（新修订）、「发布」（能发布时；有定时上线时间就是定时）、「预览」（新开页面，用最新草稿按前台模板渲染，只给能编辑的人）；右侧状态栏：状态、作者、首次发布和最后发布时间、看文章链接、「撤下」（能撤下时）、「删除」（能删时，确认）、「通知全体成员」（同列表），以及 AI 巡查对这篇的最新判断（只给能复核的人，原来的「AI 审核」面板）；普通成员在表单上方看到投稿须知
- 权限全部用 Wagtail 的页面权限和 `OwnArticlesPermissionTester`：新建看栏目的 `can_add_subpage`，编辑看 `can_edit`，发布、撤下、删除看对应的 `can_*`；保存、发布、撤下、删除用 Wagtail 的修订和 action 类，所以操作记录、信号（预渲染、AI 送审、上线时通知）和原来一样

**分类** `/admin/categories/`

- 列表：名称、网址片段、排序、开放投稿、文章数；新建、编辑（同一个表单页）；删除只给没有文章在用的分类（按钮不出现，直接提交删除也拒绝并提示）；保存后重新生成栏目页（沿用原来的信号）

**网站页面** `/admin/pages/`

- 固定几项：首页的置顶文章、资讯栏目的介绍、关于我们、用户协议、隐私政策（还有别的普通页面也列出来）
- 普通页面：标题、正文（Markdown）、SEO 标题、搜索描述；保存草稿、发布、预览
- 置顶文章：最多 3 篇，从已发布的文章里选，排顺序；保存即发布首页
- 资讯栏目的介绍：v7.0 起改存 Markdown（和正文一样；迁移把原来的富文本转成 Markdown），编辑即发布

**图片** `/admin/images/`

- 网格：缩略图、标题、集合、尺寸；筛选：搜标题、集合；分页每页 48
- 上传（可以一次选多张）：进选中的集合（只能选有加图权限的集合），走 Wagtail 的图片表单（格式、大小）；编辑标题、集合；删除（有删除权限时，确认）
- 「集合」（超管，图片页右上的按钮）：集合树，新建子集合、改名、删除空集合；默认封面、默认头像的子文件夹在这里建
- **选图**：表单里的图片字段（封面、首屏图、栏目横幅、默认封面……）是选图控件：缩略图、「选择」「清除」两个按钮；「选择」打开对话框，里面是能选的图片的网格（搜索、按集合、上传一张），点一张就选上

### 4.3 活动

**赛事** `/admin/tournaments/`（`tournaments:index`）

- 列表：标题、状态、报名开始、报名截止、待审核（有就写「N 份」，链到这项赛事的待审报名）；筛选：搜标题、状态、报名方式；行上：编辑，「更多」里按状态出现发布、通知全体成员、标记为已结束、队伍编排（个人报名）、审核报名、复制、取消赛事、删除（只有从没发布过的草稿）
- 新建、编辑、复制（`tournaments:add` / `edit` / `copy`）：一页表单，分「内容」「时间」「报名规则」「通知」几组（和原来的分组一样）；复制页的表单提交回复制地址，每次都新建一项，原来那项不动；时间框只到分钟，保存时如果只是秒被截掉，保留原来的时间（不误发「时间改了」）；`TournamentAdminForm` 的全部校验照搬（有报名后锁报名方式和自动通过、人数下限和全站战队人数上限）；保存后照原来：时间改了通知、补创建人、人数警告、`after_change`；复制照 `copy_for_new`
- 发布、标记结束、取消、队伍编排、通知全体成员：原来的视图，换成新后台的模板

**内战** `/admin/scrims/`（`scrims:index`）：同赛事。列表：标题、状态、规格、开始时间、报名截止；「更多」：发布、通知、标记结束、分队、复制、取消、删除（没人报名的草稿）。分队页沿用原来的视图和拖拽脚本

### 4.4 成员

**用户** `/admin/users/`（超管）

- 列表：昵称、邮箱、是否交大、角色、状态（在用 / 已停用）、注册时间；筛选：搜昵称或邮箱、角色、状态、是否交大
- 编辑页：昵称、是否来自交大、启用（停用必须写原因，停用后照原来 `after_deactivation`；自己的账号这里停用不了）、**角色**（勾选：内容编辑、认证作者、赛事管理员、内战管理员，以及手工建的分组（设计 4.2）；投稿者、交大用户、校外用户由系统维护，不在这里勾）；右侧只读：邮箱和是否验证、注册时间、游戏 ID 和段位、联系方式（有权限时）、所在战队；下面一块「功能规则」：这个人的单独规则，加一条（功能、允许或禁止、说明）、删一条
- 不能新建、删除用户（注册要本人同意协议，注销由本人发起）；超级管理员的设定在底层后台

**角色** `/admin/roles/`（超管，「用户与权限」的小标签）

- 每个用户组一块（四个后台角色在前，然后投稿者、交大用户、校外用户和手工建的）：名称、人数（链到筛好的用户列表）、能做什么（照 `design.md` 4.1 的表写一句）、这一组的**功能限制**（用户组功能限制：哪项功能对这组关着、说明；加、删；同一项不重复加）
- 角色本身不能在这里新建、删除、改权限（细粒度的在底层后台）

**战队** `/admin/teams/`（`teams:index`，超管）

- 列表：队名、队长、人数、招募、状态（正常 / 已解散 / 队长已停用）；筛选：搜队名、「队长已停用」
- 编辑（`teams:edit`）：队名、简介、招募、缺的位置（勾选）；保存后 `on_team_changed`；右侧：成员列表、「指定队长」「解散」（原来的视图）

**成员分组** `/admin/member-groups/`

- 列表：名称、是否显示、人数、排序；新建、编辑、删除
- 编辑：名称、简介、显示、排序；成员一行一个（选人、职务、组内顺序），可以加行、删行

### 4.5 审核

- **报名** `/admin/registrations/`：原来的列表、详情、通过 / 驳回 / 撤销、批量通过、导出，换新模板
- **内容**（巡查记录）`/admin/moderation/`：原来的视图，换新模板
- **头像** `/admin/avatars/`：原来的视图，换新模板
- **评论** `/admin/comments/`（`comments:index`）：列表（正文前 200 字、作者、文章、时间、隐藏、置顶）；筛选：搜正文、只看隐藏的、只看置顶的；行上直接「隐藏 / 恢复」「置顶 / 取消置顶」（沿用 `comments.services` 的 `hide` / `unhide` / `pin` / `unpin`，置顶的限制照 `pin_problem`）；不能新建、删除、改正文

### 4.6 数据、设置、手册

- **活动数据** `/admin/activity/`：原来的视图，换新模板
- **全站设置** `/admin/settings/site/`（`backoffice:site_settings`）：`SiteSettings` 一页表单，按原来的分组分块（站点信息、邮件、报名和活动、AI 审核、备份……），图片字段用选图控件；密钥字段不回显、空着不改（沿用 `SiteSettingsAdminForm`）；「AI 审核」一组含接口密钥（同样不回显、空着不改，旁边写着现在有没有保存）、接口地址、附加请求参数（JSON 对象）、超时、最多输出 token（v7.1，不再读环境变量）；「发送测试邮件」「测试对象存储」「试一下 AI」三个按钮（原来的视图，「试一下 AI」试完回到这一页）；保存后的预渲染沿用信号
- **字体库、排版设置、静态页面**：原来的视图，换新模板
- **操作记录** `/admin/log/`：所有操作记录（页面的和模型的），时间、谁、做了什么（动作的中文名）、对象；筛选：动作、时间段；每页 50
- **底层后台**：设置页最下面一行「Wagtail 底层后台（应急用）」，只有超管看得到
- **手册** `/admin/manual/`：原来的视图，换新模板；手册里的路径照新后台的说法改

## 5. 组件（`b-*`，写在 `input.css` 的「后台」一节）

| 类 | 用途 |
|---|---|
| `b-body` | 后台页面的 `<body>`：底色 `bg` |
| `b-top`、`b-brand`、`b-nav`、`b-nav__link`、`b-account` | 顶栏（深色条），大类链接，当前项 `aria-current` |
| `b-head`、`b-head__kicker`、`b-head__title`、`b-head__actions`、`b-head__back` | 页头 |
| `b-tabs`、`b-tabs__tab`、`b-subtabs` | 标签 |
| `b-main`、`b-split`、`b-aside`、`b-single` | 内容区、编辑页两栏、右侧状态栏；新建页没有状态栏时一栏（`b-single`，和两栏里的表单一样宽） |
| `b-section`、`b-section__title`、`b-section__text` | 一块白底的内容（首页的「我的文章」、右侧状态、各页的说明块） |
| `b-list`、`b-steps`、`b-chips`、`b-actions` | 一组浅色行；手册的编号步骤；状态筛选的小块（`core/admin/_tabs.html`）；一排按钮 |

| `b-filters` | 筛选条（一行表单，手机上换行） |

| `b-grid`、`b-grid__item` | 图片网格 |
| `b-picker` | 选图控件（缩略图 + 按钮） |
| `b-dialog` | 选图对话框（原生 `<dialog>`） |
| `b-cards`、`b-card` | 首页的待办卡片 |
| `b-fieldset`、`b-fieldset__legend` | 表单分组 |
| `b-formbar` | 表单底部的按钮条（长表单时贴在底部） |
| `b-kv` | 右侧状态栏里的「名称：值」列表 |
